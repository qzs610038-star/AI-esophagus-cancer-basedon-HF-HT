# PFMval 与多项目文献统一管理 — 执行计划

> 目标：在不破坏现有论文、项目文档、实验结果和 PDF 文件的前提下，把 Zotero、PFMval_new 文献目录、文献卡片和论文引用统一成可扩展的管理系统。
>
> 计划状态：方案稿；尚未执行文献迁移、批量导入、合并或删除。
>
> 制定日期：2026-09-21

## 一、当前基线

### Zotero

- Zotero Desktop 9.0.3 已安装并可用，本地接口和浏览器连接器正常。
- 当前本地库读取到 65 篇期刊文章，主题主要是计算病理学、空间转录组、病理图像到基因/通路表达预测、多组学和深度学习。
- 当前只有 1 个自定义分类，未读取到标签，说明文献主题较集中，但项目归属、阅读状态和证据关系尚未标准化。

### PFMval_new

项目中已经存在一套有价值的文献资产：

- `Ai病理项目文献汇总/`：11 个主题目录和本地 PDF/资料；
- `Ai病理项目文献汇总/LITERATURE_INDEX.md`：面向人和智能体的浏览索引；
- `Ai病理项目文献汇总/literature_manifest.json`：包含年份、来源、标签、可用性和与 MPP2 的关系；
- `Ai病理项目文献汇总/08_项目文档与笔记/`：文献卡片和项目笔记；
- 论文准备包中的 `references.bib`：面向单个论文包的引用快照；
- 许多分析报告和学习指南已经记录了“直接依据、邻近方法、背景和候选方案”的关系。

因此，统一方案应当“连接现有结构”，而不是重新复制一套论文目录。

## 二、统一架构

采用四层结构：

```text
Zotero 全局文献库
    ├── 文献元数据、PDF、DOI、个人笔记、去重
    ├── 跨项目复用的主题与状态标签
    └── 每个项目的集合视图
             ↓
项目文献注册表 literature_manifest.json
    ├── 与当前项目的关系
    ├── 是否已有本地 PDF / 全文
    ├── 是否已核对、已采用、仅作背景或已淘汰
    └── 关联实验、报告和学习材料
             ↓
文献卡片与 LITERATURE_INDEX.md
    └── 给人和智能体阅读的解释层
             ↓
项目级 references.bib
    └── 论文、报告或 LaTeX/Markdown 草稿的可复现引用快照
```

职责边界：

| 层级 | 唯一职责 | 不应承担的职责 |
|---|---|---|
| Zotero | 管理论文身份、附件、去重、跨项目复用 | 不记录每次实验的最终结论 |
| `literature_manifest.json` | 记录项目关系、证据等级和可用性 | 不替代 Zotero 的完整元数据 |
| 文献卡片 | 记录理解、批判和与项目的具体联系 | 不作为唯一的引文数据库 |
| `references.bib` | 服务一个具体论文/报告的引用 | 不作为全局文献主库 |

## 三、Zotero 集合与标签规则

### 1. 集合：表达“文献属于哪个视图”

建议建立以下顶层集合：

```text
00_收件箱_待分流
10_项目
  ├── PFMval_new
  │   ├── Phase2_HE到空间通路
  │   ├── Phase3_MIL与疗效预测
  │   ├── 论文与综述准备
  │   └── 历史方案与已不采用
  └── 以后新增项目
20_通用方法
  ├── 空间转录组
  ├── 病理基础模型
  ├── MIL与WSI
  ├── 多模态融合
  └── 图像预处理与工具
30_数据与临床背景
90_已读归档
99_待核对元数据
```

Zotero 允许同一条文献属于多个集合，因此同一篇论文可以同时位于 `PFMval_new/Phase2_HE到空间通路` 和 `20_通用方法/空间转录组`，不需要复制 PDF 或创建重复条目。

### 2. 标签：只表达“状态和关系”

标签保持少量、固定、可检索。建议只保留三组：

| 维度 | 示例 | 用途 |
|---|---|---|
| 状态 | `status/inbox`、`status/reading`、`status/read`、`status/verified`、`status/archived` | 表示阅读和核对进度 |
| 证据关系 | `role/direct_basis`、`role/adjacent`、`role/background`、`role/inspiration`、`role/not_adopted` | 防止把启发性论文写成直接依据 |
| 方法主题 | `method/HE2ST`、`method/UNI2h`、`method/MIL`、`method/multimodal` | 支持跨项目检索 |

项目归属优先通过集合表达；不要把每个项目都变成一组标签。一个条目最好不超过 6 个核心标签。

## 四、统一文献卡片

每篇进入项目主线的文献建立一张卡片，建议放在：

`Ai病理项目文献汇总/08_项目文档与笔记/literature_cards/`

卡片至少包含：

```yaml
zotero_key: "Zotero 条目编号"
citation_key: "BibTeX 引用键"
project_scope: [PFMval_new]
association_scope: direct_method_basis
status: verified
last_reviewed: 2026-09-21
source_url: "DOI 或正式论文地址"
local_pdf: "相对路径；没有则写 metadata_only"
```

正文固定回答：

1. 论文解决什么问题？
2. 数据、任务和评价指标是什么？
3. 方法中哪些部分与 PFMval_new 直接相关？
4. 哪些内容只是邻近工作或研究启发？
5. 项目实际采用了什么、没有采用什么？
6. 论文有哪些限制，不能支持哪些结论？
7. 论文中的事实对应哪些页码、图表或章节？

`association_scope` 沿用当前项目已有语义：

- `direct_method_basis`：直接支撑当前方法或基线；
- `adjacent`：方法相近，但不是当前实现的直接依据；
- `background`：提供领域、临床或技术背景；
- `inspiration`：仅用于提出候选方向；
- `not_adopted`：已经核查但当前项目不采用；
- `historical`：保留历史价值，不代表当前方案仍有效。

这样可以解决“旧论文仍在库中，但不应继续影响当前决策”的问题。

## 五、PFMval_new 的迁移与清理方案

### 阶段一：先建立映射，不移动原文件

把现有 11 个目录映射到统一集合：

| 现有目录 | 统一视图 |
|---|---|

| `02_病理基础模型_FoundationModels` | `PFMval_new/Phase2_HE到空间通路` + `通用方法/病理基础模型` |
| `03_多实例学习MIL与WSI分类` | `PFMval_new/Phase3_MIL与疗效预测` + `通用方法/MIL与WSI` |
| `04_空间转录组方法与工具` | `通用方法/空间转录组` |
| `05_多模态融合与预后预测` | `PFMval_new/Phase3_MIL与疗效预测` + `通用方法/多模态融合` |
| `06_食管癌流行病学与临床背景` | `数据与临床背景` |
| `07_图像预处理与工作流工具` | `通用方法/图像预处理与工具` |
| `08_项目文档与笔记` | 保留为项目解释层，不作为 PDF 集合 |

不删除旧目录，不批量移动 PDF，不计算哈希。先依据 DOI、题名和作者做人工/工具辅助去重；无法确认的条目标记为 `99_待核对元数据`。

### 阶段二：把当前 65 篇 Zotero 条目分成四类

| 分类 | 判定标准 | 后续动作 |
|---|---|---|
| 核心依据 | 当前代码、评价协议、论文方法直接使用 | 纳入 PFMval_new 主集合和文献卡片 |
| 邻近方法 | 可作比较、解释或替代方案 | 纳入方法集合，标记 `role/adjacent` |
| 背景材料 | 临床、数据、工具或概念背景 | 纳入背景集合，按需建卡片 |
| 历史/待核对 | 内容过旧、重复、与当前项目关系不清 | 不删除，转入归档或收件箱 |

“内容陈旧”不直接等于“无价值”。经典方法保留为 `historical` 或 `background`；真正影响当前路线的内容必须经过重新核对后才能标为 `verified`。

### 阶段三：重新生成项目视图

PFMval_new 的项目视图只登记进入项目决策、论文、代码解释或学习指南的文献。建议补充以下字段：

```json
{
  "zotero_key": "...",
  "citation_key": "...",
  "project_scope": ["PFMval_new", "Phase2"],
  "association_scope": "direct_method_basis",
  "status": "verified",
  "availability": "local_pdf_verified",
  "local_pdf": "相对路径",
  "used_in": ["报告路径或实验编号"],
  "last_reviewed": "2026-09-21",
  "review_due": "2027-03-21"
}
```

`LITERATURE_INDEX.md` 作为便于浏览的派生索引；`literature_manifest.json` 作为项目关系的结构化登记；Zotero 仍是论文元数据和附件的主来源。

## 六、未来项目接入模板

每增加一个项目，只需增加四类对象：

1. Zotero 中建立 `10_项目/<项目名>` 集合；
2. 项目仓库中建立 `literature_manifest.json` 或项目文献登记区；
3. 建立 `literature_cards/` 和 `LITERATURE_INDEX.md` 项目视图；
4. 论文或报告需要时，从 Zotero 生成该交付物自己的 `references.bib`。

新项目不复制全局 PDF，也不建立全库级别的巨大 `references.bib`。同一篇论文通过 Zotero 的多集合归属服务多个项目。

## 七、日常工作流

```text
发现论文
  → 保存到 Zotero 00_收件箱
  → 去重、补 DOI、确认题名和作者
  → 判断项目集合与方法集合
  → 添加状态/关系/方法标签
  → 需要时建立文献卡片
  → 写报告前导出当前项目 references.bib
  → 用 Zotero 条目或 BibTeX 引用键插入引用
  → 项目决策改变时更新 association_scope 和 review_due
```

可直接让 Codex 执行的自然语言指令：

- “检查 Zotero 中 PFMval_new 相关文献，按核心依据、邻近方法、背景和历史材料分组。”
- “搜索我的 Zotero，找出 2024 年以后与 HE 图像预测空间通路相关的论文，并列出未进入项目注册表的条目。”
- “读取这篇已索引论文，生成 PFMval_new 文献卡片，区分论文事实、项目推断和未核实内容。”
- “把当前项目主线文献导出为 `references.bib`，并检查报告中的引用是否都有对应条目。”
- “比较项目文献注册表和 Zotero，找出缺 DOI、缺 PDF、缺引用键和重复条目。”

插件职责边界：搜索、盘点、导出和引用插入可以直接进行；向 Zotero 导入新记录、保存浏览器条目、合并或删除条目属于写操作，应先确认具体来源和目标。

## 九、风险与控制

| 风险 | 概率 | 影响 | 控制措施 |
|---|---|---|---|
| 同一论文在 Zotero、PDF 目录和 BibTeX 中有不同身份 | 高 | 引用重复或丢失 | 优先使用 DOI/题名/作者去重；保留 Zotero key 与 citation key 的双向映射 |
| 旧论文继续被误当作当前方法依据 | 高 | 论文论证和实验解释失真 | 强制记录 `association_scope`、`status` 和 `last_reviewed` |
| 每个项目复制一份 PDF 和全库 BibTeX | 中 | 存储膨胀、版本分叉 | Zotero 作为全局源；项目只保存卡片、登记表和交付物引用快照 |
| 自动生成的摘要混入项目事实 | 中 | 科研结论边界不清 | 文献卡片分开写“论文事实、项目推断、待核查事项” |
| 新项目使用不同标签和目录命名 | 中 | 长期检索困难 | 新项目只扩展项目名，不改变状态、关系和方法词汇表 |
| 批量迁移误覆盖现有材料 | 低 | 原始资料受损 | 第一阶段只建立映射；不删除、不覆盖、不移动原始 PDF 和实验资产 |

## 十、验收标准

第一轮整理完成后，应满足：

- Zotero 中每篇主线论文都有唯一条目，且能追溯 DOI、PDF 或正式来源；
- PFMval_new 的主线文献可以按 Phase2、Phase3、通用方法和背景检索；
- 每篇进入论文或实验决策的文献都有 `association_scope` 和 `status`；
- 项目文献注册表能指向 Zotero 条目和本地文献卡片；
- `references.bib` 可以从 Zotero 重新生成，且报告中的引用键可解析；
- 旧论文、未采用方案和待核对材料仍可找到，但不会与当前已确认依据混在一起；
- 新项目只需复制接入模板，不需要复制整个 PFMval_new 文献目录。

## 十一、建议的近期执行顺序

先做三件事即可产生明显收益：

1. 在 Zotero 中建立 `00_收件箱`、`10_项目/PFMval_new`、`20_通用方法` 和 `90_已读归档` 四个主集合；
2. 给当前 65 篇条目只补“项目关系”和“阅读状态”，暂时不追求完整摘要；
3. 从 PFMval_new 的 Phase2/Phase3 主线文献开始更新项目注册表和文献卡片，再处理历史材料。

这样可以先解决“论文在哪里、是否仍适用、与哪个项目有关”三个核心问题，再逐步补齐全文、笔记和最新文献。
