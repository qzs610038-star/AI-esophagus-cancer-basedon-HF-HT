# 数据泄漏与“三层分离”协议学术规范指南

本指南面向医学图像处理与空间转录组预测领域的初学者与研究人员，旨在系统性地讲解机器学习中**数据泄漏（Data Leakage）**的原理、危害，并通过通俗与专业并重的语言，剖析旧三患者方案中的隐性泄漏，进而详解新版 **MPP-v3bis** 方案中**“三层信号分离协议”**的学术规范与设计原理。

---

## 1. 核心概念与直觉比喻（高考备考模型）

在机器学习（AI 模型训练）的学术规范中，为了公正地评价模型的泛化性能，我们将数据集划分为三个独立的部分。我们可以将这三者与人类学生的备考过程进行直观对照：

| AI 术语 | 科学定义 | 高考备考比喻 | 规则约束 |
| :--- | :--- | :--- | :--- |
| **训练集 (Train Set)** | 用于优化模型权重参数的数据集合，参与梯度的计算与反向传播。 | **平时的教科书与课后习题** | 学生可以一边看着标准答案一边纠正错误，在大脑中沉淀知识网络（**拟合权重参数 $\theta$**）。 |
| **验证集 (Val Set)** | 用于评估训练过程、选择超参数、保存最优 epoch 权重、触发早停（Early Stopping）的集合。 | **学校的模拟考试卷** | 不用来背答案，而是用来衡量复习效果，帮助学生调整备考策略、决定何时停止复习（**调整超参数、控制训练轮数**）。 |
| **测试集 (Test Set)** | 仅用于对定型后的模型进行最终泛化性能评估的独立集合。 | **保密的正式高考卷** | 在复习彻底结束、模型完全定型前，学生绝不能提前接触。用于计算模型最终的预测精度（**跨患者泛化 PCC、MAE、$R^2$**）。 |

## 2. 数据泄漏的数学与统计学定义

在学术研究中，**数据泄漏（Data Leakage）**是指在模型构建和评估过程中，本属于测试集（甚至验证集）的信息以各种直接或间接的形式进入到模型中，从而使模型在测试集上的表现被“虚高估计”。

我们可以从数学与信息论的角度来定义两种泄漏：

### 2.1 显式权重优化泄漏（Explicit Weight Leakage）
这是最粗暴的泄漏形式。直接将测试集 $D_{\text{test}}$ 送入损失函数进行梯度反向传播：
$$\theta_{t+1} = \theta_t - \eta \nabla_{\theta} L(D_{\text{train}} \cup D_{\text{test}}; \theta_t)$$
这相当于学生在考试前直接背诵了高考真题的答案，此时测试成绩已完全失去客观性。

### 2.2 隐式模型选择泄漏（Implicit Model Selection Leakage）
在本项目中，旧三患者方案所面临的隐性泄漏正是此类。
模型在训练阶段的**每一步（Step/Iteration）**中虽然确实没有将测试集 $D_{\text{test}}$ 参与权重的直接更新，但是在**训练完成后（Epoch 层面）**，代码利用测试集上的损失反馈，来进行离散参数的最优选择：
$$\text{epoch}^* = \arg\min_{e \in [1, E]} L_{\text{loss}}(D_{\text{test}}; \theta_e)$$
这相当于：学生虽然没有直接背真题的答案，但是学校通过高频的真题考试反馈，不断帮学生筛选出**“对这套高考真题而言成绩最好的一轮复习状态（Best Checkpoint）”**作为最终成绩上报。
此时，**测试集的信息实际上顺着模型选择链条（Early Stopping & Epoch Select）倒流回了系统**，导致最终上报的泛化性能被严重高估。

## 3. 旧三患者方案下的隐患剖析

在旧的“三患者方案”中，项目包含患者：`HYZ15040`、`JFX0729`、`LMZ12939`。

1.  **单患者内部的空间泄漏防范**：
    在单患者内， patches 之间因物理相邻存在极强的特征关联（空间相关性）。为了防范泄漏，[split.py](file:///d:/AI空间转录病理研究/PFMval_new/split.py) 采用了**基于空间物理距离约束的贪心划分法**：
    *   解析文件名坐标：`patch_x{coord}_y{coord}.png`。
    *   遍历排除：强制验证集内任意两个 patch 以及验证集与训练集 patch 之间的欧氏距离必须大于 **350 像素**，以确保局部去噪和空间独立。
2.  **跨患者交叉验证下的泄漏隐患**：
    在跨患者 Leave-One-Patient-Out（例如 Fold 1：JFX + LMZ $\rightarrow$ HYZ）的实际训练中，为了防范过拟合，通常需要选择最佳的 checkpoint。但由于没有独立的第三方外部验证集，代码将 `HYZ`（测试集）同时作为了 `val_loss` 的计算对象：
    ```python
    # 伪代码：在旧跨患者训练脚本中常见的过拟合控制
    if current_loss_on_HYZ < best_loss:
        best_loss = current_loss_on_HYZ
        save_checkpoint('best_model.pth')
    ```
    在这种状态下，**“选择第几个 epoch 模型”的反馈信号源完全由测试折 HYZ 贡献**。这就导致了严格学术规范下的测试污染。

## 4. MPP-v3 / MPP-v3bis 的三层分离协议

在新版 MPP（Multi-Patient Pathology/Protocol）方案下，多源混合患者的样本量扩展至约 42K patches，且在 MPP-3/5 等划分方案中存在 **50% 的物理重叠（overlap）**。
如果只做单患者内的物理空间分割，重叠的 patches 会导致去重逻辑彻底失效，使数据极易通过 overlapping 泄漏。

因此，**MPP-v3bis** 引入了严苛的 **“三层信号分离协议”**，其架构如下：

```
  【 数据信号隔离边界 】
  
  ┌────────────────────────────────────────────────────────┐
  │ 1. 训练信号层 (Train Patients)                           │
  │    使用患者: HYZ15040, JFX, LMZ12939, TGC, XSL           │
  │    作用: 计算梯度、更新模型权重、拟合 Z-score 均值与方差    │
  └──────────────────────────┬─────────────────────────────┘
                             │
                             ▼
  ┌────────────────────────────────────────────────────────┐
  │ 2. 内部验证信号层 (Internal Val Patient)                │
  │    使用患者: 固定 ZHZ                                   │
  │    作用: 仅在 Epoch 结束时计算损失，控制 Early Stopping   │
  └──────────────────────────┬─────────────────────────────┘
                             │
                             ▼
  ┌────────────────────────────────────────────────────────┐
  │ 3. 外部测试信号层 (External Test Patient)                │
  │    使用患者: 固定 MPP-2/XZY                             │
  │    作用: 仅在最优 checkpoint 固定后，进行一次性泛化性能评估 │
  └────────────────────────────────────────────────────────┘
```

### 4.1 核心规则与红线

为了在学术论文中实现无瑕疵的科学性，MPP-v3bis 设立了以下硬性规则：

1.  **特征归一化隔离**：
    所有 ssGSEA 通路评分标签需通过 Z-score 进行标准化。标准化公式中的均值 $\mu$ 与标准差 $\sigma$ **必须只在 Train Patients 集合上拟合（Fit）**：
    $$\mu = \text{mean}(Y_{\text{train}}), \quad \sigma = \text{std}(Y_{\text{train}})$$
    绝对禁止将验证集（ZHZ）和测试集（XZY）包含进均值和标准差的计算。计算完成后，将拟合好的参数 $\mu$ 和 $\sigma$ 应用于所有集合：
    $$Y^* = \frac{Y - \mu}{\sigma}$$
    若使用全量数据一同拟合 Z-score，将导致测试集的标签信息在训练前就被模型“间接感知”。
2.  **验证集不参与拟合**：
    内部验证集 `ZHZ` 仅被动用于计算 `val_loss`。它的数据绝对不可参与 MLP 回归头的任何反向传播参数拟合。
3.  **外部测试集一测定乾坤**：
    外部测试集 `XZY` 被彻底锁死。在训练过程中，它不可被加载。只有当最优 Epoch 被 ZHZ 的 `val_loss` 选定后，加载 `best_model.pth`，对 XZY 进行一次性预测，产出泛化 PCC、$R^2$ 与 MAE。

## 5. 优劣势与学术可行性评估

### 5.1 旧三患者方案

*   **优势**：通过 [split.py](file:///d:/AI空间转录病理研究/PFMval_new/split.py) 的物理坐标欧氏距离，严格拉开了单患者内部 patch 的空间关联度，具有极强的物理独立性。
*   **劣势**：缺少独立的第三层外部测试集。当面对有 50% 物理重叠的多患者 MPP 方案时，传统的物理距离分割法无法防范 overlap patches 带来的数据穿透泄漏。

### 5.2 新 MPP-v3bis 方案（推荐主线）

*   **优势**：
    1.  **学术严谨**：完美做到了 Train-Val-Test 的信号隔离，不存在隐性泄漏，完全符合顶会与顶刊的同行评审标准。
    2.  **避开去重难题**：采用整例患者隔离（将整个 ZHZ 作为验证，整个 XZY 作为测试），从物理上直接杜绝了 MPP 重叠 patches 的泄漏通道。
    3.  **受控的横向比较**：固定测试集为同一个 `MPP-2/XZY`，能以“控制变量法”干净地评估 MPP-1 到 MPP-5 的切图分块机制对泛化性的影响。
*   **劣势**：由于需要将一整例患者数据（ZHZ，含 4.2K patches）完全划出作为验证集，导致模型可以使用的训练样本量减少了约 10%。
