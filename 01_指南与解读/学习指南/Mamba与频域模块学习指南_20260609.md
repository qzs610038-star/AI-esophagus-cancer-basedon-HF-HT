# 一、基础概念：图像的频率域与傅里叶变换

## 1.1 什么是图像的"频率"？

**一句话**：频率描述的是像素值在空间上变化的速度。

**直观理解**：
- **低频** = 图像中变化缓慢的区域（大块组织、平滑的背景染色）
- **高频** = 图像中变化剧烈的区域（细胞边界、纹理细节、噪声）

用音频类比：低频是低音鼓的"咚——"，高频是小提琴的尖细音。图像的频率域就是把这些"空间音调"分离出来。

## 1.2 傅里叶变换 (FFT) 做什么？

**一句话**：傅里叶变换将图像从"每个像素的值"表示，转换为"每种频率的强度"表示。

```
空间域 (我们看到的):              频率域 (FFT 之后):
┌──────────────────┐              ┌──────────────────┐
│ ▓▓░░░░▓▓░░░░▓▓░░ │              │ ★ (低频, 中心)    │
│ ░░▓▓░░░░▓▓░░░░▓▓ │   ──FFT──→   │  ◇ (中频, 纹理)   │
│ ▓▓░░░░▓▓░░░░▓▓░░ │              │   · (高频, 边缘)  │
│ ░░▓▓░░░░▓▓░░░░▓▓ │              └──────────────────┘
└──────────────────┘              中心亮点=平滑区域
(条纹纹理)                          外围散点=边缘/噪声
```

**关键性质**：
1. **FFT 是可逆的**：做完 FFT 之后可以用 IFFT（逆变换）完美还原原图，信息不丢失
2. **频率域的操作等价于空间域的全局操作**：在频率域乘一个数 = 在空间域做一次覆盖全图的卷积
3. **rFFT（实数 FFT）**：因为图像像素是实数，FFT 结果有对称性，只需保留前 N//2+1 个频率分量。65 token → 33 频率分量，265 token → 133 频率分量

## 1.3 为什么我们关心 1D 序列的 FFT（而非 2D 图像 FFT）？

**关键澄清**：我们的 GFNet 做的 FFT 对象不是 H&E 图像的像素，而是 **ViT token 序列**。

```
H&E Patch (224×224 像素)
  → UNI2-H ViT (frozen backbone)
    → 265 个 token, 每个 1536 维
      → 选取 65 个 token (cls_patch64 模式)
        → [B, 65, 1536] 的序列
          → Linear 投影到 512 维 → [B, 65, 512]
            → 🔥 沿 token 维度做 1D FFT → [B, 33, 512] 频率分量
              → 可学习滤波 → IFFT → [B, 65, 512]
                → MLP head → 30 个基因通路预测
```

**这意味着**：FFT 分析的"信号"是 **65 个 token 沿序列维度的变化模式**，而非原图的 2D 纹理。Token 序列的频率反映的是"相邻 patch token 之间的特征变化节奏"——一种介于单 token 和全局图像之间的中尺度表征。

> ⚠️ **重要**：因此，原文 §6.4 讨论的"纤维束方向→频率峰值"等 2D 图像频率的直觉，并不能直接套用到 1D token 序列 FFT 上。1D 序列 FFT 的物理意义更抽象——它捕获的是"token 间特征在序列维度上的周期性模式"。

### 1.3.1 架构辨析一：为什么在 tile 内做 token 间 FFT，而不是建模 tile 之间的空间关系？


这是对当前架构最根本的追问。让我们先理清三个空间尺度：

```
尺度 1 — 全切片图像 (WSI, ~10mm × 10mm)
  └─ 切分为数百个 224×224 tiles（每个 ~112μm × 112μm @20x）
       └─ 尺度 2 — 单个 tile 内，ViT 再切为 16×16=256 个 14×14 patch（每个 ~7μm）
            └─ 尺度 3 — 每个 patch 内的像素纹理
```

当前 GFNet 操作在**尺度 2**：对单个 tile 内的 token 序列做 FFT。缺失的是**尺度 1**：tile 之间的空间依赖。

**为什么 tile 内建模仍有意义？**

224×224 tile（~112μm @20x）在生物学上并非"无结构的一块"——它内部包含：
- 肿瘤细胞团 vs 间质的微结构差异（~50-100μm 尺度）
- 免疫细胞浸润的局部聚集模式
- 腺体/血管结构的局部形态

FFT 沿 token 序列维度捕获的就是这些**中尺度（mesoscale）组织模式**——这确实比只用 CLS token（全局平均池化）多了一层空间分辨率。实验也支持这一点：GFNet Token (0.3967) > Transformer Token (0.3821)，说明 token 间的序列模式含有 CLS 未完全捕获的信息。

**为什么尚未建模 tile 间关系？**

有三个现实约束：

1. **Ground truth 对齐**：空间转录组 spots 直径 55-100μm，一个 tile（~112μm）大致对应一个 spot。tile 间建模意味着一个 spot 的预测需要聚合多个 tile 的输出，标签策略需要重新设计。

2. **计算复杂度**：一个患者有数千个 tile，它们的空间排列是不规则的（组织轮廓不规则），需要图结构或可变长度序列来处理。EGN-v2 做了这个方向（GraphSAGE 在 spot 空间图上），但性能远不如简单独立的 CLS/Token 方法（PCC ~0.20 vs ~0.43），说明在目前数据量下，tile 间的空间图信号被过拟合噪声淹没了。

3. **优先级**：实验证明，在 15K 样本/2 患者训练的条件下，改善**单个 tile 内的特征提取质量**（CLS LoRA → +5.1%）带来的增益远大于空间图建模。tile 间建模的方向在逻辑上正确，但在 3 患者数据量下尚未显示出实证优势。

**9 患者展望**：数据量增加 3-4× 后，tile 间空间图建模（类似 EGN-v2 但使用更强的 token 特征）值得重新评估。届时每个 fold 有 6 患者训练，可能首次有足够的统计量让空间图信号从噪声中浮现。

### 1.3.2 架构辨析二：从 265 个 token 中选 65 个的标准是什么？

**短答案：没有智能标准——纯位置截取。** 这是一个值得坦诚面对的架构局限。

**265 个 token 的结构**

UNI2-H（基于 DINOv2 ViT-L/14 + register tokens）对 224×224 输入图像输出 265 个 token：

| 位置 | 数量 | 含义 |
|:---:|:---:|------|
| 0 | 1 | **CLS token** — 全局图像摘要 |
| 1-8 | 8 | **Register tokens** — DINOv2 的"杂项桶"，不对应固定空间位置 |
| 9-264 | 256 | **Patch tokens** — 16×16 空间网格（行优先排列），每个对应 14×14 像素区域 |

代码实现在 `model_online_tokens.py:select_uni_tokens()`。

**两种选取模式**

| 模式 | 选取内容 | 有效 patch 数 | 空间覆盖 |
|------|---------|:---:|------|
| `legacy_firstN` | 直接取前 65：[CLS, 8 reg, 56 patch] | 56 | 顶部 3.5 行（不完整） |
| `cls_patch64` | CLS + 跳过 8 reg + 前 64 patch | **64** | 顶部 4 行（16×16 的上 1/4） |

**cls_patch64 的改进**：排除 register tokens（它们不对应固定空间位置，混入 FFT 序列会引入噪声）。实验验证有效：PCC 从 0.3914 → 0.3967 (+1.4%)。

**cls_patch64 的局限**："前 64 个 patch"对应 16×16 网格的**顶部 4 行**，即图像的上 1/4。这是空间上有偏的采样——来自图像下半部分的组织信息被系统性地丢弃了。

**为什么选 65（而不是 265 全部）？** 纯计算考虑。GFNet 的 FFT 在序列维度上操作，参数量 = `N/2+1 × D × 2`。65-token 的 GFNet block 约 6.66M 参数，265-token 会显著增加。但 `num_tokens` 在代码中是可配置参数——265-token GFNet 在技术上是可行的，第一阶段 smoke test 中也跑过。当频域方向整体关闭后，265-token 扩展未被继续推进。

**如果重新设计，更合理的选取策略可能是**：
- **均匀空间下采样**：从 16×16 网格中取 8×8=64 个均匀分布的 patch（空间覆盖无偏）
- **注意力引导选取**：用 CLS token 对 patch 的 self-attention 权重取 top-64
- **全部使用**：直接用 265 token（以计算量换取完整性），在 9 患者更大数据下可能值得尝试

# 二、GFNet 详解：用傅里叶变换替换自注意力

> 📄 Rao et al. "Global Filter Networks for Image Classification." NeurIPS 2021.

## 2.1 论文核心逻辑

### 问题

ViT 的自注意力层计算复杂度是 O(N²)（N = token 数量），且在小数据集上容易过拟合。

### 核心洞察

自注意力可以看作一种**输入依赖的全局 token mixing**：不同样本会产生不同的 mixing 权重。GFNet 的核心替代思路是：把这种数据依赖的全局混合，换成**可学习但输入无关的频域全局滤波器**。它牺牲了一部分自适应性，换来更低复杂度和更强的结构性正则化。

### 方法

```
Transformer Block:                    GFNet Block:
x = x + Attention(LN(x))             x = x + GlobalFilter(LN(x))
x = x + FFN(LN(x))                   x = x + FFN(LN(x))

其中 GlobalFilter:
1. rFFT(x, dim=1) → 沿 token 维度做 1D 实数 FFT
2. x_freq ⊙ W (可学习复数权重) → 每个频率分量乘以可学习标量
3. irFFT(x_freq, n=N, dim=1) → 转回空间域
```

## 2.2 为什么 GFNet 优于 Transformer（本项目验证）

我们在 PFMval 上获得了确凿的实证：

| 对比维度 | Transformer 65t | GFNet 65t (legacy) | GFNet 65t (cls_patch64) |
|------|:---:|:---:|:---:|
| Val PCC | 0.3821 | 0.3914 (+2.4%) | **0.3967 (+3.8%)** |
| 可训练参数 (Encoder) | 7.68M | 6.66M (-13%) | 6.66M (-13%) |
| Train-Val Gap (E2) | >0.20 | 0.168 | **0.160** |

**三个层面的优势**：

1. **抗过拟合**：固定滤波器意味着模型必须学到**通用的频率模式**，而不是针对每个训练样本调整。在仅 15K 训练样本的场景下，这是一种强正则化。Train-Val Gap 收窄 20% 以上证实了这一点。

2. **全局感受野**：频域的一个点对应空间域（token 序列）的全局模式——单层 GFNet filter 就能捕获任意两个 token 间的长程依赖，不需要像 Transformer 那样依赖 multi-head attention 的多头机制。

3. **参数量更少**：filter 只学 `N/2+1 × D × 2`（实部+虚部）个参数。65 tokens × 512 dim = 33×512×2 ≈ 34K params，对比 Transformer 的 self-attention（QKV 投影）需要 ~1M params。

> 注：上面是基础 GFNet filter 的参数量。A1 的 modReLU 版本会额外引入 `33×512≈17K` 个 bias 参数，用于频域幅度门控。

## 2.3 cls_patch64：修复 token 选择的意外收获

### 265 个 token 的完整结构

UNI2-H（基于 DINOv2 ViT-L/14 + register tokens）对每个 224×224 输入图像输出 265 个 token：

| 位置索引 | 数量 | 身份 | 含义 |
|:---:|:---:|------|------|
| 0 | 1 | **CLS token** | 全局图像摘要（分类头用） |
| 1-8 | 8 | **Register tokens** | DINOv2 引入的"杂项桶"——不对应固定空间位置，用于吸收注意力图中的 artifacts |
| 9-264 | 256 | **Patch tokens** | 16×16 空间网格（行优先排列），每个对应 14×14 像素的局部区域 |

> **Register tokens 的背景**：DINOv2 训练时发现，ViT 的注意力图会在背景区域产生虚假的高注意力值（artifacts）。引入 8 个额外的可学习 token 后，这些 artifacts 被 register tokens "吸收"，patch token 的注意力图变得更干净。但它们不对应任何空间位置，在需要空间序列建模的场景中是噪声。

### 两种选取模式对比

**背景**：原始 GFNet `legacy_firstN` 模式直接从 ViT 输出取前 65 个 token（`all_tokens[:, :65, :]`）。但 65 个 token 里混入了 8 个 register tokens，实际只有 56 个有意义的 patch token——且这 56 个只覆盖了 16×16 网格的顶部 3.5 行。

**修复**：A0b 使用 `cls_patch64` 模式——CLS + 跳过 8 个 register + 取 64 个真正的 patch token。

| 模式 | 选取内容 | 有效 patch 数 | 空间覆盖 |
|------|---------|:---:|------|
| `legacy_firstN` | `all_tokens[:, :65, :]` = [CLS, 8 reg, 56 patch] | 56 | 顶部 3.5 行（16×16 网格中不完整的 1/4） |
| `cls_patch64` | [CLS, patch₀...patch₆₃] = [index 0, 9-72] | **64** | 顶部 4 行（16×16 网格的上 1/4） |

代码实现位于 `model_online_tokens.py:select_uni_tokens()`：

```python
# cls_patch64 模式的核心逻辑
cls_token = all_tokens[:, 0:1, :]                    # [B, 1, D] — CLS
patch_start = 1 + reg_tokens                           # = 9，跳过 CLS + 8 reg
patch_tokens = all_tokens[:, patch_start:patch_start + 64, :]  # [B, 64, D]
return torch.cat([cls_token, patch_tokens], dim=1)   # [B, 65, D]
```

**效果**：PCC 从 0.3914 → 0.3967 (+1.4%)，Train-Val Gap 从 0.168 → 0.160。排除 register tokens 后，序列内的 token 更"干净"，沿 token 维度的 FFT 更可能捕获有意义的空间变化模式。

### 一个坦诚的局限：没有智能选取标准

**"64 个 patch"的选取纯粹是按位置截取——没有基于信息量、注意力权重或空间均匀性的智能选择。**

这意味着两个问题：

1. **空间覆盖有偏**：前 64 个 patch 对应 16×16 网格的**顶部 4 行**（图像的上 1/4）。图像下半部分的组织形态信息被系统性地丢弃。对于 H&E 切片，如果关键结构（如肿瘤核心、浸润边缘）恰好位于 tile 的下半部分，这些信息将完全丢失。

2. **"65"这个数字本身没有生物学依据**：它来自工程便利性——足够小以控制 GFNet 参数量（6.66M），又足够大以保留合理的空间分辨率。第一阶段也测试过 265-token GFNet（smoke test），但因频域方向关闭未被推进到正式实验。

**为什么没有实现更智能的选取？**
- 当时的目标是修复 register token 混入这一已确认的 bug，而非优化 token 选取策略本身
- 实验优先级聚焦于"频域是否有效"这一核心假说——token 选取是次要变量
- 任何智能选取（注意力引导、均匀采样）都需要额外代码，且会引入新的超参数

**如果重新设计，候选方案**：

| 方案 | 做法 | 优点 | 风险 |
|------|------|------|------|
| 均匀空间下采样 | 从 16×16 取 8×8=64 个均匀 patch | 空间覆盖无偏 | 需要改变 token 索引逻辑 |
| 注意力引导选取 | CLS 对 patch 的 attention 权重取 top-64 | 信息量最大化 | attention 来自 frozen backbone，可能与预测任务不align |
| 全部 265 token | 不做选取，直接走 GFNet | 信息完整 | 参数量增大，过拟合风险增加 |
| 可学习选取 | 加一个轻量 gating 网络预测每个 patch 的重要性 | 端到端优化 | 额外参数，小数据下不可靠 |

目前这些方案均未进入实验。9 患者数据下，265-token 全量 GFNet 或均匀下采样可能值得重新评估。

# 三、modReLU：频域稀疏化假说及其失败

## 3.1 假说

modReLU 在 GFNet 的 GlobalFilter 中增加了一个可学习的 bias 参数，在 IFFT 之前对频率分量施加幅度门控：

```python
magnitude = x_freq.abs()                       # 每个频率分量的幅度
activated = torch.relu(magnitude + self.bias)   # bias < 0 → 弱分量被截断
x_freq = activated * (x_freq / (magnitude + 1e-8))  # 保留相位，修改幅度
```

**理论期望**：modReLU 能自动学习哪些频率分量是"噪声"（幅度小 → bias < 0 截断），哪些是"信号"（幅度大 → 保留）。这等价于**频域自动去噪**——只保留对基因通路预测有信息量的频率分量。

## 3.2 实际结果

| 指标 | A0b (无 modReLU) | A1 (modReLU) | Δ |
|------|:---:|:---:|:---:|
| Best Val PCC | **0.3967** | 0.3724 | **-6.1%** |
| Best Val Loss | **0.3320** | 0.3394 | +2.2% |
| Train-Val Gap (PCC) | **0.160** | 0.241 | **+50%** |
| Best Epoch | 2 | 4 | 窗口延后但更差 |

## 3.3 为什么会失败

modReLU 在本任务上失败的原因有三层：

**第一层（直接原因）：截断了有用信息。** H&E 病理图像中的细微纹理（如核形态变化、细胞间质细微差异）在频率域的幅度通常很小，但可能携带关键的诊断信息。modReLU 的 bias 学到的是一个"一刀切"的阈值——把弱信号连同噪声一起截掉了。

**第二层（机制原因）：加剧了过拟合。** 可学习的 bias 增加了自由度（17K 额外参数），在小样本场景下，模型会学会"过度清理"训练集常见的频率分量，但这些分量在测试患者上恰好是区分性特征。

**第三层（根本原因）：假说本身不适用于此任务。** 频域稀疏化的前提是"信号频率分量稀疏且幅度大，噪声频率分量密集且幅度小"。但在病理图像中，关键的形态学信息往往分布在大量中等幅度的频率分量上——不是稀疏的。modReLU 的 hard thresholding 在这个前提不成立的数据上必然失败。

**通路层面的证据**：部分通路（MYC、Wound Healing）有小幅提升，但 Coagulation、Inflammatory Response、E2F、Oxidative Phosphorylation 等通路显著退化。退化通路恰好是需要细微纹理信息（如 ECM 结构、免疫浸润模式）的通路——这与"modReLU 截断微弱频率分量"的假说一致。

# 四、AFNO：为什么我们没有走到这一步

## 4.1 AFNO 比 GFNet 多了什么

> 📄 Guibas et al. "Adaptive Fourier Neural Operators." ICLR 2022.

AFNO 是 GFNet 的增强版，主要增加两个机制：

**增强 1：块对角权重（跨通道交互）**
- GFNet：频率 f 的通道 c 只乘以标量权重 w[f,c]
- AFNO：频率 f 的通道被分成若干块，块内做完整的矩阵乘法
- 意义：允许同一频率的不同特征通道相互影响

**增强 2：软阈值收缩**
- 对频域结果施加 `soft_shrink(x, λ) = sign(x) * max(|x| - λ, 0)`
- 意义：幅度小于 λ 的频率分量被归零——"自动去噪"

## 4.2 为什么 AFNO 被取消

AFNO 的触发条件是：

> A1 (modReLU) 达到 🟢 或 🟡 **且** B1a > B1b（频域对照阳性）

实际结果：
- A1 = 🔴 失败（modReLU 退化 -6.1%）
- B1a ≈ B1b（频域旁路无增量）

**两条独立证据线均指向"频域处理在 PFMval 上没有机制性优势"**。AFNO 本质上是 GFNet + 更强的频域操作——如果更简单的频域操作（modReLU、GFNet freq branch）都没有增量，更复杂的 AFNO 不会突然变好。

**教训**：AFNO 的软阈值收缩与 modReLU 的幅度门控在机制上是同源的（都是"抑制弱频率分量"）。modReLU 的失败已经否定了这个方向的基本假设——AFNO 不需要再试。

# 五、CLS 频域旁路：为什么频域信息不能简单叠加

## 5.1 实验设计

CLS 模式是 PFMval 的最强基线（Frozen 0.4113, LoRA 0.4322）。我们想验证：**在 CLS 的预测路径上附加一个处理 patch token 的频域分支，能否提供额外的信息增量？**

```
B1b (对照 — 非频域):                 B1a (频域):
UNI2-H ViT                           UNI2-H ViT
├─ CLS → Linear → [B,1024]          ├─ CLS → Linear → [B,1024]
└─ 64 patch tokens → mean → [B,1536] └─ 64 patch tokens → GFNetBlock → mean → [B,1536]
   → Concat → MLP → 30 通路             → Concat → MLP → 30 通路
```

B1a 和 B1b 的唯一差异：旁路中是 GFNet FFT filter（频域）还是 mean pooling（非频域）。其余完全相同（token 数、concat 结构、MLP head 参数量）。

<details>
<summary><b>📖 折叠概念：什么是 Concat（向量拼接）？为什么用双分支结构？</b></summary>

#### 1. Concat 是什么？—— 胶水，不是搅拌机

**Concat（concatenation，向量拼接）** 是神经网络中最简单也最常用的信息融合方式。

**直觉类比**：你有一张"全局摘要卡片"和一张"局部细节清单"，你不把它们的内容混在一起搅拌，而是把它们**钉在一起**交给下一个人去看。

```
分支 A 的输出:  [0.5,  0.3, -0.2]           ← 3 个数字（CLS 分支，全局摘要）
分支 B 的输出:  [0.8, -0.1,  0.4,  0.9]      ← 4 个数字（patch 分支，局部细节）
                         │
                   Concat（拼接）
                         │
                         ▼
合并后的向量:    [0.5,  0.3, -0.2,  0.8, -0.1,  0.4,  0.9]  ← 7 个数字
                 ├─── 分支 A ────┤  ├──────── 分支 B ────────┤
```

关键特征：
- **信息不丢失**：拼接后的向量完整保留了每个分支的输出，不会因为"搅拌"而混淆
- **维度可不同**：分支 A 可以输出 1024 维，分支 B 输出 1536 维 → 拼接得到 2560 维
- **下游来决定**：拼接后的向量交给 MLP 处理，MLP 自己学习"全局摘要占多少权重、局部细节占多少权重"

**与 Add（加法融合）的对比**：

| 操作 | 做法 | 要求 | 效果 |
|------|------|------|------|
| **Concat** | 向量首尾相接 | 无约束，两个分支维度可以不同 | 信息完整保留，但维度增大 |
| **Add** | 对应位置相加 | 两个分支维度必须相同 | 信息被混合，但维度不变 |

> 在 Transformer 的残差连接（`x = x + Attention(x)`）中用的是 Add；在多尺度特征融合中常用的才是 Concat。

#### 2. 这个实验里的双分支 Concat 在做什么？

回到 §5.1 的图：

```
分支 1 (CLS):    [B, 1536]  →  Linear  →  [B, 1024]    "全局视角"
分支 2 (patch):  [B, 64, 1536]  →  聚合  →  [B, 1536]  "局部细节"
                                        │
                                   Concat（拼接）
                                        │
                                        ▼
                                   [B, 2560]
                                        │
                                      MLP
                                        │
                                        ▼
                                    30 个通路预测
```

**设计者的初衷**（为什么觉得这样会更好）：

- CLS token 是 ViT 最后一层产出的"全局摘要"——它知道"这张 tile 整体是什么组织类型"，但丢失了 patch 级别的空间细节
- 64 个 patch token 保留了"tile 内部不同子区域的特征"——比如左上角是肿瘤细胞团、右下角是间质
- **假说**：把全局摘求和局部细节拼接起来，MLP 就能同时看到"整体是什么"和"局部有什么"→ 更准确的基因通路预测

这个想法在计算机视觉中有一个经典先例——**多尺度特征融合（Multi-Scale Feature Fusion）**。在目标检测（如 FPN）、语义分割（如 U-Net）中，同时利用全局语义和局部细节是已被验证的有效策略。

#### 3. 为什么它在本实验中反而降低了性能？

实验结果是反直觉的：B1b（concat 了 mean patch 信息）的 Val PCC = 0.3955，显著**低于** CLS-only Frozen 基线 0.4113。即使用更复杂的 GFNet FFT 替换 mean pooling，B1a（0.3881）也没有挽回。

**原因分析**：

| 原因 | 解释 |
|------|------|
| **信息冗余** | UNI2-H 的 CLS token 是经过 24 层 ViT Block 处理后的全局表示。在 self-attention 机制下，CLS 已经通过注意力权重间接聚合了所有 patch token 的信息。额外 concat patch 特征是"把同一份信息说了两遍"。 |
| **维度膨胀 → 过拟合** | CLS-only 的 MLP head 是 `1536→1024→512→30`（约 2.1M 参数）。Concat 后变成 `2560→2048→30`（约 5.4M 参数），参数量翻倍不止。在 15K 训练样本下，额外的参数只会去拟合训练噪声。 |
| **破坏 CLS 的预训练语义** | CLS token 在 UNI2-H 预训练阶段被训练为"自包含的图像表示"。强行把其他向量的拼进来，等于告诉 MLP"别信 CLS 自己的判断，再看看这些 patch features"——但 MLP 没有被预训练过如何使用这些额外信息。 |

#### 4. 一句话总结

> **Concat = 把两个信息源的内容钉在一起交给下游。它的优势是信息不丢失，代价是维度增加。在这个实验中，因为 CLS token 本身已经包含了足够的全局信息，钉入额外的 patch 特征只是增加了维度和过拟合风险，而没有带来新的有用信息。**

</details>

## 5.2 结果

| 实验 | Val PCC (best loss) | Peak PCC | vs CLS Frozen (0.4113) |
|------|:---:|:---:|:---:|
| B1b (mean) | 0.3955 | 0.3955 | **-0.0158 (-3.8%)** |
| B1a (gfnet) | 0.3881 | 0.3956 | -0.0232 (-5.6%) |

> 口径说明：`Val PCC (best loss)` 是本项目统一决策口径；`Peak PCC` 只作为训练过程峰值参考。因此，B1a 与 B1b 的峰值几乎相同（0.3956 vs 0.3955），但按统一 best-loss 口径 B1a 低于 B1b（0.3881 vs 0.3955）。

## 5.3 为什么频域旁路没有增量

**第一：B1a 没有显著优于 B1b → 频域处理本身没有提供额外信息。** 按 peak PCC，两者几乎相同（0.3956 vs 0.3955）；按 best-loss PCC，B1a 反而低于 B1b（0.3881 vs 0.3955）。无论采用哪种口径，都看不到 GFNet FFT filter 相比 mean pooling 的机制性增量。

**第二：两者都低于 CLS Frozen 基线 → concat 旁路架构本身就损害了性能。** 这是更重要的发现：即使不加频域，简单地 concat patch token 的聚合信息也会使 CLS 模型变差。原因可能是：
- CLS token 本身已经编码了足够的全局信息，额外 concat 引入了冗余/噪声
- 融合后的 MLP head（2560→2048→30）参数量增加，在 15K 样本下更容易过拟合
- **关键混淆变量**：这些实验同时改变了 `token_select_mode`（legacy→cls_patch64），无法完全排除 cls_patch64 本身对 CLS 模式的负面影响

**第三：频域在"token mixing"场景（GFNet 替换 TransformerEncoder）和"旁路"场景（CLS + freq branch）的行为完全不同。** Token mixing 中频域是主力——取代了整个 attention 机制。旁路中频域只是配角——试图从 patch token 中提取补充信息。主角已经很好（CLS token），配角提供不了增量。

# 六、Mamba / SSM：状态空间模型

## 6.1 什么是状态空间模型 (SSM)？

**一句话**：SSM 是一种用"记忆状态"替代"两两比较"来处理序列的方法。

**类比**：
- **Transformer（自注意力）**：每读一个新句子，你都要回头翻看前面**所有**句子，计算它们与当前句子的关联度。O(N²) 的工作量。
- **SSM**：你有一个"记忆笔记本"（状态向量），每读一个句子就更新笔记本的内容。读完最后一个句子时，笔记本里浓缩了整本书的关键信息。O(N) 的工作量。

SSM 的核心方程：
```
状态更新:  h'(t) = A·h(t) + B·x(t)     （用新输入更新记忆）
输出生成:  y(t)  = C·h(t) + D·x(t)     （从记忆中提取输出）
```

## 6.2 Mamba 的改进

原始 SSM 的 A、B、C 矩阵是**固定的**（对所有输入一样），无法选择性关注。

**Mamba（2023）** 的核心贡献：让 B 和 C 矩阵变成**输入依赖的**（B = f(x), C = g(x)），模型可以根据当前输入的内容**选择性**地记住或遗忘——称为 Selective State Space Model。

## 6.3 MambaIR / VSS Block

Mamba 最初为 1D 文本设计。应用到 2D 图像需要四向扫描：
```
左上→右下 → SSM → ┐
右下→左上 → SSM → ┼→ 合并 → 输出
右上→左下 → SSM → ┤
左下→右上 → SSM → ┘
```

VSS Block = SS2D（四向 Selective SSM）+ FFN，结构上等价于 Transformer Block。

## 6.4 本项目适配性更新

**原评估（06-09）**：MambaIR 排 P2，因为序列太短（65 token）、依赖成本高、核心问题是过拟合而非计算效率。

**实验后更新（06-11）**：

| 维度 | 06-09 评估 | 06-11 更新 |
|------|:---:|------|
| 序列长度 | 65 token 下 SSM 无优势 | 不变。但 C1 证明了 Token 路线不是死路 → 未来可能探索更长序列（265 token），届时 SSM 的线性复杂度才有意义 |
| 核心技术问题 | 过拟合→需要正则化 | 不变。Mamba 的输入依赖机制可能**加重**过拟合（类似 Transformer），而非像 GFNet 的固定滤波器那样抗过拟合 |
| 频域方向关闭的影响 | — | MambaIR 与频域方向**完全独立**。频域关闭不意味着 SSM 不可行——但当前的优先级焦点是 Token+LoRA 而非新架构 |

**结论**：MambaIR 维持 P2 暂停状态。当前优先：Token+LoRA 的跨 fold 验证 → 正则化消融。MambaIR 的评估窗口在 Token+LoRA 完成至少 2-fold 验证后重新打开。

# 七、对本项目的适配性：完整判定

## 7.1 核心挑战回顾

PFMval 面临的最关键问题（按影响程度排序）：

1. **数据量极小**：15K patches / 2 患者训练 → 任何有额外自由度的模型都会快速过拟合
2. **跨患者泛化**：不同患者的组织形态、染色条件差异大 → 模型容易学到患者特异性特征
3. **有效训练窗口极窄**：1-2 epoch → 需要快速收敛 + 强正则化

## 7.2 各方向的最终判定

### 🟢 GFNet FFT Token Mixing（保留但降级）

**适配性**：中等偏上。GFNet 比 Transformer 好 (+3.8%)，但提升来自**参数减少 + 固定滤波器正则化**，而非"频域信息有特殊价值"。GFNet 本质上是**一个更轻量的 Token Mixer**——它在小数据上正则化更强，但不代表频域机制是核心增量来源。

**当前定位**：Token+LoRA 路线的默认 Encoder。不单独作为研究方向。

### 🔴 modReLU / 频域稀疏化（关闭）

**适配性**：不成立。病理图像的关键形态信息分布在大量中等幅度的频率分量上——不是稀疏的。modReLU 的 hard thresholding 截断了有用信息。

### 🔴 CLS 频域旁路（关闭）

**适配性**：不成立。CLS token 已经编码了足够的全局信息。旁路架构本身（无论频域与否）在 CLS 模式下都不如简单的 CLS-only head。

### 🔴 AFNO（取消）

**适配性**：前提不成立。AFNO 的软阈值与 modReLU 的机制同源——modReLU 的失败已经否定了"频域稀疏化"的基本假设。

### 🟢 Token + LoRA（正式路线）

**适配性**：最好。C1 的 0.4169 证明了：
- LoRA 的 backbone 适配增益是跨架构的（CLS 和 Token 模式都是 +5.1% vs frozen）
- Token 模式 + GFNet Encoder + LoRA 首次超越了 CLS Frozen 基线
- 健康的多通路正增益（Wound Healing, Coagulation, Angiogenesis, ECM, G2M, hypoxia）——不是靠少数通路拉高均值

**当前定位**：仅次于 CLS LoRA 的第二强配置。需要 Fold2/3 交叉验证确认稳定性。

### 🟡 MambaIR / VSS Block（暂停）

**适配性**：未知。频域方向的关闭与之无关——Mamba 是完全不同的机制。但当前优先级是 Token+LoRA 验证，而非新架构探索。评估窗口后移。

## 7.3 核心教训

**"频域信息对病理图像有特殊价值"是一个有吸引力的假说，但实验证明它不成立——至少在当前的任务设定、数据量和模型规模下不成立。**

为什么假说落空了？三个可能的原因：

1. **1D token 序列 FFT ≠ 2D 图像 FFT**。我们做 FFT 的对象是 ViT token 序列，不是原图像素。Token 序列的"频率"反映的是相邻 token 间特征变化的节律——这确实包含信息，但不等同于"纤维束方向→频率峰值"的 2D 物理直觉。

2. **CLS token 已经足够好**。UNI2-H 的 ViT backbone 在预训练阶段已经学会了从 patch token 中提取全局信息并压缩到 CLS token 中。额外的 patch token 聚合（频域或非频域）只是引入了冗余信息。

3. **小数据的正则化需求压倒一切**。在这个数据量下，任何增加模型自由度（而非减少）的操作都会导致过拟合。GFNet 成功是因为它**减少了**自由度；modReLU 失败是因为它**增加了**自由度（bias 参数 + 非线性门控）。
