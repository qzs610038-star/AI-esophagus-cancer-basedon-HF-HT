## 一、结论先行

本轮重跑建议统一为：

```text
每个 MPP 划分:
  六例非 XZY 患者全部进入候选训练池
  每例患者独立划出约 10% patch/group 作为 internal val
  剩余 patch 作为 train
  MPP-2/XZY 固定为 external test，只在 best checkpoint 固定后评估一次
```

核心变化：

1. 内部验证不再用“整例 HYZ 或 ZHZ 留出”，改为六例患者每例各留 10%，保证训练集仍覆盖六例患者的患者间差异。
2. MPP-3 与 MPP-5 是 50% 步长重叠 patch，不能随机 patch split；必须使用空间 block + overlap embargo 算法，避免同一物理视野或高度重叠视野同时进入 train 与 val。
3. z-score 必须在 split 之后拟合：只用 train split 拟合 mean/std，再用同一套参数转换 train、internal val、external XZY。
4. 每个 MPP 生成独立的 `split_manifest.csv`、`zscore_params.json/csv`、`zscore_manifest.json`，训练脚本只读取这些 manifest，不允许不同人手工拼路径。

本计划仍是初稿；末尾列出需要你拍板的问题。

## 二、统一数据边界

| 层级 | 数据 | 用途 | 能否参与 z-score 拟合 | 能否参与 epoch 选择 |

| Train | MPP-N 六例患者每例约 90% 可用样本 | 训练 MLP、拟合 z-score | 是 | 是，作为 train loss |

| External Test | 固定 MPP-2/XZY | 最终外部泛化报告 | 否 | 否 |


## 三、内部验证集划分方案

### 3.1 MPP-1/2/4：100% 步长或非重叠主线

对 MPP-1、MPP-2、MPP-4，内部验证建议使用患者内空间 block split，而不是纯随机 patch split。

算法草案：

1. 从 patch stem 或标签列解析 `x,y` 坐标。
2. 每例患者单独处理，禁止跨患者混排后再抽样。
3. 将 patch 按空间坐标划入 coarse block，例如：

   ```text
   block_x = floor(x / block_size)
   block_y = floor(y / block_size)
   block_id = patient + ":" + block_x + ":" + block_y
   ```

4. `block_size` 初始建议取 `3 * 224 = 672 px`，后续可根据实际 patch 坐标密度调整。
5. 用固定 seed 对 block 抽样，直到该患者 internal val 样本数接近 10%。
6. 被选中的 block 全部进入 internal val，其余 block 进入 train。
7. 输出 `split_manifest.csv`，每行至少包含：

   ```text
   mpp_id,patient,patch_stem,x,y,split,block_id,overlap_group_id,reason
   ```

验收标准：

- 每例患者 internal val 比例落在 8%-12%。
- train/internal val 患者集合完全一致，均覆盖六例患者。
- 同一 `patch_stem` 不得重复出现在不同 split。
- dataset 加载时禁止回退到无坐标/无 ID 的行序匹配。

### 3.2 MPP-3/5：50% 步长重叠实验

MPP-3 与 MPP-5 的关键风险是相邻 patch 物理视野大量重叠。如果直接随机抽 10%，训练集很可能包含与验证 patch 重叠 50% 甚至更高的邻居，内部 val 会虚高。

推荐算法：空间 block 抽样 + overlap embargo。

**定义 patch 视野**

默认 patch 大小为 224 px。两个 patch 的 top-left 坐标分别为 `(x1,y1)`、`(x2,y2)`，若满足：

```text
abs(x1 - x2) < 224 and abs(y1 - y2) < 224
```

则两者视野有重叠，不能分别进入 train 与 internal val。

**划分步骤**

1. 每例患者独立建立 patch 表：

   ```text
   patch_stem, x, y, bbox = [x, y, x+224, y+224]
   ```

2. 用 coarse block 抽取候选 internal val block，目标为该患者总 patch 的约 10%。
3. 将候选 block 中 patch 标为 `internal_val`。
4. 对每个 internal val patch，查找所有与其 bbox 重叠的 patch。
5. 若重叠 patch 不在 internal val 中，则标为 `embargo`，不参与训练、不参与验证、不参与 z-score 拟合。
6. 其余 patch 标为 `train`。
7. 若最终 internal val 占比低于 8% 或高于 12%，调整候选 block seed 或 block size，但不能取消 embargo。

这个方案的代价是 MPP-3/5 会丢弃一部分 internal val 周边 patch；这是防泄漏成本，应在报告中公开。

**必须输出的审计文件**

`overlap_embargo_audit.csv`：

```text
mpp_id,patient,val_patch,neighbor_patch,dx,dy,iou,neighbor_final_split
```

通过条件：

```text
不存在 iou > 0 的 train/internal_val 配对
```

建议脚本在发现重叠泄漏时直接失败：

```text
[ERROR] overlap leakage: train patch overlaps internal val patch
```

## 四、z-score 统一分配

### 4.1 拟合边界

所有 MPP 统一使用以下顺序：

```text
先 split -> 再拟合 z-score -> 再训练
```

z-score 参数只能由 `split=train` 的样本拟合：

```text
fit_df = raw_labels where split == "train"
mean = nanmean(fit_df[pathways])
std  = nanstd(fit_df[pathways], ddof=1)
std == 0 -> 1.0
```

不得使用：

- internal val 的标签拟合 z-score。
- external XZY 的标签拟合 z-score。
- train+val 合并拟合 z-score。
- sklearn `StandardScaler` 默认 `ddof=0` 口径。
- 已经 z-scored 的队友标签再次拟合二次 z-score。

### 4.2 转换边界

同一套 train-only 参数应用到：

| 数据 | 转换方式 |
|------|----------|
| Train | 使用本 MPP train-only mean/std |
| Internal Val | 使用本 MPP train-only mean/std |
| External XZY | 使用本 MPP train-only mean/std |

也就是说，MPP1-MPP5 各有一套自己的 z-score 参数，因为各自训练输入分布不同。XZY 虽然固定来自 MPP-2，但在每个 MPP 实验中都必须用该实验训练集的参数转换标签，不能复用其他人生成的 XZY z-score。

### 4.3 指标报告建议

PCC 对线性缩放不敏感，可作为主排序指标继续使用。

MAE/R2 会受 z-score 参数影响。为避免 MPP 间 MAE/R2 不可比，建议同时保存 raw-scale 评估：

1. 模型训练仍在 z-score 空间完成。
2. 预测后用本 MPP 的 train-only mean/std 对预测值 inverse transform。
3. 与 XZY raw ssGSEA 标签计算 raw MAE/R2。
4. 报告同时列出：

   ```text
   external_xzy_pcc_zspace
   external_xzy_mae_zspace
   external_xzy_r2_zspace
   external_xzy_mae_raw
   external_xzy_r2_raw
   ```

如果第一轮不实现 raw-scale inverse transform，则报告中必须注明 MAE/R2 是各自 z-score 空间下的辅助指标，不作为跨 MPP 主排序依据。

### 4.4 参数文件

每个 MPP 输出：

```text
mpp_standard_splits/
  group_{N}/
    split_manifest.csv
    zscore_params_from_train.json
    zscore_params_from_train.csv
    zscore_manifest.json
    labels/
      train/{patient}/{patient}_ssGSEA_zscore.csv
      val/{patient}/{patient}_ssGSEA_zscore.csv
      external/XZY/XZY_ssGSEA_zscore_by_group_{N}_train.csv
```

`zscore_manifest.json` 至少包含：

```json

  "mpp_id": 3,
  "fit_split": "train",
  "fit_patients": ["HYZ15040", "JFX", "LMZ12939", "TGC", "XSL", "ZHZ"],
  "excluded_splits": ["internal_val", "external_test", "embargo"],
  "ddof": 1,
  "clip_applied_after_transform": true,
  "clip_range": [-100, 100],
  "split_seed": 42,
  "val_ratio_target": 0.1,
  "overlap_policy": "bbox_embargo_for_mpp3_mpp5"
```


## 十、Gemini 评审决议与方案优化

本部分记录经 Gemini AI 评审后确立的实验决议与方案优化建议：

### 1. 待确认问题决议
* **Q1 (Embargo 策略)**：**接受**。防泄漏是模型泛化的底线。
* **Q2 (验证集比例)**：**允许 8%-12% 弹性浮动**，以适配 coarse block 网格。
* **Q3 (外部测试集)**：**固定使用 MPP-2/XZY**，确保跨 MPP 比对的对照基准一致。
* **Q4 (Raw 标签获取)**：**必须采用原始标签**计算 z-score，缺失的 MPP 需追溯重建，不可使用已被他人归一化的数据。
* **Q5 (反归一化 MAE)**：**作为 P1 任务本轮直接实现**，保证误差度在物理尺度上具有可比性。

### 2. MPP-3/5 样本流失风险与应对
* **风险**：若 block 尺寸过小，Embargo 隔离带会造成严重的训练样本流失（可能达 30%-50%）。
* **应对**：在 split 时适当增大 coarse block size（如设为 $5 \times 224 = 1120$ px 或更大），以减小隔离带的周表比，最大化保留训练样本。

### 3. 空间连续性影响与未来演进
* **影响**：当前划分在切片内随机挖空 Block 和 Embargo 区域，会破坏空间图拓扑连通性。这在推理后处理时没有影响，但未来若在**训练阶段**引入空间 GNN 或 Patch-level Transformer，会导致图卷积受阻。
* **演进方案**：若未来采用空间感知训练，数据集划分需升级为：
  1. **巨型子图划分**：切片一分为二（如左右半），只在分界线处施加 embargo，保留两侧极高的内部图连通性；
  2. **患者级留一法**：以整例患者为划分单位，完全不破坏任何空间连续性。

## 十一、Codex 评判与执行定版

结论：Gemini 的决议总体采纳，且与本方案的防泄漏边界一致。以下作为后续执行的定版口径。

### 1. 对 Gemini 决议的评判

| 项 | Codex 评判 | 执行口径 |
|----|------------|----------|
| Embargo 策略 | 采纳。MPP-3/5 的 50% overlap 是真实泄漏通道，宁可牺牲样本量也不能让重叠视野跨 train/val。 | MPP-3/5 必须启用 bbox overlap embargo；发现 train-val overlap 直接失败。 |
| 8%-12% 验证比例 | 采纳。空间 block 和 embargo 会让精确 10% 不现实，弹性范围合理。 | 每例患者 internal val 目标 10%，允许 8%-12%；超出范围必须在 manifest 写明原因。 |
| 固定 MPP-2/XZY | 采纳。统一外部测试集是 MPP1-5 横向比较的控制变量。 | XZY 继续固定为 MPP-2/XZY；所有 MPP 只在 best checkpoint 固定后评估一次。 |
| Raw 标签重建 z-score | 强采纳。队友 z-scored 标签口径不统一，不能作为本轮统一标准的输入。 | 统一从 raw `{patient}_ssGSEA.csv` 生成 split 后 train-only z-score；拿不到 raw 标签的 MPP 暂不进入主比较。 |
| Raw-scale MAE/R2 | 采纳为 P1，并纳入本轮分析交付。 | 训练仍用 z-score 空间；报告必须同时输出 z-space 指标和 raw-scale MAE/R2。若 raw 标签缺失，则该 MPP 标记为不可完整比较。 |

### 2. 对 block size 建议的补充约束

Gemini 提出的 `5 * 224 = 1120 px` 或更大 block size 是合理方向，但不能简单写死。block size 需要由数据审计结果选择，推荐先比较三档：

```text
3 * 224 = 672 px
5 * 224 = 1120 px
7 * 224 = 1568 px
```

选择准则按优先级排序：

1. MPP-3/5 无 train-val overlap 泄漏。
2. 每例患者 internal val 比例落在 8%-12%。
3. `embargo / total` 尽量低，原则上优先低于 30%；若达到 30%-50%，必须在结果解释中降级该 MPP 的有效样本量结论。
4. internal val 覆盖多个空间区域，避免只抽到切片边缘或单一组织区域。

因此后续 split 脚本不应只有一个固定参数，而应输出 `split_candidate_summary.csv`：

```text
mpp_id,patient,block_size,total_n,train_n,val_n,embargo_n,val_ratio,embargo_ratio,n_val_blocks,leakage_pairs
```

最终采用的 block size 必须在 `split_manifest.csv` 和 `zscore_manifest.json` 中记录。

### 3. 空间连续性的定位

Gemini 关于空间连续性的提醒成立，但它是未来空间模型的约束，不阻断当前 frozen UNI2-h feature + MLP 重跑。

当前路线的输入是逐 patch 预提取特征，MLP 不依赖图拓扑或邻域消息传递；block/embargo 造成的空间不连续主要影响样本分布与有效样本量，不影响模型结构可运行性。

若后续升级到空间 GNN、Patch-level Transformer、邻域聚合或图正则，本方案的 patch-level block split 不再自动适用，需要单独设计：

```text
空间模型路线:
  优先级 1: 患者级留一
  优先级 2: 巨型连续子图划分 + 分界线 embargo
  不建议: 随机 scattered block split
```

### 4. 定版后的待办调整

在第六节执行步骤中，后续实现时需显式补充两项：

1. 在步骤 2 后增加 `split_candidate_summary.csv` 生成与人工确认，尤其用于 MPP-3/5 的 block size 选择。
2. 在步骤 8 的统一分析报告中强制加入 raw-scale MAE/R2 表，不再把它作为可选附录。

### 5. 最终 Go/No-Go

Go：可以按 Gemini 决议进入实现设计。

保留门槛：

- 任何 MPP 缺 raw 标签，不能进入主排序。
- MPP-3/5 任一 train-val overlap 泄漏未清零，不能启动正式训练。
- raw-scale MAE/R2 未产出时，PCC 可先用于 smoke 判断，但不能形成最终 MPP1-5 定版结论。
