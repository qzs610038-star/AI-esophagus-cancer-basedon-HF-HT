# MPP 五划分验证执行计划

更新时间：2026-07-01

> 目标：本周完成 5 种基于 MPP 的 Visium HD patch 划分方案的统一模型验证，明确哪一种划分方式更适合作为后续跨患者训练和外部验证主线。

## 一、结论先行

### 1. 统一测试模型

本轮统一使用 **UNI2-h 冻结特征 + 两层 MLP 回归头**。

选择理由：

- 本次实验要验证的是 **5 种 MPP 划分方法**，不应同时引入 LoRA、Token/GFNet、频域分支等额外变量。
- 冻结 UNI2-h 只训练两层 MLP，变量最少，训练成本低，更适合作为 MPP 划分方式的公平对照。
- 该设定直接回答“不同 MPP/步长切分下，UNI2-h 基础特征对外部 XZY 的泛化差异”，不会混入 backbone 微调带来的不确定性。
- 本轮命令、实验 ID 和报告中不再使用 `lora` / `cls_lora_r8` 命名，避免与旧在线 LoRA 主线混淆。

备选复核模型：

- LoRA、Token+LoRA、GFNet/频域路线只作为后续 P1 复核，不进入本周 P0 主矩阵。
- 若 UNI2-h + 两层 MLP 在 5 个划分中的排序稳定，可先据此决定 Top1/Top2 MPP，再另行规划是否追加 LoRA 复核。

### 2. 本周主实验矩阵

先做 **XZY 外部验证集固定** 的 5 组对比。

| 编号 | 划分方式 | MPP | 步长 | 外部验证集 | 模型 | 本周优先级 |
|---|---|---:|---:|---|---|---|
| MPP-1 | 原最高分辨率 | 0.17/0.13/0.27 | 100% | XZY | UNI2-h + 2-layer MLP | P0 |
| MPP-2 | 与 79 例队列一致 | 0.27 | 100% | XZY | UNI2-h + 2-layer MLP | P0 |
| MPP-3 | MPP-2 增量重叠版 | 0.27 | 50% | XZY | UNI2-h + 2-layer MLP | P0 |
| MPP-4 | 接近 20x/0.5 MPP 预训练尺度 | 0.54 | 100% | XZY | UNI2-h + 2-layer MLP | P0 |
| MPP-5 | MPP-4 增量重叠版 | 0.54 | 50% | XZY | UNI2-h + 2-layer MLP | P0 |

统一原则：

- 外部验证集固定为 **编号 2、MPP 0.27、步长 100% 的 XZY**，对应最新情报要求。
- 默认建议 6 个非 XZY 患者全部进入训练，外部 XZY 不参与训练、调参或 epoch 选择；是否额外划分内部验证集见后续 Claude 评审框架。
- 服务器 MPP 目录中的 `{patient}_ssGSEA.csv` 仍是原始 ssGSEA 分数，训练前必须先做 z-score 标准化；标准化参数只能用训练集拟合，再应用到训练集、可选内部验证集和外部 XZY，避免标签分布泄漏。
- 所有实验采用同一模型、同一训练参数、同一随机种子策略、同一指标口径。
- 默认 `val_strategy=none` 时使用固定预算训练和 final checkpoint；若评审决定启用内部验证集，才按 internal `val_loss` 最小选择 best checkpoint，不能按外部 XZY 选择 epoch。
- 主要报告指标：外部 XZY Test PCC、Test MAE、Test R2、逐通路 PCC、Train-Val Gap、训练样本数、外部验证样本数。

## 八、结果判定标准

主排序：

1. 外部 XZY Test PCC 均值最高。
2. 若 PCC 接近，优先选择 Test MAE 更低、R2 更稳定者。
3. 若总指标接近，优先选择逐通路退化更少者。
4. 若 MPP-3/MPP-5 因重叠 patch 获得高 PCC，但 Train-Val Gap 明显扩大，不能直接判为最佳。
5. 若 MPP-4/MPP-5 patch 数太少导致方差大，即使接近预训练 MPP，也需谨慎。

建议成功标准：

- Top1 相比 MPP-2 至少提升 `+0.01 PCC`，可作为明确改进。
- Top1 与 MPP-2 差距小于 `0.005 PCC`，优先选更简单、更少泄漏风险、更少重叠的 MPP-2。
- 任一方案出现 NaN、明显数据泄漏、外部验证混入训练，整组标记为无效，不进入排序。

## 九、MPP 初学者文档大纲

文档标题：

`MPP定义与训练影响_初学者指南_20260701.md`

建议结构：

1. MPP 是什么
   - MPP = microns per pixel，即每个像素代表多少微米。
   - MPP 越小，分辨率越高，同样 224 像素看到的真实组织范围越小。
   - MPP 越大，分辨率越低，同样 224 像素看到的真实组织范围越大。
2. MPP 与放大倍数的关系
   - 常用近似：0.5 MPP 对应 20x，0.25 MPP 对应 40x。
   - 本项目当前记录：79 例队列约 0.22 MPP，Visium HD 有 0.17/0.13/0.27，基础模型常见尺度约 0.50 MPP。
3. 224 x 224 patch 的物理视野
   - 0.13 MPP：约 29.12 微米宽。
   - 0.27 MPP：约 60.48 微米宽。
   - 0.54 MPP：约 120.96 微米宽。
   - 因此 0.13 MPP 下 4 个像素覆盖的真实长度约等于 0.27 MPP 下 2 个像素，不是简单“更清楚就更好”。
4. 为什么病理基础模型在 MPP 不匹配时可能退化
   - 预训练时模型见过的纹理尺度与下游输入尺度不同。
   - 细胞核大小、腺体结构、间质纹理在 token 中的尺度分布改变。
   - 0.13 MPP 可能过细，模型看到局部细胞细节但失去更大组织结构。
   - 0.54 MPP 可能贴近 20x 预训练尺度，但 patch 数减少，空间转录组监督样本变少。
5. 步长 50% 的利弊
   - 优点：patch 数量增加。
   - 缺点：patch 间高度重叠，训练样本相关性增强，可能夸大有效样本量。
   - 必须避免重叠 patch 跨 train/test 泄漏。
6. 为什么本周先固定 XZY
   - 先把问题缩小为“5 个划分谁更适合外部验证”。
   - XZY 固定后，后续再做交叉留一，成本更可控。
7. 如何读结果
   - 不只看 PCC 均值。
   - 看通路级表现、Train-Val Gap、失败通路、数据量变化、外部验证稳定性。

## 十、风险矩阵

| 风险 | 概率 | 影响 | 缓解 |
|---|---:|---:|---|
| 现有训练脚本只能处理旧 3 患者 fold，不能直接处理 7 例 XZY 外部验证 | 高 | 阻塞训练 | A 先做 1 epoch dry-run，必要时新增配置入口或外部验证参数 |
| 直接使用未 z-score 的原始 ssGSEA 标签 | 高 | 指标不可比、训练尺度异常 | 训练前先用训练集拟合 z-score 参数并转换所有标签；保存参数和标准化 CSV |
| 标签 CSV 与新 patch stem 不匹配 | 中 | 训练无效 | 训练前输出交集审计表，交集不足 100% 不启动 |
| MPP-3/5 重叠 patch 泄漏 | 中 | 结论虚高 | 默认不划内部验证集，按患者级外部验证固定 XZY；若启用内部划分，必须检查重叠组只在 train 内或 val 内 |
| MPP-4 patch 数太少 | 中 | 结果方差大 | 记录样本数，必要时增加随机种子复跑或只作为辅证 |
| UNI2-h 权重离线加载失败 | 中 | 训练阻塞 | 先跑 `HF_HUB_OFFLINE=1` 加载 smoke test |
| 训练过拟合窗口很短 | 高 | final checkpoint 可能偏晚或内部 best epoch 不稳定 | 默认固定预算并统一 epoch；若启用内部验证集，按 internal val_loss 保存 best 并记录 Train-Val Gap |
| 5 组训练时间超出本周 | 中 | 延误决策 | 先 1 epoch 全部冒烟，再优先跑 MPP-2、MPP-4、MPP-1，最后跑重叠版 |
| README 示例参数 `--epochs` 与脚本真实参数不一致 | 高 | 命令启动失败 | 使用脚本真实参数 `--num_epochs` |
| 服务器同步误删训练结果 | 低 | 严重数据丢失 | 禁止 `git clean -fd`，训练结果先归档再同步 |

## 十一、优先级降级策略

如果本周时间不足：

1. 必跑：MPP-2、MPP-4、MPP-1。
2. 次优先：MPP-3。
3. 最后：MPP-5。

原因：

- MPP-2 是与 79 例队列接近的自然基线，也是指定外部验证集来源。
- MPP-4 是与常见 20x/0.5 MPP 基础模型更接近的关键假设。
- MPP-1 是原最高分辨率对照。
- MPP-3/5 主要检验“重叠增加样本量是否有价值”，但泄漏和相关性风险更高。
