## 二、路径适配方案

### 2.1 现有代码 vs 队友布局的接口差异

| 维度 | 现有代码约定 | 队友实际布局 |
|------|------|------|
| 缓存目录 | `{cache_root}/{mpp_id_int}/{patient}/*.pt` | `{cache_root}/MPP{mpp_id}_UNI/{patient}/*.pt` |
| 训练标签 | `{labels_root}/mpp{mpp_id}_{patient}_zscored.csv` | `{labels_root}/group_{mpp_id}/train/{patient}/{patient}_ssGSEA_zscore.csv` |
| 验证标签 | 同上（同一目录） | `{labels_root}/group_{mpp_id}/val/{patient}/{patient}_ssGSEA_zscore.csv` |
| 外部标签 | `{labels_root}/mpp{ext_id}_{patient}_zscored.csv` | `{labels_root}/group_{train_id}/external/XZY/XZY_ssGSEA_zscore_by_group_{train_id}_train.csv` |
| z-score 参数 | `{cache_root}/zscore_params_mpp{id}.json` | `{labels_root}/group_{id}/zscore_params_from_train.csv` |

> 关键点：外部 XZY 标签使用 `group_{train_mpp_id}` 的参数变换（而非 external_mpp_id），因为 z-score 参数是在训练组上拟合的。

### 2.2 结论：代码改动方案（推荐）

**不新建独立脚本，在 `train_mpp_uni2h_mlp.py` 中新增 `--use_partner_paths` 标志**，当启用时切换路径拼接逻辑。向后完全兼容（默认走原有逻辑）。

改动量估算：

| 文件 | 改动 | 行数 |
|------|------|:---:|
| `train_mpp_uni2h_mlp.py` | 新增 `--use_partner_paths` 参数 + 路径分支逻辑 | ~60行 |
| `dataset_mpp.py` | **无需修改**（`barcode` 列已在 ID 匹配策略的候选列表中） | 0 |
| `prepare_mpp_zscore.py` | **无需修改**（队友已完成，不重跑） | 0 |
| `extract_uni2h_mpp.py` | **无需修改**（队友已提取） | 0 |
| `scripts/finalize_experiment.py` | **无需修改** | 0 |

### 2.3 为什么不做目录重组

队友数据在服务器 `D:\AIPatho\...`，本机无法直接访问。服务器上重组目录（junction 到 `MPP1_UNI → 1`）虽然可行但引入了隐式依赖——队友后续更新缓存时 junction 目标不变。相比之下，代码显式支持队友布局更干净、可审计。

## 三、代码改动（已实施）

以下修改已完成并通过语法验证：

### 3.1 `train_mpp_uni2h_mlp.py` — 改动摘要

**新增 CLl 参数**（L199-L204）：
- `--use_partner_paths`：启用队友目录布局
- `--auto_split`：自动从 `split_info.json` 读取 train/val 划分

**partner 模式自动默认值覆盖**（~L213）：当 `--use_partner_paths` 时，`--cache_root` 默认覆盖为 `D:\AIPatho\qzs\pfmval_deploy_git\uni2h_cache`，`--labels_root` 默认覆盖为 `D:\AIPatho\ljx\MPP1_4_uni\patch_split_zscore`。用户也可显式传参覆盖。

**新增路径构造函数**（~L80-L130）：
- `_build_cache_dir()` — `MPP{N}_UNI/{patient}` vs `{mpp_id}/{patient}`
- `_build_train_label()` — `group_{id}/train/{p}/{p}_ssGSEA_zscore.csv`
- `_build_val_label()` — `group_{id}/val/{p}/{p}_ssGSEA_zscore.csv`
- `_build_external_label()` — `group_{train_id}/external/XZY/XZY_ssGSEA_zscore_by_group_{train_id}_train.csv` ⚠️ 使用 `train_id` 而非 `external_id`
- `_build_zscore_params_path()` — `zscore_params_from_train.csv` vs `zscore_params_mpp{id}.json`

**新增预检函数** `_run_preflight()`：训练前顺序打印所有 train/val/external 的 cache path、label path、.pt 文件数、CSV 行数，任一路径缺失则中止。

**新增 z-score 加载函数** `_load_zscore_params()`：partner 模式从 `split_info.json` 推断 fit_patients，读 `zscore_params_from_train.csv` 获取通路参数；标准模式读 JSON。

**训练集/验证集/外部测试集路径拼接**全部改为调用路径构造函数，根据 `partner` 标志分支。

**`model_params.txt`** 新增 `use_partner_paths=` 行。

### 3.2 `dataset_mpp.py` — 改动摘要

`merge_mpp_patients()` 新增 `partner: bool = False` 参数。当 `partner=True` 时使用队友布局拼接 cache_dir 和 label_csv。

### 3.3 向后兼容性

- `--use_partner_paths` 默认 `False`，不传则 100% 原逻辑不变
- 现有 MPP-3/V3/V3bis 命令无需任何修改
- `dataset_mpp.py` 的 `partner` 参数默认为 `False`，所有已有调用方无影响

## 四、训练命令

以下命令按服务器路径书写。在本机测试时，把 `--cache_root` 和 `--labels_root` 显式指向本地副本。

### 4.1 环境变量

```powershell
$env:PYTHONIOENCODING = "utf-8"
$env:HF_HUB_OFFLINE = "1"
$env:OMP_NUM_THREADS = "8"
$env:MKL_NUM_THREADS = "8"
```

### 4.2 推荐命令（使用 --auto_split）

`--auto_split` 自动从 `split_info.json` 读取 train/val 划分，省去手动传 `--train_patients --val_patient`，避免手误：

```powershell
# MPP1 smoke (3 epoch)
python -u train_mpp_uni2h_mlp.py `
  --use_partner_paths --auto_split `
  --train_mpp_id 1 `
  --external_mpp_id 2 --external_patient XZY `
  --num_epochs 3 --patience 3 `
  --batch_size 32 --lr 1e-4 --seed 42 --num_threads 8 `
  --dataset_name mpp1_partner_valHYZ_xzy_ext_uni2h_mlp_smoke_20260704

# MPP4 smoke
python -u train_mpp_uni2h_mlp.py `
  --use_partner_paths --auto_split `
  --train_mpp_id 4 `
  --external_mpp_id 2 --external_patient XZY `
  --num_epochs 3 --patience 3 `
  --batch_size 32 --lr 1e-4 --seed 42 --num_threads 8 `
```
