## 二、MPP1/4 训练排错经验

### 踩坑 1：`--train_patients` required=True 与 `--auto_split` 冲突

**现象**：`argparse` 在 `--auto_split` 逻辑执行前就要求 `--train_patients`，直接报错退出
**修复**：改为 `default=""`，解析后手动检查"两者至少有一个"
**教训**：新增自动推理参数时，被其覆盖的 `required=True` 参数必须改为 optional

### 踩坑 2：缓存目录有 train/val 子层级

**现象**：`_build_cache_dir` 输出 `MPP1_UNI/JFX/`，但实际 `.pt` 在 `MPP1_UNI/JFX/train/` 下
**修复**：新增 `split` 参数，partner 模式拼接 `/{split}` 后缀
**教训**：队友的目录结构与预期不一致是常态，preflight 打印 0 个 .pt 时应立刻怀疑路径层级

### 踩坑 3：`.pt` 文件存的是全部 token 而非 CLS

**现象**：`feat_dim=265`，MLP 按 `in_dim=265` 构建 Linear → `[32,265,1536] × [265,1024]` 维度崩溃
**修复**：`dataset_mpp.py` 的 `__getitem__` 自动检测 2D → 取 `[0, :]`（CLS token）
**教训**：`feat_dim` 的检测逻辑不应假设缓存一定是 1D；需加 ndim 判断，2D 取 shape[1]

### 踩坑 4：XZY 缓存只在 MPP1_UNI 下完整

**现象**：MPP4_UNI/XZY/train/ 只有 269 patches 且坐标与标签 CSV 不匹配
**修复**：partner 模式 XZY 固定从 MPP1_UNI 加载（XZY 是同一物理样本）
**教训**：外部测试集的特征缓存应只存一份，所有 MPP 轮次共享；但队友的提取脚本可能重复提取，导致部分 MPP 的 XZY 数据不完整

## 三、正式训练结果回传后需同步给队友的内容

### 3.1 必须同步（实验结果）

| 内容 | 格式 | 说明 |
|------|------|------|
| MPP1 正式训练 XZY PCC / MAE / R² | 数值 | 核心外部评测指标 |
| MPP4 正式训练 XZY PCC / MAE / R² | 数值 | 同上 |
| 最佳 epoch | 数值 | val_loss 选出的 best epoch |
| `predictions.csv` | 文件 | XZY 外部测试预测（`true_`/`pred_` 列名） |
| `per_pathway_pcc_*.csv` | 文件 | 逐通路 PCC 排名，队友可验证通路级一致性 |
| `training_history.csv` | 文件 | 逐 epoch 指标，队友可分析收敛曲线 |
| 训练配置摘要 | 文本 | batch_size/lr/seed/patience 等超参数 |

### 3.2 可选同步（方法学参考）

| 内容 | 说明 |
|------|------|
| 三层信号源分离协议 | Train 5 + Val HYZ15040 + Ext XZY 的划分逻辑和 z-score 防泄漏审计 |
| val_loss 早停机制 | 避免 MPP-3 frozen-MLP 过拟合的教训 |
| `--use_partner_paths` 参数 | 队友后续 MPP 轮次可直接传此参数，无需手动填路径 |
| `--auto_split` 参数 | 自动从 `split_info.json` 读取 train/val 划分，避免手误 |

### 3.3 需要队友确认/对齐的事项

| 事项 | 说明 |
|------|------|
| MPP2 和 MPP5 的特征缓存是否已提取？ | 如果队友负责 MPP2/5，同样可复用本代码 |
| XZY 外部测试标签 CSV 命名规范 | 当前为 `XZY_ssGSEA_zscore_by_group_{N}_train.csv`，如果 MPP2/5 需要用 `group_2`/`group_5` 的参数 |
| 后续实验是否统一用 HYZ15040 做内部验证？ | 维持一致性可横向对比所有 MPP 的 val_loss/PCC |
| 特征缓存文件格式是否需要统一为 CLS-only [1536]？ | 当前 265-token [265,1536] 格式每次加载都要取 [0,:]，有微小但持续的 I/O 浪费 |
