## 执行摘要

针对 PFMval 项目的核心挑战（15K-18K patches / 3 患者 / 跨患者泛化衰减 31%-77% / 有效训练窗口仅 1-2 epoch），本报告对 **2 个 Mamba 系列模块** 和 **9 个频域系列模块** 进行了系统性迁移可行性评估。

**核心结论**（修订后）：
1. **GFNet 仍是最高性价比迁移目标（P0）** — 零依赖 FFT 全局滤波器，TokenEncoder 参数量下降 ~25%（非初版宣称的 60%+），代码改动量 ~80 行。**但必须先修复 model_online_tokens.py 接口 + 建立 65-token Transformer baseline，再跑 GFNet 消融。**
2. **AFNO 紧随其后（P1）** — 块对角频率混合 + 软阈值收缩，表达能力 > GFNet，但需额外调参成本。
3. **MambaIR VSS Block 降为 P2** — 默认 65 tokens 下 Transformer 的 O(N²) 瓶颈不显著；mamba-ssm 的 CUDA 依赖和方向扫描设计成本高于频域方案。**待 GFNet/AFNO 方向确认有效后再评估。**
4. **AFFNet / SpectFormer 作为中远期选项（P2）** — 分别代表自适应滤波和双分支融合，需 9 患者数据支撑。
5. **ConvSSM / FlashFFTConv / TimesNet / FourierGNN / FourCastNet 不适合迁移（P3/不推荐）**

**最大发现（修正后）**：GFNet 的 FFT 全局滤波器可能捕获单 patch 内部的组织纹理频率模式（纤维走向周期、细胞排列密度），这部分频域信息在当前的纯空间 TransformerEncoder 中完全缺失。虽然与切片级坐标编码不在同一空间层级，但频域特征补充本身对病理图像是有物理意义的。

# 一、项目架构回顾与瓶颈分析

## 1.1 当前两种模型架构

### CLS 模式（`model_online_cls.py`）✅ 可运行

```
H&E Patch [B,3,224,224]
  → UNI2-H ViT Backbone (24 blocks, 可选 LoRA)
  → CLS Token [B, 1536]
  → Linear+LayerNorm → [B, 1024]
  → +Coord Embeddings (x_embed + y_embed)
  → MLP Head (1024→2048→GELU→Dropout→30)
  → ssGSEA Predictions [B, 30]
```

**特点**：仅用 CLS token，丢弃了 264 个 patch token 的空间信息。参数量 ~4M（不含 backbone）。训练极快。**代码可正常运行，已有 Fold1 完整结果（LoRA=0.4322）、Fold2 有可参考结果（LoRA=0.3726, exit=1）、Fold3 未成功。**

### Token 模式（`model_online_tokens.py`）⚠️ 接口 bug，当前无法运行

```
H&E Patch [B,3,224,224]
  → UNI2-H ViT Backbone
  → Token Sequence [B, 65→265, 1536]    ← 默认 65 tokens (lite 模式)
  → LightweightTokenEncoder:             ← ⚠️ 传入参数不兼容
      input_proj (1536→512)
      → TransformerEncoder (1 layer, 8 heads, d_ff=1024)
      → Global Mean Pooling
      → output_proj (512→1536)
      → LayerNorm
  → [B, 1536] → +Coord Embeddings → MLP Head
```

**特点**：保留前 N 个 token 做序列聚合（默认 65 lite / 可选 265 full）。

**⚠️ 接口 bug 详情**（修订时验证）：
- `model_online_tokens.py:69-77` 调用 `LightweightTokenEncoder(..., token_drop_rate=..., use_attn_pool=...)`，但 `model_uni_tokens.py:26` 的构造函数签名是 `(embed_dim, hidden_dim, n_heads, n_layers, dropout)` — 不支持 `token_drop_rate` 和 `use_attn_pool`
- `model_online_tokens.py:118` 做元组解包 `encoded, _attn = self.token_encoder(tokens)`，但 `model_uni_tokens.py:55` 的 `forward()` 只返回单个 tensor `x`
- **直接运行 `python model_online_tokens.py` 会报 `TypeError`**

**⚠️ 65-token 截断的 token 顺序风险**（二审补充）：
`model_online_tokens.py:115` 通过 `all_tokens[:, :self.num_tokens, :]` 直接截取前 65 个 ViT token。标准 ViT 的 token 顺序为 `[CLS, patch_0_0, patch_0_1, ..., patch_15_15]`（raster scan），因此 65-token = CLS + 前 64 个 patch tokens（约图像上 1/4 区域，即顶部 4 行）。这意味着：
- **65-token 不是均匀空间下采样**，而是空间偏置截断（偏向图像左上区域）
- **对 GFNet 频域解释的影响**：如果 FFT 沿 token 序列维度做，被截断的序列不代表完整的 2D 空间频率 — 高频分量可能因空间截断而失真
- **建议前置验证**：确认 UNI2-H 的 token 顺序（是否为标准 ViT raster scan，是否含 register tokens），并考虑将 65-token 改为空间均匀下采样（如 grid_sample）以保留完整的空间频率信息
- **缓解方案**：Full 265-token 模式无此问题（含全部 1+256 tokens），但计算量和显存相应增加

### LightweightTokenEncoder 详细结构（实际代码逐行精算）

```python
# model_uni_tokens.py: LightweightTokenEncoder (实际代码精算, 与自检 3,680,768 一致)
input_proj:    Linear(1536, 512)                           # 1536×512+512     = 786,944
encoder:       TransformerEncoder(1 layer, d=512, 8head):  #                  ≈ 2,100,480
               ├─ self_attn: Q/K/V 3×Linear(512,512)      # 3×(512×512+512)  =   787,968
               ├─ attn_out:   Linear(512,512)              # 512×512+512      =   262,656
               ├─ FFN1:       Linear(512,1024)             # 512×1024+1024    =   525,312
               ├─ FFN2:       Linear(1024,512)             # 1024×512+512     =   524,800
               └─ 2×LayerNorm                               # 2×(512+512)      =     2,048 (weight+bias)
output_proj:   Linear(512, 1536)                            # 512×1536+1536   =   787,968
norm:          LayerNorm(1536)                              # 1536+1536        =     3,072 (weight+bias)
──────────────────────────────────────────────────────────────────────────────────────────
总计 (1层):    = 3,680,768 (3.68M)  ← 与 model_uni_tokens.py 自检完全一致
总计 (2层):    ≈ 5,780,736 (5.78M)  — 加深至2层时
```

> 初版报告引用的 "3.2M" 和 "~2.4M TransformerEncoder" 为口头估算。此表为逐组件精算值。

## 1.2 能力瓶颈诊断（修订后）

| 瓶颈 | 严重度 | 当前表现 | 根因 |
|------|:---:|------|------|
| **跨患者泛化衰减** | 🔴 高 | Fold 间 PCC 差异 0.3726→0.4322（16%） | 训练患者特异性模式被模型记忆，非通用组织形态特征 |
| **过拟合极快** | 🔴 高 | 有效窗口仅 1-2 epoch | 15K 样本 vs ~7M 参数，LoRA 虽缓解但未根治 |
| **频域信息完全缺失** | 🟡 中 | Token Encoder 纯实数空间 | H&E 纹理（纤维走向、细胞排列）在频域有稀疏表征 |
| **Token 间交互能力待验证** | 🟡 中 | Token 模式尚未跑通，无法评估收益 | 1 层 Transformer + 65 tokens 下感受野可能已够用；序列效率瓶颈在 265 tokens 时才出现 |
| **坐标编码利用不充分** | 🟡 中 | 仅做简单加法 | x_embed/y_embed 是切片级 spot 坐标，在 TokenEncoder **之后**加入 |

> ⚠️ **坐标编码的空间层级澄清**（初版报告的重要修正）：坐标编码 `x_embed(pos_x) + y_embed(pos_y)` 位于 `model_online_tokens.py:122`，即 TokenEncoder（处理 ViT 内部 token）**之后**。坐标编码作用于**切片级 spot**的位置（~100μm 尺度），而非 224×224 patch 内部 16×16 的 ViT token 位置。GFNet/频域模块替换的是 TokenEncoder 内部的 Transformer，操作的是单 patch 的 ViT token 序列。**两者不在同一空间层级。**

## 1.3 迁移模块的切入点

本项目的 Mamba 和频域模块替换目标是 `LightweightTokenEncoder` 中的 `TransformerEncoder`：

```
ViT tokens [B, N, 1536]          (N=65 lite / 265 full)
  → input_proj (1536→512)
  → TransformerEncoder           ← 替换此处的 token mixing 机制
  → mean_pool
  → output_proj (512→1536)
  → LayerNorm → [B, 1536]
    (然后才加切片级坐标编码 x_embed + y_embed)
```

频域模块的作用层级是**单 224×224 patch 内部 ViT token 间的频率混合**，不直接感知切片级坐标邻接关系。频域信息的物理意义在于：H&E 图像中纤维束方向、细胞排列密度等纹理特征在频率域有稀疏表征，FFT filter 可捕获空间域 transformer 不易学到的模式——这些频率模式在组织学上是通用的（不受具体患者影响），因此对抗过拟合有一定理论依据。

此外，频域模块也可作为 **CLS 模式的增强插件**：在 UNI2-H backbone 提取特征时额外保留部分 patch tokens（不做 token encoder），对这些 patch tokens 做 FFT 频域旁路提取频域特征向量，与 CLS token 的编码结果拼接后送入 MLP 回归头。注意：单个 CLS 向量本身没有空间序列维度，无法直接做空间 FFT；必须从 patch tokens 侧提取频域信息再融合。此方案对 CLS-only 路径改动成本较小（仅增加旁路），且 CLS 模式已有 baseline 可直接对比。

# 二、Mamba 系列迁移分析

## 2.1 ConvSSM

| 维度 | 评估 |
|------|------|
| **论文** | Convolutional State Space Models for Long-Range Spatiotemporal Modeling (NVIDIA, 2023) |
| **代码** | https://github.com/nvlabs/convssm |
| **核心机制** | 卷积递归更新 + 状态空间模型(SSM)，并行化处理长序列，子平方级复杂度 |

### 2.1.1 契合度：⭐⭐ (低)

ConvSSM 的核心设计目标是**时空序列建模**（视频预测、天气预报、交通流量），其创新在于将 SSM 与卷积递归结合处理 3D (T×H×W) 数据。PFMval 处理的是独立 2D patch（224×224），patch 之间不存在时序依赖。

**可以强行迁移**：将 265 个 token 视为"空间序列"，用 ConvSSM 的 SSM 核心替代 TransformerEncoder。但这相当于把 ConvSSM 降级为普通 1D SSM，浪费了其卷积递归更新的核心设计。

### 2.1.2 可替换组件

- 替换 `LightweightTokenEncoder.encoder`（TransformerEncoder）为 1D SSM 扫描
- 265 个 token 按某种空间顺序（如 Hilbert 曲线排序）展开为 1D 序列

### 2.1.3 实现复杂度：⭐⭐⭐⭐ (高)

- 需要引入 `nvlabs/convssm` 仓库（依赖 CUDA 扩展编译）
- 代码改动量：~200 行（新建 SSMTokenEncoder 类 + 训练脚本适配）
- 潜在依赖冲突：需要特定 CUDA/cuDNN 版本

### 2.1.4 预期收益：⭐ (极低)

- SSM 的线性复杂度在 65（默认）~265 tokens 上优势均不明显（1 层 Transformer 的 O(N²) 完全可承受）
- 没有理论依据表明 SSM 的"状态记忆"机制比 self-attention 更适合 token 聚合

### 2.1.5 风险

- 过度工程化：引入重量级依赖解决不存在的问题
- 训练不稳定：SSM 的 HiPPO 初始化对学习率敏感

### 2.1.6 判定：❌ **不推荐迁移**

ConvSSM 为视频/时空任务设计，降级用于 token 序列聚合是"大材小用 + 方向错误"。项目瓶颈不在序列长度计算效率。

## 2.2 MambaIR

| 维度 | 评估 |
|------|------|
| **论文** | MambaIR: A Simple Baseline for Image Restoration with State-Space Model (ECCV 2024) |
| **代码** | https://github.com/csguoh/mambair |
| **核心机制** | 基于 VSS Block（Vision State Space Block）的图像恢复，性能超越主流 Transformer/CNN 基准 |

### 2.2.1 契合度：⭐⭐ (低-中) [修订降级]

MambaIR 的核心组件 **VSS Block** 是通用视觉特征处理模块。但在本项目的**默认配置**（65 tokens）下其优势明显缩水：

- **线性复杂度 O(N) 优势不大**：65 tokens 时 Transformer attention 仅 O(65²)=4,225，完全可承受；即使 265 tokens（full 模式），1 层 attention 的 O(265²)=70K 也不是实际瓶颈。O(N) vs O(N²) 只有**加深到 3-4 层 + full 265 tokens** 时才形成实质差距。
- **全局感受野已有替代**：1 层 Transformer + mean pooling 在 65 tokens 上的有效感受野已覆盖全序列；GFNet 的 FFT filter 同样提供全局感受野且零依赖。
- **VSS 的设计假设（2D 空间扫描）与 ViT token 序列不完全匹配**：MambaIR 假定输入有 2D 空间结构（H×W），通过四向扫描保证空间不变性；而本项目 token 序列来自 ViT 的 1D 排列（含 CLS + 16×16 patch tokens），空间连续性不如原始图像。

### 2.2.2 实现复杂度：⭐⭐⭐ (中) [修订上调]

- 核心依赖：`mamba-ssm` 包 — **与当前 PyTorch 2.6.0+cu118 的兼容性未验证**。`mamba-ssm` 主要针对 CUDA 11.8+/12.x + PyTorch 2.0+ 构建，cu118 分支的预编译 wheel 可能不可用，需从源码编译（引入 `causal-conv1d` 等额外依赖）
- 如 `mamba-ssm` 不可用，需实现纯 PyTorch 回退版（Conv1d + GLU），但回退版已退化为普通卷积，失去 SSM 的核心优势
- 四向扫描（SS2D）增加代码复杂度：需要 4 次序列翻转+扫描+逆翻转
- 比 GFNet 的 ~80 行多出 2-3 倍的实现和调试成本

### 2.2.3 预期收益：⭐⭐ (低-中) [修订下调]

| 场景 | 预期收益 | 依据 |
|------|:---:|------|
| 65 tokens, 1 层 VSS vs 1 层 Transformer | ~0 | 序列短，attention 已够用 |
| 65 tokens, 3-4 层 VSS vs 1 层 Transformer | +0~0.02 | 深度优势开始显现 |
| 265 tokens, 3-4 层 VSS vs 1 层 Transformer | +0.01~0.03 | 长序列 + 深度组合下 O(N) 优势最明显 |

但 3-4 层 VSS 在 15K 样本下的过拟合风险未知，且当前无 265-token baseline 可对比。

### 2.2.4 风险

- **依赖链脆弱**：`mamba-ssm` → `causal-conv1d` → 特定 CUDA 版本，与本项目 cu118 环境可能冲突
- **方向敏感性**：ViT token 序列非严格 2D 空间排列，四向扫描的收益存疑
- **从未在病理 token 聚合上验证**：MambaIR 主要验证场景是图像恢复（ pixel-level），与回归任务的迁移差距大
- **过拟合风险未知**：SSM 参数效率高是一把双刃剑 — 更少的参数也可能意味着对训练分布更强的记忆

### 2.2.5 判定：🟡 **降级为 P2 — 待频域方向确认后再评估**

**降级理由**：
1. 默认 65 tokens 下 O(N²) 不是瓶颈，VSS 的核心卖点（线性复杂度）在本项目默认配置下优势缩水
2. `mamba-ssm` 的 CUDA 依赖安装和兼容性调试成本高于所有频域方案（GFNet 零依赖，AFNO 仅需 PyTorch 内置 FFT）
3. 当前更突出的问题是**小样本过拟合 + 跨患者泛化**，而非序列计算效率 — GFNet/AFNO 的参数正则化效应（更少参数 + 软阈值）更对症
4. 应先用 GFNet/AFNO 验证"频域信息对病理 token 聚合是否有用"，如果频域方向本身不成立，Mamba 也不太可能有效；如果频域有效，再评估 Mamba 作为更深 encoder 的选项

# 三、频域系列迁移分析

## 3.1 GFNet — P0 最高优先级

| 维度 | 评估 |
|------|------|
| **论文** | Global Filter Networks for Image Classification (NeurIPS 2021) |
| **代码** | https://github.com/raoyongming/GFNet |
| **核心机制** | 用 FFT 全局滤波器替换 Vision Transformer 中的自注意力层 |

### 3.1.1 核心原理

GFNet 的核心洞察：**自注意力（Self-Attention）在频域等价于一个全局频率滤波器**。

```
Self-Attention:  O = softmax(QK^T/√d) × V     # O(N²) 复杂度
GFNet Filter:    O = IFFT( FFT(X) ⊙ W )        # O(N log N) 复杂度
                                         ↑
                                  可学习的复数权重矩阵 W
```

每个频率分量独立乘一个可学习权重 — 这等价于在空间域做**全局卷积**（卷积核大小 = 序列长度）。

### 3.1.2 为什么 GFNet 可能对 PFMval 有效？（修订后）

> ⚠️ **空间层级澄清**：GFNet 替换的是 `LightweightTokenEncoder` 内部的 TransformerEncoder，操作的是**单 224×224 patch 内部 ViT token 序列**（16×16 grid + CLS），不是切片级 spot 网格。以下论证基于此修正。

| 项目特征 | GFNet 潜在优势 | 机制与限制 |
|---------|-----------|------|
| **ViT token 来自 2D patch grid** | FFT 可捕获 patch 内部的 2D 空间频率 | 16×16 patch tokens 转 1D 序列后 FFT 沿序列维度做，等价于沿 patch 扫描方向的频率分解 — 如 patch 行列扫描方向与组织纹理方向一致则有物理意义 |
| **过拟合严重** | GFNet filter 参数极少 | GlobalFilter: N/2+1 × d 个复数参数（65 tokens: 33×512×2=34K; 265 tokens: 133×512×2=136K），远小于 Transformer attention 的 ~1.05M |
| **频域信息缺失** | FFT 提供频域表征 | H&E 的纤维走向、细胞排列密度在频率域有稀疏表征；低频=大块组织结构，高频=细胞边界/纹理细节 |
| **跨患者泛化差** | 频率模式可能是组织学通用特征 | 纤维束方向周期、细胞核间距等频域特征理论上不受患者染色差异影响（但未经实验验证） |

**不成立的原论证**：初版报告称"GFNet 与坐标编码天然协同"，这是错误的。坐标编码 `x_embed/y_embed` 作用于**切片级 spot 坐标**（~100μm 尺度），在 TokenEncoder **之后**才加入；GFNet 操作的是**单 patch 内部 ViT token**（~14μm 尺度）。两者不在同一空间层级，不能直接"协同"。GFNet 的价值应重新定位为：**为单 patch 内部的特征聚合提供频域视角**，补充纯空间域 Transformer 缺失的信息通道。

### 3.1.3 参数精算：GFNet vs TransformerEncoder

基于 1.1 节的逐组件精算，对比 65-token 和 265-token 两种配置下 GFNet 替换 TransformerEncoder 的参数变化：

| 组件 | Transformer (1层) | GFNet (65 tok) | GFNet (265 tok) | 说明 |
|------|:---:|:---:|:---:|------|
| input_proj (1536→512) | 787,456 | 787,456 | 787,456 | 不变 |
| **Token Mixer** | **~1,050,624** | **33,792** | **136,192** | attention → FFT filter |
| FFN (512→1024→512) | ~1,050,624 | ~1,050,624 | ~1,050,624 | 不变（GFNetBlock 保留 FFN） |
| output_proj (512→1536) | 787,968 | 787,968 | 787,968 | 不变 |
| LayerNorm ×3 | ~4,352 | ~4,352 | ~4,352 | 不变 |
| **TokenEncoder 总计** | **3,680,768 (3.68M)** | **2,663,936 (2.66M)** | **2,766,336 (2.77M)** | 与自检一致 |
| **参数减少** | — | **-1,016,832 (-27.6%)** | **-914,432 (-24.8%)** | |

> 初版报告宣称 "参数减少 60%+"，是将 TokenEncoder 整体从 3.2M→1.2M 的粗略估计。实际精算结果：**参数减少 ~25-28%**（主要来自 attention 权重被 FFT filter 替换）。60%+ 的降幅需要同时削减 FFN 和 projection 维度，但这会改变模型容量，不应与 baseline 对比时做。

### 3.1.4 可替换组件

```
替换方案：GFNetBlock 替换 TransformerEncoderLayer（保留 FFN + input/output_proj）

当前 (65-token lite 默认):
  tokens [B,65,1536] → input_proj(1536→512)
  → TransformerEncoder(d=512, 8heads, ff=1024)  ← 替换这里
  → mean_pool → output_proj(512→1536) → [B,1536]

改为 GFNet:
  tokens [B,N,1536] → input_proj(1536→512)
  → GFNetBlock:
      x = x + GlobalFilter(LayerNorm(x))    # FFT → 逐频率复数乘 → IFFT
      x = x + FFN(LayerNorm(x))             # Linear→GELU→Dropout→Linear→Dropout
  → mean_pool → output_proj(512→1536) → [B,1536]

N=65 (lite): 频率分量 33 个, GlobalFilter 仅 34K 参数
N=265 (full): 频率分量 133 个, GlobalFilter 136K 参数
```

> ⚠️ **注意**：当前 `model_online_tokens.py` 存在接口 bug（见 1.1 节），在替换 Transformer 之前必须先修复 `LightweightTokenEncoder` 构造参数不兼容和返回值解包问题。训练命令也会变化（需增加 `--encoder_type gfnet` 参数）。

### 3.1.5 实现复杂度：⭐ (极低)

- **零额外依赖**：`torch.fft.rfft` 是 PyTorch 内置函数
- **核心代码量**：~80 行（新建 `model_gfnet.py` 中的 GFNetTokenEncoder 类 + GlobalFilter）
- **前置工作**：修复 `model_online_tokens.py` 的接口 bug（~10 行改动） + 在 `model_uni_tokens.py` 的 `LightweightTokenEncoder` 中增加可选的 `encoder_type` 参数或新建独立的 GFNet 版 TokenEncoder
- **训练命令兼容性**：需增加 `--encoder_type gfnet` 参数，非"完全向后兼容"

### 3.1.6 预期收益：⭐⭐⭐ (中-高) [修订下调]

| 指标 | 预期改善 | 依据（修订后） |
|------|:---:|------|
| **Val PCC vs 同配置 Transformer baseline** | +0.01~0.03 | GFNet 在 ImageNet 上以更少参数追平 ViT；但病理 token 聚合不同于 ImageNet 分类，迁移效果存疑 |
| **跨患者 PCC** | +0.01~0.03 | FFT filter 参数少 → 过拟合慢，但"频率模式是组织学通用特征"尚为假设 |
| **可训练参数 (TokenEncoder)** | **-25~28%** | 3.68M → 2.66M (65 tok) / 2.77M (265 tok)，精算值非估算 |
| **训练速度** | +10~20% | rFFT 替代 attention 矩阵乘；65 tokens 时差异更小 |
| **有效训练窗口** | 可能 +1~2 epoch | 参数减少 → 过拟合速度降低（需实验验证） |

### 3.1.7 风险

- **空间层级错配**：GFNet 在 ViT token 序列维度做 FFT，而 ViT token 的 1D 排列顺序（CLS + 按行扫描的 patch tokens）不一定保留有意义的 2D 空间频率结构
- **频率分辨率限制**：65 tokens → 仅 33 个频率分量；265 tokens → 133 个分量，但 lite/full 两档的频率分辨率差异可能影响结果
- **最终 pooling 仍是 mean**：GFNet 只改 token mixing，不改聚合方式
- **初始化敏感**：复数权重初始化为 0.02 倍 randn，需确保初始状态近似恒等映射（权重 ≈ 1+0i），否则前期训练不稳定

### 3.1.8 判定：🟢 **推荐迁移（P0 — 最高优先级，但附前提条件）**

**前提条件**（必须先完成）：
1. 修复 `model_online_tokens.py` 的接口 bug（token_drop_rate / use_attn_pool / 返回值解包）
2. 建立 65-token lite Transformer baseline（至少 Cross-Fold1）作为 GFNet 消融的对比基准
3. 确认 baseline 可正常训练（loss 收敛、无 NaN）

**GFNet 仍是本报告性价比最高的方案**：零额外依赖 + 最低实现成本 + 参数减少 ~27% 抗过拟合。但初版的"60%+ 参数减少""与坐标编码协同""训练命令无需改变"等表述过于乐观，已修正。

## 3.2 AFNO — P1 高优先级

| 维度 | 评估 |
|------|------|
| **论文** | Adaptive Fourier Neural Operators: Efficient Token Mixers for Vision Transformers (FAIR, 2022) |
| **核心机制** | FFT + 自适应权重（块对角 + 软阈值收缩）替代自注意力 |

### 3.2.1 契合度：⭐⭐⭐⭐ (高)

AFNO 与 GFNet 的目标相同（用 FFT 做 token mixing），但多了两个关键改进：

1. **块对角权重**：不是每个频率一个标量，而是一个小矩阵作用于特征维度 → 允许**跨特征通道的频率交互**
2. **软阈值收缩**（Soft-Shrinkage）：对高频分量做稀疏化 → **天然去噪，抗过拟合**

这两点对 PFMval 非常有价值：
- 我们的 1536 维 UNI 特征内部有高度相关性（块对角可解耦）
- 软阈值 = 自动忽略噪声频率 = 正则化效果

### 3.2.2 可替换组件

与 GFNet 相同位置，但提供更强的频率-通道混合能力。

### 3.2.3 实现复杂度：⭐⭐ (低-中)

```python
# AFNO 核心：FFT + block-diag MM + soft-shrink
class AFNOMixer(nn.Module):
    def __init__(self, seq_len, dim, num_blocks=8, sparsity_threshold=0.1):
        # 将 dim 分为 num_blocks 组，每组独立做频域乘
        self.block_size = dim // num_blocks
        self.w1 = nn.Parameter(...)  # [num_blocks, N//2+1, block_size, block_size]
        self.w2 = nn.Parameter(...)
        self.sparsity_threshold = sparsity_threshold

    def forward(self, x):
        x = torch.fft.rfft(x, dim=1)
        # 分块：reshap → block-diag MM → soft-shrink
        x_blocks = x.reshape(B, N//2+1, num_blocks, block_size)
        x_blocks = einsum('bnbc,bncd->bnbd', x_blocks, w1) + bias
        x_blocks = soft_shrink(x_blocks, sparsity_threshold)
        x_blocks = einsum('bnbc,bncd->bnbd', x_blocks, w2) + bias
        x = irFFT(x_blocks.reshape(B, N, D))
        return x
```

比 GFNet 复杂 ~3×，但仍远轻于 TransformerEncoder。

### 3.2.4 预期收益：⭐⭐⭐ (中等)

- 比 GFNet 更强的表达能力（跨通道频率交互）
- 软阈值 = 内置正则化 → 抗过拟合
- 理论上比 GFNet 更容易捕获通路特异性频率模式

### 3.2.5 风险

- 块数量（num_blocks）是敏感超参数，需要消融实验
- 软阈值阈值需要调参，可能对训练初期不稳定
- 比 GFNet 多 2-3× 参数，但仍远小于 Transformer

### 3.2.6 判定：🟢 **推荐迁移（P1 — 高优先级）**

AFNO 是 GFNet 的"高级版"。在 GFNet 验证频域方案有效后，应优先尝试 AFNO 看是否有额外提升。

## 3.3 AFFNet — P1-P2 中高优先级

| 维度 | 评估 |
|------|------|
| **论文** | Adaptive Frequency Filters As Efficient Global Token Mixers (ICCV 2023) |
| **核心机制** | 自适应频率滤波器 — 可学习的频率掩码替代注意力 |

### 3.3.1 契合度：⭐⭐⭐ (中高)

AFFNet 的核心思想与 GFNet/AFNO 类似，但其独特之处在于：

- **自适应滤波器**：根据输入动态调整频率权重（GFNet 的权重是静态可学习参数）
- **即插即用**：设计为 ViT 中 Self-Attention 的直接替换，接口完全兼容

"自适应" 意味着滤波器权重是输入 token 的函数，而非固定参数 — 这能根据不同的输入 patch（不同组织区域）自动调整频率选择性。

### 3.3.2 可替换组件

与 GFNet/AFNO 同位置。AFFNet 的优势可能是"输入自适应"——不同组织区域（肿瘤 vs 正常 vs 纤维化）自动激活不同频率。

### 3.3.3 实现复杂度：⭐⭐ (低-中)

需实现输入→滤波权重的轻量 MLP 映射。

### 3.3.4 判定：🟡 **推荐迁移（P1-P2）**

在 GFNet 和 AFNO 之间进行消融：静态过滤 vs 块对角 vs 自适应 = 三种递增复杂度。建议 GFNet（P0 验证方向）→ AFNO（P1 增强）→ AFFNet（P1-P2 最复杂变体）的渐进路线。

---

## 3.4 SpectFormer — P2 中优先级

| 维度 | 评估 |
|------|------|
| **论文** | SpectFormer: Frequency and Attention is what you need in a Vision Transformer (2023) |
| **核心机制** | 频域分支 + 空间注意力分支的多光谱融合 |

### 3.4.1 契合度：⭐⭐⭐ (中高)

SpectFormer = **频域处理 + 空间注意力 双分支并行**，然后融合。这是最"不浪费"的方案：

```
tokens [B,N,D]
  ├─→ Spectral Branch: FFT → Learnable Filter → IFFT
  └─→ Spatial Branch:  Self-Attention (或简化版)
  → Fusion (concat/add/gate) → FFN → 输出
```

对本项目的特殊意义：**频域分支捕获全局纹理/结构（纤维走向、组织排列），空间分支捕获局部细胞形态**。双分支天然互补。

### 3.4.2 可替换组件

替换整个 LightweightTokenEncoder，或将 SpectFormer 的混合设计融入 encoder。

### 3.4.3 实现复杂度：⭐⭐⭐ (中)

比单一 GFNet/AFNO 多 ~50% 代码量，但仍在可控范围（~200 行）

### 3.4.4 判定：🟡 **推荐迁移（P2 — 中优先级）**

"频域 + 空间"双分支是最有可能突破当前 PCC 天花板的设计，但复杂度也最高。建议在 GFNet 验证频域有效、9 患者数据到齐后，作为长期架构搜索方向。

## 3.5 FFT Dynamic Token Mixer — P2 中优先级

| 维度 | 评估 |
|------|------|
| **核心机制** | 基于 FFT 的动态 token mixer，直接在频域对 token 做交互 |

### 3.5.1 契合度：⭐⭐⭐ (中高)

相比 GFNet 的"逐频率标量乘"，FFT Dynamic Token Mixer 在频域做**完整的矩阵乘法**（而非逐元素乘），提供更强（也更重）的频率-空间混合。

### 3.5.2 实现复杂度：⭐⭐ (低-中)

类似 AFNO 块对角，但用动态权重。

### 3.5.3 判定：🟡 **推荐迁移（P2）**

作为频域方案矩阵中的一个变体，在核心方案验证后消融对比。

## 3.6 FlashFFTConv — P3 低优先级

| 维度 | 评估 |
|------|------|
| **核心机制** | 用 FFT 高效实现长序列卷积，替代标准 Conv1d |
| **适用场景** | NLP 长序列（1K-16K tokens）的卷积 |

### 3.6.1 契合度：⭐ (低)

FlashFFTConv 解决的是**长序列 1D 卷积的效率问题**（如 16K 长度的文本序列）。本项目 token 序列仅 65（默认）~265 长度，1D 卷积在这个长度上完全不需要 FFT 加速。

### 3.6.2 判定：❌ **不推荐**

解决的问题在本项目中不存在。65~265 tokens 的 1D 卷积计算量可忽略不计。

## 3.7 FourCastNet / FourierGNN / TimesNet — 不推荐

| 模块 | 设计目标 | 为何不适用 |
|------|---------|-----------|
| **FourCastNet** | 气象预测（地球网格数据） | 基于球面网格的 AFNO，H&E patch 无网格结构 |
| **FourierGNN** | 时序预测（图+傅里叶） | 针对 1D 时序的图结构，虽有"图"字但方向完全不同 |
| **TimesNet** | 时序分析（1D→2D 转换） | 将 1D 时序 reshape 为 2D 图像做卷积，与项目任务方向相反 |

**判定：❌❌❌ 三个均不推荐迁移。**

## 4.4 对比基准选择（重要修正）

初版报告用 **CLS 模式 Frozen Cross-Fold1 PCC=0.4113** 作为 GFNet 的成败门槛。这是错误的——GFNet 是 Token 分支的替换实验，应与**同配置的 Token Transformer Encoder baseline**对比。

**正确的基准设定**：
| 实验 | 对比基准 | 阈值 |
|------|------|------|
| GFNet (65-token, frozen) | Transformer (65-token, frozen) **— 需先训练** | GFNet ≧ baseline |
| GFNet (65-token, LoRA) | Transformer (65-token, LoRA) — 已有 CLS 模式 LoRA Cross-Fold1=0.4322 可作为参考上限 | — |
| AFNO / AFFNet / VSS | 同上（同 num_tokens 同 mode） | 各自 ≧ baseline |

**如果 Token 模式 Transformer baseline 的 PCC 本身不如 CLS 模式**（这是可能的——保留更多 token 并不保证更好），那频域方案的目标首先应该是**追平 CLS baseline**，而非超越它。

## 5.1 GFNet TokenEncoder（P0 — 推荐立即实现）

```python
# model_gfnet.py — GFNet Token Encoder for PFMval
"""
GFNet-based Token Encoder: 用 FFT 全局滤波器替换 TransformerEncoder。
用法: 先修复 model_online_tokens.py 接口 bug, 再通过 --encoder_type gfnet 参数切换。
"""

import torch
import torch.nn as nn


class GlobalFilter(nn.Module):
    """FFT 全局滤波器：在频域逐频率学习权重，等价于空间域全局卷积。
    
    Args:
        seq_len: token 数量 (265 full, 65 lite)
        dim: 特征维度 (512 after input_proj)
    """
    def __init__(self, seq_len: int, dim: int):
        super().__init__()
        # 复数权重 [N_freq, dim]，其中 N_freq = seq_len // 2 + 1
        self.complex_weight = nn.Parameter(
            torch.randn(seq_len // 2 + 1, dim, 2, dtype=torch.float32) * 0.02
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """x: [B, N, D] → [B, N, D]"""
        B, N, D = x.shape
        # FFT → 频域复数乘法 → IFFT
        x_freq = torch.fft.rfft(x.float(), dim=1, norm='ortho')   # [B, N//2+1, D] complex
        weight = torch.view_as_complex(self.complex_weight)        # [N//2+1, D]
        x_freq = x_freq * weight.unsqueeze(0)                       # broadcast 乘
        out = torch.fft.irfft(x_freq, n=N, dim=1, norm='ortho')   # [B, N, D]
        return out.to(x.dtype)


class GFNetBlock(nn.Module):
    """GFNet Block: GlobalFilter + FFN，对标 TransformerEncoderLayer。
    
    结构: x = x + GlobalFilter(LN(x)); x = x + FFN(LN(x))
    """
    def __init__(self, seq_len: int, dim: int, mlp_ratio: float = 2.0, dropout: float = 0.3):
        super().__init__()
        self.norm1 = nn.LayerNorm(dim)
        self.filter = GlobalFilter(seq_len, dim)
        self.norm2 = nn.LayerNorm(dim)
        self.ffn = nn.Sequential(
            nn.Linear(dim, int(dim * mlp_ratio)),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(int(dim * mlp_ratio), dim),
            nn.Dropout(dropout),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = x + self.filter(self.norm1(x))
        x = x + self.ffn(self.norm2(x))
        return x


class GFNetTokenEncoder(nn.Module):
    """GFNet 版本 Token Encoder：替换 LightweightTokenEncoder 的 Transformer 部分。
    
    与 LightweightTokenEncoder 接口完全兼容，可直接替换。
    """
    def __init__(
        self,
        embed_dim: int = 1536,
        hidden_dim: int = 512,
        seq_len: int = 265,
        n_layers: int = 1,
        dropout: float = 0.3,
    ):
        super().__init__()
        self.input_proj = nn.Linear(embed_dim, hidden_dim)
        self.blocks = nn.ModuleList([
            GFNetBlock(seq_len, hidden_dim, dropout=dropout)
            for _ in range(n_layers)
        ])
        self.output_proj = nn.Linear(hidden_dim, embed_dim)
        self.norm = nn.LayerNorm(embed_dim)

    def forward(self, tokens: torch.Tensor) -> torch.Tensor:
        """
        Args:
            tokens: [B, num_tokens, embed_dim]
        Returns:
            encoded: [B, embed_dim]
        """
        x = self.input_proj(tokens)          # [B, N, hidden_dim]
        for block in self.blocks:
            x = block(x)                     # [B, N, hidden_dim]
        x = x.mean(dim=1)                    # [B, hidden_dim] 全局平均池化
        x = self.output_proj(x)              # [B, embed_dim]
        x = self.norm(x)
        return x
```

## 5.2 MambaIR VSS Block（P2 — 待频域方向确认后再实现）

```python
# model_mamba_encoder.py — Mamba-based Token Encoder
"""
基于 Mamba-2 的 Token Encoder。需要 pip install mamba-ssm。
如 mamba-ssm 不可用，回退到纯 PyTorch 简化实现（下方 SSRBlock）。
"""
import torch
import torch.nn as nn

try:
    from mamba_ssm import Mamba2 as Mamba
    HAS_MAMBA = True
except ImportError:
    HAS_MAMBA = False


class VSSBlock(nn.Module):
    """Vision State Space Block（简化版，依赖于 mamba-ssm）。
    
    如 mamba-ssm 不可用，可用纯 PyTorch S4 简化实现替代。
    """
    def __init__(self, dim: int, d_state: int = 16, dropout: float = 0.3):
        super().__init__()
        self.norm = nn.LayerNorm(dim)
        if HAS_MAMBA:
            self.mamba = Mamba(d_model=dim, d_state=d_state)
        else:
            # 回退：简化的 1D 深度可分离卷积 + 门控
            self.mamba = nn.Sequential(
                nn.Conv1d(dim, dim, kernel_size=3, padding=1, groups=dim),
                nn.SiLU(),
            )
        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x: [B, N, D]
        residual = x
        x = self.norm(x)
        if HAS_MAMBA:
            x = self.mamba(x)
        else:
            x = x.transpose(1, 2)
            x = self.mamba(x).transpose(1, 2)
        return residual + self.dropout(x)


class VSSBlockSimple(nn.Module):
    """纯 PyTorch 简化 S4 Block（零依赖回退方案）。
    
    使用 Conv1d + GLU 近似 SSM 的线性时间扫描行为。
    性能可能不如完整 mamba-ssm，但无需额外依赖。
    """
    def __init__(self, dim: int, expand_ratio: float = 2.0, dropout: float = 0.3):
        super().__init__()
        hidden = int(dim * expand_ratio)
        self.norm = nn.LayerNorm(dim)
        self.conv = nn.Conv1d(dim, dim, kernel_size=4, padding=2, groups=dim)
        self.proj = nn.Sequential(
            nn.Linear(dim, hidden * 2),
            nn.GLU(dim=-1),
            nn.Linear(hidden, dim),
        )
        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x: [B, N, D]
        residual = x
        x = self.norm(x)
        # 深度可分离卷积（空间混合）
        x_conv = self.conv(x.transpose(1, 2)).transpose(1, 2)
        # 通道混合（门控线性单元）
        x = self.proj(x_conv)
        return residual + self.dropout(x)
```

## 6.1 关键风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|:---:|:---:|------|
| **Token 模式 baseline 本身低于 CLS 模式** | 🟡 中 | 频域方案即使优于 Token baseline，仍可能不如 CLS LoRA (0.4322) | 同时保留 CLS baseline 作为上限参考；如果 Token 路线整体不如 CLS，则频域模块应直接应用到 CLS 模式的增强插件上 |
| **频域方案 PCC 不升反降** | 🟡 中 | 浪费 3-5 天 GPU 时间 | 阶段 A 仅 3 次 smoke test 即可判定；如果 GFNet (65-token) < baseline，可跳试一次 265-token 看是否长序列下频域优势才显现 |
| **代码接口修复引入新 bug** | 🟡 中 | baseline 结果不可靠 | 修复后先跑自检 + 1 epoch dry run；参数统计确认与设计一致 |
| **mamba-ssm CUDA 兼容性** | 🟡 中 | VSS 实验无法进行 | 优先尝试纯 PyTorch 回退版（VSSBlockSimple）；如果回退版性能差，放弃 Mamba 方向（已是 P2，影响有限） |
| **GFNet 在 65 tokens 上频率分辨率太低** | 🟡 中 | 33 个频率分量不够 | 直接跳 265-token 尝试；或使用 multi-head filter（分组 token 各自 FFT 再合并） |
| **9 患者数据到齐后结果反转** | 🟡 中 | 在小数据上有效的方案在大数据上无效 | 所有方案保留参数和配置，9 患者下可快速重跑验证 |
| **频域 filter 学到平凡解** | 🟢 低 | PCC = 0 | 初始化权重为 1+0i（全通滤波器），保证初始状态 ≈ 身份映射 |
| **265-token 显存不足 (RTX 4060 8GB)** | 🟡 中 | 无法跑 full token 实验 | 启用 grad_checkpointing；降 batch_size 到 2 + grad_accum=4；必要时切服务器 RTX 4080 16GB |

## 6.2 实验设计原则（修订后）

### 6.2.1 控制变量

每次消融**只改变一个组件**：
- 相同的 backbone（UNI2-H frozen 或相同 LoRA rank）
- 相同的 fold 配置（优先 Cross-Fold1：JFX+LMZ → HYZ）
- 相同的 num_tokens（65 或 265，不得混合对比）
- 相同的超参数（lr=1e-4（train_online_tokens.py 默认值）, epochs=150, early_stop_patience=20, 取 **val_loss 最小** epoch）
- 相同的优化器和调度器

### 6.2.2 核心监控指标

除了标准 PCC/MAE/R²，增加：
- **Train-Val Gap**：频域方案的 gap 预期缩小（参数少 → 过拟合慢）
- **TokenEncoder 参数量**：验证 "参数越少泛化越好" 假设（GFNet vs Transformer: 2.66M vs 3.68M for 65-token）
- **逐通路 PCC 标准差**：频域方案是否改善了当前最弱的通路
- **vs CLS baseline 的相对 PCC**：确保 Token 路线整体方向正确

### 6.2.3 失败快速判定标准（修订后）

| 实验 | 对比基准 | 判定失败 | 动作 |
|------|------|------|------|
| Transformer baseline (65-token) | CLS frozen (0.4113) / CLS LoRA (0.4322) | Token baseline PCC 远低于 CLS baseline (>0.05 gap) | Token 路线本身存疑，直接尝试 CLS + 频域插件 |
| GFNet (65-token) | Transformer baseline (65-token) | Val PCC < baseline | 跳试 265-token GFNet；如仍无效，放弃频域 token mixing |
| AFNO (65-token) | GFNet (65-token) | Val PCC < GFNet | AFNO 的额外复杂度无收益，停止 AFNO 分支 |
| GFNet (265-token) | Transformer baseline (265-token) | Val PCC < baseline + GFNet(65)也不如baseline | 频域方向在 token 路线上无效，关闭 |
| VSS Block ×2 (265-token) | Transformer baseline (265-token) | Val PCC < baseline | 放弃 Mamba 方向 |

> ⚠️ **与初版的关键区别**：初版用 CLS frozen 0.4113 作为所有方案的唯一门槛。修订后每种配置都有对应的同配置 baseline，避免"苹果比橙子"。
