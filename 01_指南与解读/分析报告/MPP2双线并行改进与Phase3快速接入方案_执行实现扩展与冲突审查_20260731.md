## 2. 与原方案冲突或需要用户确认的事项

以下内容不修改原文，只规定正式执行前必须如何处置。

### C01：A0 六折 LOPO 不是 accepted baseline 的简单复现

**原方案表述：** A0 用新的六折 LOPO 复现 accepted baseline。

**当前事实：** accepted baseline 使用 patch-level manifest 验证；仓库没有现成的六折 LOPO 编排器。改为六折 LOPO 会改变划分、checkpoint 选择和结果解释，属于新实验协议。

**建议处置：**

- 将 A0 正式命名为“同架构 LOPO 新基线”，不得称为 accepted baseline 的数值复现；
- 新建 experiment、绑定 W###、source commit、六个 outer folds 和 run budget；
- accepted baseline 继续作为历史锚点，LOPO A0 作为新协议对照。

**待用户确认：** 是否批准把 A0 作为新的正式实验，而不是只读方案准备。

### C02：LOPO 的 checkpoint 选择仍需定义

若直接使用 outer held-out patient 的标签选择 epoch，该患者同时参与模型选择和模型评估，LOPO 指标会偏乐观。

可选方案：

1. **低成本推荐：** 预先锁定 epoch 或训练步数，所有 outer folds 和候选完全一致；
2. 在五名训练患者内部再做 inner patient split，但会把单模型成本扩大到最多 30 次训练；
3. 只在五名训练患者内部使用 patch-level validation 选择 checkpoint，并明确它只是优化监控，不是患者级泛化证据。

**待用户确认：** 第一轮是否采用方案 1，以控制运行成本。

### C03：原方案宽表与 G16 五列科学产物合同冲突

原方案要求：

```text
patient, slide, patch_stem, x, y, pathway_01...pathway_30, ...
```

G16 正式科学预测产物要求五列长表。两者不能用同一个文件同时满足。

**建议直接校正为双产物：**

1. `prediction_long.csv`：严格满足 G16 五列合同，用于科学证据、指标和结果导入；
2. `phase3_feature_wide.parquet/csv`：面向 Phase 3 的宽表交付，不作为 G16 科学预测主表；
3. `provenance.json`：保存 patient、slide、坐标、score_type、checkpoint、通路顺序和哈希。

不得伪造历史 `sample_id` 或 `spatial_cluster_id`。

### C04：空间身份映射当前不闭环

A1-S、空间热点和 GraphSAGE 都需要可靠的样本身份与坐标。现有历史预测缺少这些列。

**执行门：**

- 只能通过 authoritative manifest 和特征文件名建立一对一映射；
- 必须验证总数一致、无重复、无缺失，并保存映射哈希；
- 禁止按 CSV 行号、DataLoader 顺序或文件系统枚举顺序回填身份；
- 无法完成无歧义映射时，A1-S 的科学验证状态为 `BLOCKED`。

### C05：Phase 3 终点尚未闭环

yzq 已审核材料中的现有实验使用 `pCR / non_pCR` 二分类标签，但尚未提供标签原始字段、医学判定标准、复核状态和完整逐患者字典。其他材料中的自由文本 `completely success` 仍不能直接等同结构化 pCR；空白患者也不能自动编码为 non-pCR。

**Phase 3 AUC 前置条件：**

- 完整逐患者标签表；
- pCR 的医学定义和正负类编码；
- 缺失/不确定标签处理规则；
- patient-level folds；
- 同一患者所有连续切片同折。

在此之前，已有 AUC 只能标为已审核团队探索结果；P0–P5 仍只能写成计划，不能生成或宣称 accepted AUC。

### C06：Phase 3 实际方法与实现路径仍需闭环

用户已确认删除此前误输入的方法简称。当前项目统一使用 CLAM、DTFD-MIL、TransMIL 等实际多实例学习方法名称，但本地仍没有 tracked Phase 3 实现可核验。

**待用户或队友确认：**

- 实际运行的是 CLAM、DTFD-MIL、TransMIL 中哪些方法，以及是否存在团队自定义实现；
- 当前服务器代码路径与 commit；
- 30 维通路究竟在 patch 级融合，还是先聚合到 patient 级。

### C07：XZY 的一次评估政策需要收紧

XZY 已经影响了研究问题。如果每个候选都在 XZY 上各评估一次，再根据 XZY 选择最终方法，仍会形成隐性外部集选择。

**推荐政策：**

- 所有候选只由 LOPO 排序；
- 每条路线最多选择一个预注册 winner 进入 XZY；
- XZY 只作描述性 external challenge，不据其结果返回调参；
- 若希望比较多个候选，论文中必须明确 XZY 不是纯 confirmatory test。

**待用户确认：** 是否采用“绝对线一个 winner + 相对线一个 winner”的 XZY 上限。

### C08：Phase 3 不能反复承担方法筛选和最终验证

原方案用 B1 的 Phase 3 AUC 决定是否开发 B2，再用同一队列评价 B2，会逐步把 78 人队列变成调参集。

**建议：**

- 若无独立 Phase 3 test cohort，则所有 P0–P5 结果均标为 exploratory；
- 或在 Phase 3 内建立固定 development/test 边界；
- B1/B2 的选择仅用 development folds；
- final test 只在完全冻结后使用一次。

### C09：原方案数值门槛目前只是候选阈值

`+0.005 PCC`、`+0.01 Spearman`、`+0.01 AUC` 等阈值尚未由当前重复方差或统计功效证明。

**建议：**

- 暂保留为 minimum effect size；
- 同时要求配对方向、患者覆盖、空间块 bootstrap 和不被单患者驱动；
- 在 A0 LOPO 得到重复方差后再冻结正式门槛；
- 未冻结前不得写入 Registry 作为自动 accepted gate。

## 3. 推荐的快速实验执行层级

## 3.1 E0：零训练证据准备

这一阶段不改模型、不训练、不碰 XZY 调参。

### E0-1：accepted 产物身份审计

输入：

- accepted checkpoint；
- repair manifest；
- pathway order；
- 现有 prediction CSV；
- authoritative feature manifest。

检查：

1. 预测行数能否与 manifest 一对一对应；
2. 每个 `sample_id` 是否唯一；
3. patient/slide/patch/coordinate 是否齐全；
4. 30 条通路顺序是否与 accepted checkpoint 一致；
5. 是否存在 NaN、Inf、重复条目；
6. 能否生成 G16 五列长表。

输出：

```text
identity_mapping_audit.json
prediction_long.csv
phase3_feature_wide.csv
provenance.json
```

晋级规则：

- 映射完全无歧义：`GO`
- 需要按行号猜测：`NO-GO`
- 缺坐标但 ordinal post-hoc 可运行：仅 B1 `GO`，A1-S `NO-GO`

### E0-2：Phase 3 接口最小审计

只要求队友返回以下事实，不要求其改模型：

```text
实际模型名称
代码 commit / 服务器只读路径
patch-level 或 patient-level 融合
通路文件 schema
patient_id / slide_id 对齐键
当前 folds 与 seeds
pCR 标签字典
完整标签人数统计
```

裁决：

- patch-level 融合：B1 可直接交付 30 维 ordinal 文件；
- patient mean 融合：B1 不能直接交付，需要先设计保留空间分布的统计量；
- 标签未闭环：只准备特征，不运行或解释 AUC。

### E0-3：当前 PCC 来源分解

不训练新模型，分解 accepted 预测：

- pooled PCC；
- 每通路跨 spot PCC；
- 每患者 pooled PCC；
- 去除通路均值后的 residual PCC；
- 通路均值常数预测器；
- prediction/target 的均值、标准差、线性斜率和截距；
- raw MAE、raw R²。

目的：确认高 pooled PCC 是否主要由通路间固定均值结构贡献，并判断 A1-S/B1 是否有科学基础。

## 3.2 E1：最低成本可实现探针

### E1-A：A1-S 代码与接口探针

在不产生正式科学结论的前提下，先实现并测试：

1. 同 patient、同 slide 建图；
2. `k=4/8` 的邻居索引；
3. 权重归一化；
4. `lambda=0` 时输出与原预测逐元素相等；
5. 不跨患者、不跨切片；
6. 缺坐标、重复坐标、组织空洞时显式报错；
7. 输出保持 30 维和固定通路顺序。

需要补充的实现约束：

- 先确认 `x/y` 是网格索引、像素坐标还是物理距离；
- 未知物理尺度时不得设置带医学单位的 radius；
- kNN 必须加最大距离或组织连通限制，防止跨空洞平滑；
- 只允许使用预测值和坐标，不读取真实标签参与推理。

科学状态：

- 在没有 A0 LOPO OOF 预测前，只能完成工程探针；
- 不得用 XZY 在四个平滑配置中选最优；
- 正式门槛必须在 A0 LOPO 后评估。

### E1-B：B1 post-hoc ordinal 探针

转换规则：

1. 先按 patient 合并该患者全部纳入切片；
2. 每条通路独立排序；
3. 并列值使用预注册的 average rank；
4. 缺失值不得参与分母，并单独报告；
5. 最小有效 patch 数不足时拒绝输出；
6. 输出 `ordinal_posthoc`，不得覆盖 absolute 文件。

必须冻结的 Phase 3 推理合同：

- ROI 范围；
- 背景/低质量 patch 过滤；
- 同一患者多切片是否合并排名；
- 连续切片重复区域如何处理；
- 最小 patch 数；
- ties 和 missing 的处理；
- 新患者的排名只使用该患者自身无标签预测，不使用其他患者。

重要解释边界：

- post-hoc ordinal 只是单调重编码，不代表 Phase 2 学习能力提升；
- 每条通路的患者内百分位均值接近 0.5；
- top-20% 比例按定义接近 20%；
- Phase 3 必须使用 patch-level 分布、注意力位置或空间拓扑，不能只取均值。

### E1-C：Phase 3 双文件交付探针

第一轮不做 Phase 2 双头模型，只生成：

```text
virtual_pathway_absolute.csv
virtual_pathway_ordinal_posthoc.csv
```

Phase 3 只需支持配置切换：

```text
pathway_feature_source = absolute | ordinal_posthoc
```

若确认输入层可从 30 维改为 60 维，再增加：

```text
pathway_feature_source = absolute_plus_ordinal
```

禁止第一轮同时修改 MIL 主体、优化器、folds、seeds 或 early stopping。

## 3.3 E2：正式 A0 LOPO 新基线

E2 需要新 experiment 和用户批准，不属于本次落盘授权。

## 4. 三个绝对线初始候选的具体实现顺序

## 4.1 A1-S：优先级 P0

前置：

- E0-1 身份审计通过；
- E2 A0 OOF 已完成；
- 坐标单位和组织连通规则明确。

运行矩阵：

| 编号 | k | lambda | 说明 |
|---|---:|---:|---|
| S00 | - | 0.00 | 恒等对照 |
| S41 | 4 | 0.10 | 轻平滑 |
| S42 | 4 | 0.20 | 较强平滑 |
| S81 | 8 | 0.10 | 较广邻域 |
| S82 | 8 | 0.20 | 较广且较强 |

选择只看六折 LOPO，XZY 不参与。除原方案指标外，增加：

- top/bottom 通路热点面积变化；
- 边界 patch 与内部 patch 分层结果；
- 预测方差收缩比例；
- 邻居坐标打乱对照。

若真实坐标平滑不优于坐标打乱，不得认为空间信息有效。

## 4.2 A1-P：优先级 P1

前置：

- A0 OOF 已完成；
- 训练折内可获得样本身份和 UNI 特征；
- patient-balanced sampling 已实现。

第一轮固定：

```text
K = 16
alpha = 0.10
metric = cosine
prototype = real medoid
```

训练折内流程：

1. 每名训练患者等额采样；
2. 仅在五名训练患者聚类；
3. 每簇选择真实 medoid；
4. 通路谱只用该簇训练标签计算；
5. outer patient 只检索，不参与建库；
6. 加入 shuffled-prototype-pathway 对照。

若 alpha 需要学习，只能在训练折内部拟合，不能用 outer patient 或 XZY。

## 4.3 A1-A：优先级 P2

该候选不是最便宜实验。六折 × 三个 seeds 至少为 18 次训练，另需等参数 MLP 对照。

结构必须明确：

```text
f_adapter = f + A(f)
prediction = accepted_head(f_adapter)
```

零初始化只保证 Adapter 分支初始为零；若同时随机重建预测头，则不能声称初始模型等价于 accepted baseline。

推荐第一轮：

- 从同协议 baseline checkpoint 初始化主预测头；
- 只增加 Adapter；
- 固定一个 bottleneck=64；
- 不搜索多种 dropout、loss 或宽度；
- 等参数 MLP 通过加宽普通头匹配可训练参数量。

只有 A1-A 超过等参数对照，才允许进入连续关系对齐。

## 5. 相对线初始候选的具体实现顺序

## 5.1 B1：优先级 P0

B1 不训练，工作量最低，但要先满足：

- Phase 3 为 patch-level 融合；
- patient/slide/patch 键完整；
- 每名患者的切片纳入规则固定；
- pCR 标签闭环后才评价 AUC。

Phase 2 只做描述性验证：

- 真实与预测的逐患者逐通路 Spearman；
- Kendall tau-b；
- top-20% hotspot Jaccard；
- 与随机输出、coordinate-only、patient mean template 比较。

Phase 3 第一轮仅比较：

```text
P0 HE only
P1 HE + accepted absolute
P3 HE + ordinal post-hoc
```

若要比较 `absolute + ordinal`，需先冻结输入维度变化，且不得同时改变融合网络。

## 5.2 B2：优先级 P1

B2 只有在以下任一证据成立时启动：

1. B1 对 Phase 3 development AUC 有稳定增量；
2. accepted baseline 在 XZY 的真实逐通路排序明显不足，但 ordinal 专门训练存在明确可检验假设。

ordinal 标签必须作为新的版本化派生资产：

- 不覆盖原始 ssGSEA；
- 不覆盖标准 z-score；
- 保存 patient、pathway、ranking method、ties method 和输入哈希；
- 每个 outer fold 的标签生成规则一致。

模型结构保持不变，只更换目标和指标。第一轮使用 MSE on percentile，不直接上 pairwise loss。

## 6. Phase 3 最低改动接入合同

### 6.1 推荐接口

每个 patch 一行：

```text
patient_id
slide_id
patch_stem
pathway_01 ... pathway_30
```

额外 provenance 不进入特征张量：

```text
score_type
source_commit
checkpoint_hash
pathway_order_hash
manifest_hash
ranking_scope
```

### 6.2 必须保持不变

在同一轮 P0–P5 比较中固定：

- patient folds；
- seeds；
- patch QC；
- HE features；
- MIL backbone；
- fusion method；
- optimizer；
- epoch/early stopping；
- label encoding；
- AUC 聚合方式。

### 6.3 AUC 报告

至少报告：

- 每折 patient-level ROC-AUC；
- pooled OOF patient-level ROC-AUC；
- PR-AUC；
- pCR/non-pCR 数量；
- 95% CI；
- 相同 folds 的配对差异；
- 4 seeds / 20 folds 的原始结果，而不只报告平均值。

### 6.4 必要低成本对照

虚拟通路来自 UNI 特征，因此应称为 pathway-supervised bottleneck，而不是独立模态。

建议至少加入一个训练折内生成的 30 维对照：

- PCA-30；
- 固定随机投影 30 维；
- 不使用通路标签的 30 维压缩。

任何 PCA 或可学习压缩器只能在 Phase 3 训练折拟合。

## 9. 需要用户最终确认的四个决策

1. 是否把 A0 定义为新的“同架构六折 LOPO 基线”，而不是 accepted baseline 的数值复现？
2. 是否采用固定 epoch/训练步数，避免六折外层患者参与 checkpoint 选择？
3. 是否限制 XZY 为每条路线最多一个预注册 winner 的一次描述性评估？
4. Phase 3 是否建立 development/test 边界；若不能，是否接受所有现阶段 AUC 仅为 exploratory？

在以上决策确认前，本文可以指导只读审计和接口准备，但不得启动正式训练或宣称任何候选通过。
