# JFX0729 数据替换后重跑实验清单

更新时间：2026-06-30

> **2026-06-30 状态更新**：JFX0729 更正数据已完成本地+服务器双端处理，但 token cache 重建与 P0 重跑暂缓。后续会先统一处理新的数据变换，再重建 JFX 相关缓存并执行重跑。本清单仍用于定义受影响范围和重跑对象；下面的执行顺序不是当前立即执行命令。

## 背景

当前发现 `JFX0729` 数据集中部分空间转录组数据无法与实际 H&E 图像匹配。由于 `JFX0729` 同时参与单患者训练、三患者联合训练、跨患者三折验证、在线训练体系和多种特征缓存，替换新数据后，所有直接或间接依赖 `JFX0729` 的实验结果都应视为历史参考，不能继续作为正式结论或论文/汇报主结果。

核心配置位置：

- `config.yaml` / `configs/config.server.yaml`
- 患者配置：`patients.JFX0729`
- 三折配置：
  - Fold1: `JFX0729 + LMZ12939 -> HYZ15040`
  - Fold2: `HYZ15040 + LMZ12939 -> JFX0729`
  - Fold3: `HYZ15040 + JFX0729 -> LMZ12939`

## 建议执行顺序（需等待新数据变换方案后执行）

0. 先确定并落地新的数据变换方案；不要在此之前重建 JFX token cache。
1. 替换或确认 `JFX0729` 原始 patch、train/val split 和 `JFX0729_ssGSEA_zscore.csv`。
2. 做数据一致性检查：patch 文件名、坐标、CSV 行名、train/val 交集、样本数。
3. 归档旧 JFX 缓存和旧 JFX 相关结果。
4. 重建所有 `JFX0729` 单患者特征缓存。
5. 先重跑 `JFX0729` 单患者基线，确认新数据可正常收敛。
6. 重跑 Fold2 测试 JFX 的跨患者流程，用来快速检查新 JFX 作为外部测试集是否合理。
7. 重跑 Fold1 和 Fold3，因为这两个 fold 的训练集包含 JFX。
8. 重跑当前主线在线实验：优先 `online_cls` LoRA baseline、`A0b`、`C1`、`S1a/S1b`。
9. 重跑 MultiPatient 实验。
10. 重新生成三数据集对比、三折 CV、模型排行榜和 README/仪表盘。
