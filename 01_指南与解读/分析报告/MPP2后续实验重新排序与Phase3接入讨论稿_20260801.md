## 1. 当前已确认事实

1. Phase 2 可用于后续联合输入的是 accepted 修复版冻结基线：`mpp2_barcode_repair_v003_frozen_baseline_20260711`。
2. `CalibratedMPP2` 已排除：Ridge r003 校准后 XZY mean raw R² 从 `-0.08801664` 变为 `-0.08803688`，mean raw MAE 从 `1176.21137` 变为 `1176.22480`，外部门失败且 `evidence_status=rejected`。
3. LoRA rank=8、LoRA dropout=0.10、Huber(delta=1) 和同合同 Ridge 重试均有停止结论，不列入本轮默认候选。
4. yzq 已审核材料中的 4 seeds × 5 folds 属于团队探索证据：仅病理 AUC `0.5856`、直接拼接 `0.5269`、特征融合 `0.6299`。不能据此宣称 accepted 增益，也不能通过删病例或替换低 AUC fold 形成正式结果。
5. 用户已决定后续 Phase 3 研究采用 H&E 与 accepted 修复版冻结 MPP2 原始输出联合输入；不再设置“是否采用 MPP2”的 P1。当前问题是特征融合与直接拼接如何公平比较，后续正式设计等待队友 Phase 3 基线包。

## 2. 对独立审查报告及原论文的仔细复核

### 2.1 UCell 与方案 1 Track B

UCell 的原方法是在**单个细胞/spot 内**对全部基因排序，再根据一个基因集内各基因的 cell-wise rank 计算 Mann–Whitney U 型签名得分。它证明的是：单细胞内的基因相对排序可以减少数据集规模和组成对基因集评分的影响。

报告中的 Track B 则是在**同一患者内**，对不同 patch/spot 的同一条预测通路排序。两者的排序轴不同：

| 方法 | 被排序对象 | 排序范围 | 输出含义 |
|---|---|---|---|
| UCell | 同一 cell/spot 内的不同基因 | 单个 cell/spot | 该 spot 的基因集活性 |
| Track B B1 | 同一患者内不同 patch 的同一通路 | 单个患者全部 patch | 该 patch 在患者内的相对空间活性 |

因此 UCell 是“采用 rank 降低尺度敏感性”的理论启发，不是 Track B 的直接验证。若要做真正 UCell 风格目标，需要从每个 spot 的原始基因表达重新计算 UCell 通路分数；这会触及受保护标签资产和目标重建，必须另开任务。当前低成本 B1 仍可做，但应称为 `within-patient spatial percentile`，不能称为 UCell 实现。

### 2.2 CHRep 与方案 2

报告把 CHRep 概括为“读取测试切片自身均值/方差并动态归一化”，这一表述不够准确。CHRep 是两阶段框架：训练阶段学习结构感知的图像—表达表示；推理阶段的校准模块也由**训练切片和 training gallery**构建，包括非参数估计、可学习修正和修正幅度约束。它不是把任意冻结模型接上一次测试切片归一化就能复现。

因此方案 2 应改名为“CHRep 启发的 training-gallery 后校准探针”，并满足：

- 所有 gallery、近邻、修正参数只来自训练折；
- 不读取 XZY 或 Phase 3 测试折真值，也不使用完整队列统计量；
- 不能复用 `CalibratedMPP2` 名称；
- 先在 Phase 2 患者级 LOPO 中验证，再进入 Phase 3 融合比较。

A1-S 空间平滑与 CHRep 后校准是不同假设，不应合并成同一个实验。

### 2.3 Visual Prompt Tuning 与方案 3

VPT 原论文确实冻结视觉 Transformer 主干，并把少量可学习 prompt token 插入 Transformer 输入；VPT-Deep 在论文的 24 个识别任务中有 20 个超过 full fine-tuning，且可训练参数低于主干的 1%。

但本项目当前 accepted MPP2 使用的是已经缓存好的 `1536` 维 UNI2-h CLS 特征。VPT 不能在这些固定 CLS 向量之后补做：prompt 必须进入 UNI2-h 的 token 序列，并重新执行在线前向传播。项目迁移还存在四个差异：

1. 原论文主要是图像识别，本项目是 30 通路回归和跨患者 LOPO；
2. 只有 6 名 Phase 2 训练患者，少参数不等于不会患者级过拟合；
3. 需要重新建立在线 UNI2-h + prompt + MPP head 管线，不能复用纯缓存训练成本；
4. 必须预先锁定 VPT-Shallow 或 VPT-Deep 的一个最小配置，并与等参数 Adapter 对照，不能直接展开 prompt 长度和深度 sweep。

已有 LoRA 阴性结果不直接否定 VPT，但说明任何 UNI2-h 适配都必须采用 internal-first、患者级 LOPO 和非常有限的运行预算。

### 2.4 SPIRAL 与方案 3 中的 OT

SPIRAL 原论文处理的是多个空间转录组数据集之间的整合和坐标对齐：`SPIRAL-integration` 使用 GraphSAGE 与图域适配，`SPIRAL-alignment` 使用聚类感知的 Gromov–Wasserstein OT 对齐空间坐标。输入依赖基因表达、空间邻接、坐标和聚类结构。

它并没有直接证明可以把 H&E 1536 维特征点云无监督对齐到 30 维通路空间。将其迁移到本项目至少要重新定义：

- H&E 图与通路图的节点是否一一对应；
- 两侧距离或结构代价如何构造；
- cluster constraint 从哪里获得；
- OT coupling 如何防止把形态相似但生物学不同的区域错误匹配；
- 训练患者学到的 coupling 如何外推到 Phase 3 无 ST 真值患者。

所以 SPIRAL 更适合作为“空间图建模和跨患者结构对齐”的远期方法依据，而不是当前可直接执行的 H&E—通路适配器。

## 3. 删除旧 P1 后的重新排序

| 层级 | 当前任务 | 对应报告方案 | 排序 | 解锁条件 |
|---|---|---|---:|---|
| G0 | 取得并核验队友 Phase 3 基线实验、协议、fold 和预测 | 前置事实输入 | **前置硬门槛** | 基线包能复现直接拼接/特征融合定义与 20 个测试折来源 |
| F1 | 同一 H&E+accepted raw MPP2 输入下比较直接拼接与特征融合 | 当前已决定研究问题 | **第 1** | G0 到位；同一患者划分、MIL、临床变量、预算和 checkpoint 规则 |
| S1 | B1 within-patient spatial percentile，先绝对+ordinal 双视图 | 方案 1 / UCell 启发 | **第 2，首个新 MPP2 候选** | F1 冻结一种融合基线；patch-level 输入可用，不能只均值池化 |
| S2 | CHRep 启发 training-gallery 后校准；A1-S 单独作为空间探针 | 方案 2 | **第 3** | Phase 2 LOPO、训练折 gallery、身份和坐标闭环；禁止测试统计量泄漏 |
| S3 | 单一预注册 VPT 探针 | 方案 3A | **第 4** | 在线 UNI2-h token 管线、W###、Registry、运行预算和等参数对照 |

| S5 | B2 ordinal 端到端训练、GraphSAGE/GAT/ConvSSM 等 | 方案 1 升级或复杂扩展 | **条件候选** | B1 或 A1-S 先证明明确价值 |

## 4. F1：当前真正需要比较的是融合方式

用户已经决定采用 H&E+MPP2，因此不再以 H&E-only/pathway-only 作为是否采用 MPP2 的决策门。队友基线到位后，只在相同输入和相同协议下比较：

1. **直接拼接**：需要队友提供其准确实现位置、拼接发生在 patch 级还是患者级、拼接前是否投影/标准化；
2. **特征融合**：需要明确是双分支投影、门控、交叉注意力还是其他结构，以及参数量差异。

公平比较至少要求固定：患者 fold、随机种子、MIL 主干、输入 patch、临床变量、类别权重、训练 epoch、checkpoint 选择和 AUC 聚合方式。当前探索结果中特征融合 `0.6299`、直接拼接 `0.5269`，差值约 `+0.1030`，足以支持继续核验，但尚不能证明结构性优势。

H&E-only 如果队友基线包已经包含，可作为背景参照保留；本项目不再新增一个“是否采用 MPP2”的 P1，也不以其结果推翻用户已确定的联合输入路线。

## 5. S1：方案 1 的建议落地方式

第一步只做 B1 post-hoc，不重新训练 MPP2：

```text
accepted raw MPP2 patch predictions
  -> 每位患者内、每条通路独立计算 spatial percentile
  -> 保留 absolute 30维 + ordinal 30维
  -> 接入 F1 选定的融合结构
```

先比较 `H&E + absolute` 与 `H&E + absolute + ordinal`。如果 B1 没有稳定增量，就不解锁 B2 端到端 ordinal 训练。纯 ordinal 替代 absolute 可作为解释性附加组，但不应先扩大主比较矩阵。

## 6. S2：方案 2 的建议落地方式

方案 2 拆为两个独立探针：

- `S2-C`：CHRep 启发的 training-gallery 近邻估计/残差修正，所有参数在训练折产生；
- `S2-S`：A1-S 空间邻域平滑，只利用同一切片内坐标邻居，并设置 identity 与坐标打乱对照。

二者都先在 Phase 2 LOPO 检查 raw R²、MAE、逐通路相关和空间稳健性，再把冻结输出放入 F1 选定的 Phase 3 融合方式。不得把测试患者自身分布用于选择修正强度。

## 7. S3/S4：VPT 与 SPIRAL/OT 必须拆开

- **VPT 优先于 OT**：虽然需要在线重跑 UNI2-h，但假设和参数边界相对明确，可以设计一个极小、预注册的 prompt 探针。
- **OT 后置**：SPIRAL 式方法需要完整空间图和聚类约束，当前证据缺口更大；不能把一次通用 GW 对齐直接解释为 H&E—通路生物学对齐。

## 8. 明确不进入本轮排序的路线

- `CalibratedMPP2` 或同合同 Ridge 重试。
- LoRA rank、dropout、学习率或 epoch sweep。
- Huber(delta=1) 原合同重试。
- 使用 XZY 真值做截距、斜率、通路或 checkpoint 选择。
- 删除病例、替换低 AUC fold 后将结果作为主性能。
- 在同一约 78 例上连续筛选 Track B、CHRep、VPT 和 OT，再把最高 AUC 当作最终验证。

## 9. 当前执行裁决

| 对象 | 裁决 | 原因 |
|---|---|---|
| 删除旧 P1、固定 H&E+MPP2 联合输入 | GO | 用户已明确决定，已写入当前指令 |
| 取得队友 Phase 3 基线包 | GO | 只读事实输入，是 F1 和后续方案的前提 |
| F1 融合方式合同起草 | NO-GO NOW | 尚无可核验的基线代码、fold、参数量和预测包 |
| B1/S1 接口设计 | CONDITIONAL GO | 基线包到位后可先做无训练设计；不得提前解释 AUC |
| CHRep/VPT/OT 实验 | NO-GO NOW | 均需独立假设、工作树、Registry、预算和正式批准 |

## 10. 向队友索取 Phase 3 基线时的最小清单

1. 准确 patient manifest、pCR/non-pCR 数量、纳排记录及患者—切片—patch 对应表。
2. 4 seeds × 5 folds 的每折患者 ID、随机种子、标签与是否存在重复患者。
3. 直接拼接和特征融合的代码、配置、参数量、融合位置和输入标准化方式。
4. 实际使用的 CLAM、DTFD-MIL 或 TransMIL 主干及 checkpoint 选择规则。
5. 每折 ROC-AUC/PR-AUC、OOF patient prediction、训练日志和未删改的全部 fold 结果。
6. 输入 MPP2 的 experiment ID、checkpoint SHA、通路顺序和输出尺度。
7. 代码 commit、环境版本、运行命令，以及是否给某一方法额外临床变量或不同训练预算。

基线包到位后，下一次讨论只需先回答两个问题：直接拼接与特征融合是否真正同协议；随后是否按本稿顺序先做 B1，而不是立即启动 CHRep、VPT 或 OT。
