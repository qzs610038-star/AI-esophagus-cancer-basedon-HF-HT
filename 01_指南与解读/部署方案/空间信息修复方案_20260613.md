## 一、问题诊断：当前架构的四个结构性缺陷

### 问题 1：参数量是第一约束 — 任何增加参数的操作都在当前小样本下加速过拟合

**实验证据链**（Train-Val Gap 均取 Epoch 2，即过拟合开始显现的节点）：

| 实验 | Δ参数量 | ΔPCC | Epoch2 Train-Val Gap |
|:---|:---:|:---:|:---:|
| CLS Frozen → CLS LoRA r=8 | +极少 (LoRA 低秩) | **+5.1%** | 0.201→0.172 (收窄，可控) |
| CLS Frozen → CLS Stage2 | +2 层 ViT Block 解冻 | ±0% | 0.201→**0.281** (+40%) |
| CLS Frozen → CLS Stage3 | +4 层 ViT Block 解冻 | **-1.4%** | 0.201→**0.336** (+67%) |
| GFNet Frozen → GFNet modReLU | +bias 参数 (seq_len/2+1)×dim | **-6.1%** | 0.160→**0.241** (+50%) |
| GFNet Frozen → GFNet LoRA r=8 | +极少 (LoRA 低秩) | **+5.1%** | 0.160→0.194 (可控) |

**规律**：单调且一致 — 只有低秩约束（LoRA）能稳定增益。任何放松参数约束的操作（解冻层 / 新增可训练模块）都导致 Train-Val Gap 扩大 40%~67%，泛化性能退化或不变。

**结论**：模型表达能力已饱和。在 ~15K patches / 2 患者训练的条件下，额外自由度几乎必然拟合训练噪声而非真实信号。

---

### 问题 2：当前所有改进集中在 224×224 patch 内部预测能力 — 完全忽略全切片 patch 间空间关系

当前架构中，每个 patch 的预测是**完全独立**的：

```python
# model_online_tokens.py L189-191
x = self.proj(encoded)                             # [B, dim]
x = x + self.x_embed(pos_x) + self.y_embed(pos_y)  # 唯一的空间信息：可学习坐标偏置
x = self.head(x)                                   # [B, n_targets]
```

`x_embed(pos_x) + y_embed(pos_y)` 仅表示"在这个位置的 patch 平均表达水平偏高/偏低"，无法建模：
- **邻域平滑约束**：相邻组织的基因表达应高度相关
- **空间梯度信息**：肿瘤-基质交界处的表达梯度
- **全局上下文**：patch 在全切片中的位置（如肿瘤中心 vs 边缘）

之前 GAT 实验（0.4068，低于 Frozen 0.4113）和 EGN-v2+UNI 跨患者三折（0.3537 / 0.3909 / 0.3967，来源 `histogene/checkpoints/results_vis/CrossValidation_3Fold_Comparison/cross_validation_summary.csv`）均未稳定超过 CLS Frozen。空间关系不是没价值，而是**参数化的空间图模型在小样本下会把空间噪声学进去，而非提取真实的邻域依赖。**

---

### 问题 3：cls_patch64 取前 64 个 token — 丢弃每个 patch 底部 75% 的空间信息

UNI2-H 输出结构（265 tokens）：

```
[CLS, reg_0..reg_7, patch_0..patch_255]
 ───┬───  ─────┬─────  ───────┬───────
  1 个     8 个 register     256 个空间 token (16×16 grid)
```

当前 `cls_patch64` 实际获取：

```
16×16 token grid:
┌──────────────────┐
│ ██ rows 0-3 (64) │ ← 保留（前 25%）
├──────────────────┤
│ .. rows 4-15     │ ← 丢弃（后 75%）
│   (192 tokens)   │
└──────────────────┘
```

在病理切片中，腺体结构、免疫浸润、基质分布可能出现在 patch 的任何位置。底部 75% 区域可能包含关键的诊断信息（如浸润前沿、坏死区域、血管结构）。

**这个截断是纯粹为控制过拟合（减少 token 数 → 减少 GFNet FFT 序列长度 → 减少全局滤波器参数量）而做的妥协，代价是系统性信息丢失。**

---

### 问题 4：patch 边界 token 的空间连续性被切分破坏 — 相邻 patch 的边界的 token 在组织中实际连续

```
原始 HE 切片（连续组织）:
┌────────┬────────┬────────┐
│  P0    │  P1    │  P2    │
│        │        │        │
├────────┼────────┼────────┤  ← patch 边界（人工切分，组织实际连续）
│  P3    │  P4    │  P5    │
│        │        │        │
└────────┴────────┴────────┘

P0 底部边缘 token（grid row 15）↔ P3 顶部边缘 token（grid row 0）
→ 在组织中物理相邻，但模型完全独立处理
```

每个 224×224 patch 内的 16×16 token grid：
- 第 15 行的 16 个 token 与正下方 patch 第 0 行的 16 个 token 在组织学上连续
- 第 15 列的 16 个 token 与右侧 patch 第 0 列的 16 个 token 在组织学上连续

**这些跨 patch 边界的 token 对，其空间关系比 patch 内两个远距离 token 更紧密，但当前架构完全忽略了这个结构。**

## 二、核心判断

**当前瓶颈不是表达能力不足，而是跨患者泛化不足。下一步最优方向不是"加模块"，而是"在不增加自由度的前提下，把已经存在但被切块和采样破坏的空间信息恢复出来"。**

| 方向 | 判断 | 理由 |
|:---|:---:|:---|
| 继续加模块（GNN/Mamba/全 WSI Transformer/大 concat） | 🔴 暂停 | 小样本下参数增加 → 过拟合加速，8 个实验中 6 个失败 |
| CLS LoRA r=8 全折验证 | 🟢 P0 保留 | 当前最强基线 (0.4322)，不可动摇 |
| 低参数修复空间信息组织 | 🟢 P0 核心方向 | cls_pool8x8 (零参数) / 空间后处理 (零训练) / TV 正则 (低参数) |
| 等待 9 患者数据 | 🟡 并行等待 | 数据到齐后大样本可放宽参数约束，但空间信息修复在 3 患者下已有验证价值 |

## 四、Step 1: cls_pool8x8 — Token 采样修复（P0，立即执行）

### 原理

将 `cls_patch64`（CLS + 16×16 grid 前 4 行的 64 token）替换为 `cls_pool8x8`（CLS + 16×16 grid 经 2×2 avg pool → 8×8 = 64 token）：

```
当前 cls_patch64:                    提案 cls_pool8x8:
  patch[0:256] (16×16)                patch[0:256] (16×16)
       ↓                                    ↓
  取前 64 个 (rows 0-3)              reshape → [16, 16]
       ↓                                    ↓
  CLS + 64 tokens                    AvgPool2d(k=2) → [8, 8]
  = 65 tokens                              ↓
                                     flatten → 64 tokens
                                           ↓
                                     CLS + 64 tokens
                                     = 65 tokens
```

### 优势

| 属性 | cls_patch64 | cls_pool8x8 |
|:---|:---:|:---:|
| 参数量 | 0（选择操作） | 0（无参数 pooling） |
| 序列长度 | 65 | 65（GFNet FFT 维度不变） |
| 空间覆盖 | 25%（仅 rows 0-3） | **100%（全 16×16 grid）** |
| 噪声抑制 | 无 | 2×2 pooling 自带均值降噪 |
| 代码改动量 | — | `model_online_tokens.py` 新增一个 select mode |

### 实现

在 `model_online_tokens.py` 的 `select_uni_tokens()` 中新增 `"cls_pool8x8"` 模式：

```python
elif mode == "cls_pool8x8":
    if num_tokens != 65:
        raise ValueError(
            f"cls_pool8x8 is only defined for num_tokens=65, got {num_tokens}"
        )
    cls_token = all_tokens[:, 0:1, :]                      # [B, 1, D]
    patch_start = 1 + reg_tokens                             # 跳过 CLS + reg
    patch_tokens = all_tokens[:, patch_start:patch_start + 256, :]  # [B, 256, D]
    D = patch_tokens.shape[-1]
    # reshape 为 2D grid → pool → flatten
    patch_grid = patch_tokens.transpose(1, 2).reshape(-1, D, 16, 16)  # [B, D, 16, 16]
    pooled = F.avg_pool2d(patch_grid, kernel_size=2, stride=2)         # [B, D, 8, 8]
    pooled_flat = pooled.reshape(-1, D, 64).transpose(1, 2)           # [B, 64, D]
    return torch.cat([cls_token, pooled_flat], dim=1)                  # [B, 65, D]
```

| 实验 ID | 模型 | Encoder | Mode | Token Select | 对照基线 | 目的 |
|:---|:---|:---|:---|:---|:---|:---|
| **S1a** | OnlineTokenModel | gfnet | frozen | cls_pool8x8 | A0b (0.3967) | 纯采样修复：全空间覆盖能否提升 frozen 表现？ |
| **S1b** | OnlineTokenModel | gfnet | lora r=8 | cls_pool8x8 | C1 (0.4169) | Token+LoRA 是否从全空间覆盖受益？ |

> ⚠️ **已删除 S1c（CLS LoRA + cls_pool8x8 + freq_branch="mean"）**：`freq_branch="mean"` 并非干净的 CLS 对照，它会在 CLS 分支之外额外 concat patch mean 特征（回归头输入从 1024d → 2560d），显著增加参数量。历史 B1b（0.3955）已提示此类结构风险。CLS LoRA 原版（0.4322）保持不变，不参与此轮 token 采样对比。若 S1a/S1b 正信号强烈，再考虑在 CLS 模式下设计更干净的对照（如替换 CLS token 为 pooled CLS，而非额外 concat）。

**决策门**：
- S1a ≥ A0b + 0.01 (≥0.4067) → cls_pool8x8 替代 cls_patch64 成为 Token 路线新默认

## 五、Step 2: 零参数空间后处理（P1，Step 1 完成后执行）

### 前置条件：修改 predictions.csv 导出

⚠️ **当前 predictions.csv 仅保存 `true_*` / `pred_*` 列**（见 `train_online_tokens.py` L828-835 / `train_online_cls.py` L835-842），缺少 `filename` / `patient` / `x` / `y` / `pos_x` / `pos_y`，**无法直接做空间 KNN**。

**必须先在两个训练脚本的 `evaluate()` 中增加导出列**：
```python
# 在 evaluate() 保存 predictions 时追加：
pred_df['filename'] = all_filenames   # 样本 stem
pred_df['patient'] = all_patients     # 患者 ID
pred_df['x'] = all_x_raw              # 原始像素 X 坐标
pred_df['y'] = all_y_raw              # 原始像素 Y 坐标
pred_df['pos_x'] = all_pos_x          # 归一化 X 索引
pred_df['pos_y'] = all_pos_y          # 归一化 Y 索引
```

这需要 evaluate() 在遍历 val_loader 时同步收集 metadata。改动量约 +15 行/脚本。

### 原理

在现有模型的 **predictions.csv** 上直接做空间平滑，不重新训练任何模型。

### 2a. 简单空间平滑（alpha sweep）

对每个 patch，将其预测值向空间邻居的均值混合：

```
pred_i' = (1 - α) × pred_i + α × mean(pred_j  for j in spatial_neighbors(i, k=6))
```

- `α ∈ {0.05, 0.1, 0.15, 0.2, 0.3}` — 扫 5 个值
- `k=6` — 每个 patch 取 6 个最近空间邻居（与 TV loss 的 KNN 一致）
- 在修改导出后的 `predictions.csv`（含坐标列）上跑，计算平滑后的 PCC

**数据来源**：C1 (0.4169) 和 CLS LoRA (0.4322) 需重新跑一次 evaluate() 以生成含坐标的 predictions.csv（仅推理，不需重新训练）

**执行命令**：
```bash
python scripts/spatial_smooth_post.py \
  --predictions checkpoints/online_tokens/<run_dir>/predictions.csv \
  --k 6 \
  --alphas 0,0.03,0.05,0.1,0.15,0.2,0.3 \
  --coord_cols x,y \
  --group_col patient
```

输出：`spatial_smooth_alpha_sweep.csv`，包含每个 alpha 的 mean PCC 与相对 alpha=0 的增量。

### 2b. 边界 token 相似度加权平滑（进阶）

利用 UNI2-H 的 token 特征：对相邻 patch，计算它们共享边界处的 token 的余弦相似度作为平滑权重：

```
# 对 patch_i 和其下方邻居 patch_j:
edge_i = patch_i 的底部边缘 token  (16×16 grid row 15) → 均值 [1, D]
edge_j = patch_j 的顶部边缘 token  (16×16 grid row 0)  → 均值 [1, D]
w_ij = cosine_similarity(edge_i, edge_j)  # 范围 [0, 1]
pred_i' = (1 - α) × pred_i + α × Σ(w_ij × pred_j) / Σ(w_ij)
```

**关键**：边界 token 相似度在组织学上有明确含义——如果两个相邻 patch 的边界区域组织形态相似（高 cosine similarity），它们的基因表达预测应该更一致。如果边界是组织学过渡带（如肿瘤-基质交界），相似度低，平滑权重自然降低。

**与问题 4 的对应**：这直接回应了"patch 边界 token 空间连续性被切分破坏"——把切断的 token 关系通过相似度权重重建，但不引入额外可训练参数。

**实现复杂度**：
- 2a（简单平滑）：纯 numpy/pandas，~20 行代码，直接在 predictions.csv 上跑
- 2b（边界 token 相似度）：需要回跑一次 backbone 取边界 token 特征（每 patch 取 row 0 和 row 15 的 16 个 token 做 mean），存储为 `.npy` 缓存，然后做加权平滑

### 决策门

- 2a 最佳 α 带来 PCC +0.005 以上 → 空间平滑信号成立，进入 Step 3
- 2a 最佳 α 带来 PCC +0.003~0.005 → 信号弱但存在，考虑仅在特定通路上平滑
- 2a 无改善或负改善 → 当前瓶颈不在空间不连续性，暂停 Step 3，重新评估方向
- 2b 显著优于 2a → 边界 token 信息有独立价值，后续可考虑将边界 token 相似度纳入训练 loss

## 六、Step 3: 训练内空间正则化（P1，条件性 — 仅 Step 2 正信号后触发）

### 原理

将 TV/Laplacian 空间平滑约束直接集成到训练 loss 中，而非后处理阶段。

### 历史依据

旧离线 Token 系统（AugMix, 基线 ~0.4142）的 TV sweep 结果：

| 配置 | Best Val PCC | Δ 基线 |
|:---|:---:|:---:|
| l2 w=0.01 | 0.4170 | +0.0028 |
| laplacian w=0.1 | 0.4169 | +0.0027 |
| l2 w=0.05 | 0.4156 | +0.0014 |

⚠️ **增益幅度小（+0.003）**，且未在当前最强基线 CLS LoRA (0.4322) 上验证。CLS LoRA 的低秩约束本身已提供隐式特征平滑，空间正则的增量可能更小。

### 实验矩阵（条件性）

| 实验 ID | 模型 | 正则化 | 目的 |
|:---|:---|:---|:---|
| S3a | CLS LoRA r=8 | TV l2 w=0.01 | 最强基线上验证 TV 增益 |
| S3b | Token+LoRA + cls_pool8x8 | TV l2 w=0.01 | Token 路线验证（需 Step1 S1b 达标） |
| S3c | CLS LoRA r=8 | 通路选择性 Laplacian | 对形态相关通路 (ECM/Fibrosis/Wound/Angiogenesis/tls/Hypoxia) 用更高权重 |

### 通路选择性正则

基于 CLS LoRA Cross-Fold1 逐通路 PCC：

```
强平滑 (w_tv × 1.0):               弱平滑 (w_tv × 0.3):           不平滑 (w_tv = 0):
ECM (0.725)                       IL6 (0.573)                  Interferon_Alpha (0.049)
Fibrosis (0.688)                  EMT (0.545)                  ifng (0.162)
MYC (0.719)                       toxic (0.537)                tgfb (0.165)
Wound_Healing (0.599)             Coagulation (0.317)          Apoptosis (0.201)
OxPhos (0.685)
tls (0.642)
Glycolysis (0.580)
```

逻辑：PCC 高的通路 → 模型预测可信 → 空间平滑"修正"更安全。PCC 极低的通路 → 预测几乎随机 → 平滑只会扩散噪声。

**实现**：`SpatialTVLoss.forward()` 接受 `pathway_weights: [n_targets]` 参数，逐通路加权后再 mean。

### 决策门

- S3a Val PCC ≥ CLS LoRA + 0.005 → TV 正则正式纳入标准训练配置
- S3c 显著优于 S3a → 通路选择性正则成为新的正则化范式
- 三项均不达标 → 空间正则方向在当前样本量下确认不成立，关闭

## 八、风险与注意事项

### 风险 1: cls_pool8x8 可能不如 cls_patch64

2×2 pooling 从 256→64 是 4× 空间分辨率压缩。如果病理关键特征（如单个免疫细胞浸润）在 16×16 grid 上仅占 1-2 个 token，pooling 后可能被平均掉。

**缓解**：对比 S1a vs A0b 的逐通路 PCC，如果某些通路显著下降，说明这些通路依赖细粒度空间特征，pooling 不适配。可考虑备选方案 `cls_uniform8x8`（16×16 grid 上 stride=2 均匀采样 64 个 token，保持 65 序列长度不变，避免改变 GFNet filter 参数维度）。

### 风险 2: TV/Laplacian 增益在 CLS LoRA 上可能消失

CLS LoRA 的低秩约束已隐式提供特征平滑。历史 TV sweep 增益仅 +0.003 且是在旧系统上测的。

**缓解**：Step 2（零参数后处理）先跑，如果 2a 的 alpha sweep 在 CLS LoRA predictions 上无任何正 alpha，则 Step 3 的风险极高，建议跳过。

### 风险 3: 9 患者数据到齐后优先级重排

如果 9 患者数据在 Step 1 执行期间到齐，部分实验（特别是 S1b）可能需要在新数据上重跑才能得出可靠结论。

**缓解**：Step 1 的 2 个实验在 3 患者上仍有独立验证价值（验证"采样修复"这一通用命题）。9 患者到齐后优先跑 CLS LoRA 全 9-fold，Step 1 结果作为 Token 路线的方向判断依据。

### 风险 4: 边界 token 相似度的计算成本

Step 2b 需要对每个 patch 做一次 backbone 前向取边界 token，对于 ~2600 个验证样本约需 30-60 min（纯推理，不需梯度）。

**缓解**：先用 2a（简单平滑，零成本）验证空间平滑信号的符号和幅度，2b 只在 2a 正信号后才投入。

**决策门 S1a ≥ 0.4067 → FAIL。**

### 根因分析

cls_pool8x8 的 2×2 average pooling 将 16×16 token grid 压缩为 8×8，虽然保留了全空间覆盖，但**平均掉了对病理关键特征敏感的细粒度 token**：

1. **信息丢失**：256→64 tokens 是 4× 空间分辨率压缩。单个免疫细胞浸润、微血管结构等可能仅占 1-2 token 的特征在 pooling 后被周围组织稀释
2. **Train-Val Gap 反常扩大**：0.2603 vs A0b 的 0.1600（+63%），说明 pooling 引入了额外的训练-验证不匹配——训练集的组织纹理均值可能与验证集分布不同
3. **与 modReLU 的类比**：A1 (modReLU) 也是通过截断弱频率分量损失了纹理信息（-6.1%），cls_pool8x8 通过均值降噪损失了空间分辨率（-4.6%），机制不同但效果相似

### 对后续的影响

- **S1b (LoRA+cls_pool8x8)**：LoRA 的低秩约束可能部分补偿 pooling 的信息损失（LoRA 在 CLS 和 Token 模式上均有 +5.1% 增益），但 S1a 的 -0.018 差距较大，S1b 需要 +2.3% 才能回到 A0b 基线，需要 +4.8% 才能达到决策门 0.4269。**概率偏低但仍值得验证**（LoRA 可能从全空间覆盖中提取到 cls_patch64 丢弃的底部 75% 信息）
- **cls_uniform8x8 备选**：stride=2 均匀采样 64 token（不做平均），保持序列长度 65，可能是 cls_patch64 和 cls_pool8x8 之间的帕累托最优——全空间覆盖 + 无信息平均损失
- **Step 2a 空间后处理**：S1a 无 predictions.csv（训练被中断），无法跑 alpha sweep。S1b 训练时等待完整 epoch 循环结束以生成含坐标的 predictions.csv
