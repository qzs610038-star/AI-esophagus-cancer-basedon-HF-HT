## 3. 两个替换模型的基本架构与输入输出

### 3.1 UNI 原版：每张图像块生成一个 1024 维向量

UNI 原版采用 ViT-L/16，即大型视觉 Transformer，内部将输入图像分成 16×16 像素的小块。每个小块转换成一个 token（局部表示单元），然后通过自注意力层，让各局部表示交换图像信息。一个额外的 CLS token（全图汇总表示）承担整体图像块的特征表达。

在本轮 224×224 输入下，图像被划为 14×14＝196 个内部小块，配合 CLS 共 197 个表示单元。UNI 原版的内部表示宽度为 1024；本实验提取最终 CLS，得到每张图一个 1024 维向量。UNI 的预训练采用 DINOv2 自监督路线，执行本实验时不重新开展该预训练，也不使用其预训练损失训练通路头。

| 项目 | 本轮 UNI 接口 |
|---|---|
| 官方模型 | `MahmoodLab/UNI`，原版 UNI，不是 UNI2-h |
| 基本架构 | ViT-L/16，16 像素内部小块，1024 维表示 |
| 图像输入 | `[B, 3, 224, 224]`；B 是批次图像数，3 是 RGB 通道数 |
| 提取输出 | `[B, 1024]`，每张图取最终 CLS |
| 下游映射 | 1024→256→30 |

直观理解：UNI 负责将一张病理图像块压缩成 1024 个数，下游预测头再学习这些数与 30 条通路活性之间的对应关系。来源：[UNI 官方模型卡](https://huggingface.co/MahmoodLab/UNI)、[作者代码](https://github.com/mahmoodlab/UNI)。

### 3.2 Virchow2：本轮取一个 1280 维 CLS

Virchow2 采用 ViT-H/14，即大型视觉 Transformer，内部小块大小为 14×14 像素，32 层、16 个注意力头，内部表示宽度 1280。前馈部分使用 SwiGLU 门控结构；构造模型时保留作者要求的 `SwiGLUPacked` 和 `SiLU`。

224×224 输入产生 256 个图像 token，另有 1 个 CLS 和 4 个 register tokens（辅助内部计算的表示单元）。完整输出为 `[B,261,1280]`，其中 B 为图像批次大小。本轮**主特征取第 0 项 CLS，输出 `[B,1280]`**。

```text
图像 [B,3,224,224]
  → Virchow2
  → 完整输出 [B,261,1280]
      ├─ 第 0 项：CLS [B,1280] → 1280→256→30 回归头
      └─ 第 5 项及以后：256 个图像 token → 求均值并单独保存，暂不送入回归头
          第 1–4 项辅助 token 不参加平均
```

作者默认推荐将 CLS 与图像 token 均值拼接成 2560 维，也说明可以尝试单独使用 CLS 或均值。此前采用 2560 有作者使用范式作为依据，但会同时改变本轮的汇总接口。鉴于当前问题是对照既有 UNI2-h 的 CLS 单点基线，本版选择 **CLS 对 CLS**，并在报告中写明“Virchow2-CLS”，不称为评估了其官方推荐完整拼接表征的最佳效果。来源：[Virchow2 官方模型卡](https://huggingface.co/paige-ai/Virchow2)。

### 3.3 为什么 CLS 已经包含内部小块信息

UNI、UNI2-h 和 Virchow2 都先将一张病理图像块划成内部小块，再通过自注意力让 CLS 汇总这些小块的信息。因此 UNI2-h 的 1536 维 CLS 本身也利用了图像内部信息。**区别在于最终交给预测头的是单独 CLS，还是 CLS 加上另一份局部均值表示。**

用户对“只替换基模，却只给 Virchow2 增加均值分支”的疑问成立。本轮统一只交付 CLS，可减少这一额外设计差异。不同编码器的预训练数据、内部宽度、层数和 CLS 特征标度仍各不相同，这些属于被替换的编码器；本轮不声称三种编码器每个内部因素都相同。

### 3.4 统一的 256 维回归头

**d 维 CLS → 带偏置 Linear(d,256) → 精确 GELU → Dropout(0.3) → 带偏置 Linear(256,30)。**

Linear 是线性层，GELU 是非线性激活，Dropout 是训练时随机失活。256 维映射是可训练预测头的一部分，离线特征保持编码器原生维数；不先经过随机投影再保存。

| 编码器 | 本轮主输入 d | 回归头 | 可训练参数量 |
|---|---:|---|---:|
| UNI2-h | 1536 | 1536→256→30 | 401,182 |
| UNI 原版 | 1024 | 1024→256→30 | 270,110 |
| Virchow2-CLS | 1280 | 1280→256→30 | 335,646 |

参数量公式为 `256×d + 7,966`，包含两个线性层的偏置。统一的是头的结构与隐藏宽度，输入层参数量随原生维数变化，如实报告即可。本轮不加补零、截断、PCA 降维、额外投影层、特征标准化或 L2 归一化。

### 3.5 mean-patch 的保存与使用分开

mean-patch 指**最终图像 token 向量的平均值**，不是像素均值，也不是邻近病理图像块的均值。保存时与主 CLS 分开，并使用同一身份索引。

| 编码器 | 完整 token 输出（224 输入） | mean-patch 取法 | 本轮保存安排 |
|---|---|---|---|
| UNI | `[B,197,1024]` | `tokens[:,1:,:].mean(1)`，196 个图像 token | 新提取 CLS 时同步保存 1024 维辅助向量 |
| UNI2-h | `[B,265,1536]` | `tokens[:,9:,:].mean(1)`，排除 CLS 与 8 个 register | 已有完整、来源匹配的 token 时可直接计算；只有 CLS 或 65-token 缓存时记为不可用，不为此重提取 |
| Virchow2 | `[B,261,1280]` | `tokens[:,5:,:].mean(1)`，排除 CLS 与 4 个 register | 新提取 CLS 时同步保存 1280 维辅助向量 |

UNI 和 Virchow2 在同一次编码器前向中取得 CLS 与局部均值，不额外跑第二遍模型；新增均值向量本体合计约 102 MiB（11,589 点、float32，不含元数据）。UNI2-h 的 CLS 无法反推出局部均值，不能以补零或部分 token 的均值冒充。来源：[UNI2-h 模型卡](https://huggingface.co/MahmoodLab/UNI2-h)、[UNI 模型卡](https://huggingface.co/MahmoodLab/UNI)。

本轮不训练任何 CLS+mean-patch 分支。后续是否接入这些辅助向量由用户另行决定；辅助文件缺失不影响本轮 CLS 主比较。

### 4.2 图像缩放和归一化：做了什么，以前有没有做

**缩放**解决输入像素尺寸问题。双三次插值根据邻近像素估计缩放后的像素值，使图像适配编码器输入；它不会增加新的组织信息。**裁剪**则选择图像中的一部分，两者不能混为“保留完整视野”。

**ImageNet 通道归一化**先把普通 8 位 RGB 像素由 0–255 转为 0–1，再逐通道计算 `(像素值−均值)/标准差`。均值为 `(0.485,0.456,0.406)`，标准差为 `(0.229,0.224,0.225)`。例如红通道 0.5 变为约 0.066。目的在于将图像数值送入预训练模型期望的尺度。这些是固定常数，不从本项目的训练、验证或 XZY 重新估计，也不同于标签 z-score 或对输出特征做标准化。

**以前做过这两件事，但具体缩放链需要区分。** 旧 UNI2-h 本地加载分支调用 `create_transform(input_size=224, is_training=False, interpolation="bicubic", mean=ImageNet均值, std=ImageNet标准差)`，未传 `crop_pct`。本机 timm 1.0.26 展开及 timm 1.0.27 源码均表明，此默认分支是：

```text
同一既有 PNG → RGB
→ 短边缩放至 256（双三次）
→ 中心裁剪 224×224
→ 转为 float32、像素缩放到 0–1
→ ImageNet 通道归一化
→ 编码器
```

默认 `crop_pct=0.875`，对正方形图片保留的是中心约 87.5% 边长、76.6% 面积。即使 PNG 已为 224×224，这条链仍会先放大再裁剪；不能理解为“原图已经 224，所以无需实际处理”。这是几何覆盖比例，不是特征余弦相似度应达到的验收阈值。

来源：[旧加载器预处理][旧预处理]、[timm 1.0.27 评估变换源码](https://github.com/huggingface/pytorch-image-models/blob/v1.0.27/timm/data/transforms_factory.py)、[torchvision 0.21 Resize 文档](https://docs.pytorch.org/vision/0.21/generated/torchvision.transforms.Resize.html)。

### 4.3 用旧基线协议约束新模型，避免为了新协议重提取

v1.0 的“完整图像直接缩放为 224×224”与上述旧本地分支不同，现已取消该默认。**当前按上述旧分支准备共同预处理；全量提取前，先从实际缓存来源记录确认第一轮采用的分支。** 若现场证据表明实际使用另一条链，例如从 HF 配置构造的变换，则将新模型统一对齐实际旧链，并在准备报告中记录依据，不凭模型各自默认设置决定裁剪方式。

确认本地分支后，未来代码显式使用 Pillow 读取 RGB、torchvision 对 PIL 图像短边 `Resize(256, BICUBIC, antialias=True)`、`CenterCrop(224)`、转张量和上述归一化；记录 Pillow、torchvision、timm 版本及展开后的变换。PIL 图像的双三次缩放本身带抗锯齿处理；不另加模糊，不混入张量后端重采样。

三模型使用同一个点位对应的既有图像、相同组织区域和像素变换，不增加随机裁剪、翻转、染色增强、测试时增强或更大邻域。读取训练点图像时编码器也保持评估模式，不启用训练增强。

核对缓存来源时分别覆盖六名开发患者和 XZY。先检查既有日志、清单、加载分支和实际命中路径；缺记录记为未核实，不能据此自动判废缓存。若出现真实冲突，列出差异及最小补救方案供用户裁定，不自动全量重提取；在未解决前也不宣称预处理已完全一致。

### 4.4 UNI2-h 特征与已训练基线的复用

| 资产 | 默认处理 | 确实存在问题时 |
|---|---|---|
| 既有 UNI2-h CLS 缓存 | 只读复用原路径，以第一轮实际命中记录为准，核对身份、1536 维及数值可用性 | 先定位缺失或错误的具体点位；不静默丢行，也不自动更换全量缓存 |
| 种子 42 的 point 结果 | 复用第一轮相同划分、标签、头结构、训练配方、选模规则及种子的预测/正式检查点 | 仅指标缺项时本地重算；预测缺项时可由已有正式检查点补推理，不等同于重训 |
| 种子 43、44 的 point 结果 | 用户决定补种子时按同样条件复用对应历史种子 | 不重复计作新运行，不用三种子平均替代单种子参照 |
| 旧 spatial 与 Phase 3 | 保持原输入、缓存、权重和结果 | 本次消融不触发其重新训练或迁移 |

历史结果须按同一评价代码重算或核对后纳入比较表，并注明“历史匹配参照复用”、原批次和运行日期。复用范围只涵盖上述匹配 point 臂，不是任意历史 UNI2-h 成绩。缺失的真值应按既有身份和原训练标准化参数补齐；不另拟合标签处理。

第一轮没有完整提取元数据的项目保持未知，不把 float32 文件反推成全程精度开关均已证实。如果以后证据确实要求更换 UNI2-h 特征，相关 point 头通常需要重新训练评估；这属于需另行裁定的实质变更，当前默认不做。也不以本轮不同编码器的 point 与旧 spatial 相减来解释空间残差增益。

### 4.5 新特征的保存

新提取 UNI、Virchow2 均使用冻结编码器、评估模式和 FP32（选择理由见第 6 节），不启用 AMP，显式关闭矩阵运算和 cuDNN 的 TF32。主 CLS 与辅助 mean-patch 均存为 float32，按同一身份索引组织为 `N×d` 矩阵；各训练种子复用一次提取的结果。

元数据包含：模型/版本/本地权重路径，图像与身份清单，输入像素尺寸，实际预处理，CLS/辅助向量字段，排除的辅助 token 数，维数与 dtype（数值类型），软件版本、提取批量和资源记录。旧 UNI2-h 的未知字段单独标记历史缺项。新缓存写入独立特征目录，不覆盖旧文件；新旧来源可在 `feature_caches.json` 中并列登记。

三个模型的主 CLS 向量本体合计约 170 MiB；保存完整 token 矩阵不是本轮交付要求。

### 5.2 初始化能否统一：统一规则、随机流和可共享参数

**可以统一初始化规则和种子；不能让不同形状的输入权重逐元素相同。单独写三次“seed=42”还不够。** 原模型使用 PyTorch `nn.Linear` 默认初始化：权重和偏置按输入宽度的 `1/√fan_in` 范围初始化。三个输入层沿用同一规则，其数值范围随 1536/1024/1280 的输入宽度自然变化。[原创建顺序与种子设置][旧初始化]

未来实现按以下方式配对：

1. 每个模型初始化使用同一模型种子，种子 42 对应 42，模型随机偏移为 0；输入层在 CPU 上按原规则构造。
2. **共同输出层复制原初始值。** 从对应种子的第一轮 `initial_weights.pt` 读取 `point_head.weight`（30×256）与 `point_head.bias`（30），分别复制给 UNI、Virchow2。文件内的 relation/spatial 参数不进入新预测头。不能复制训练后的输出层。
3. 原初值附件不可用时，按第一轮源码的创建顺序重建 UNI2-h 模板并核对后使用。不同输入层消耗随机数不同，不能把“同种子依次创建两层”当成输出层初值相同的保证。
4. 采样单独使用 `PCG64(seed+100000)`。复用原训练身份顺序并核对已保存的 `center_orders`；保存的是行索引时必须同时核对该行代表的点位，不能只比数字排列。
5. Dropout 单独使用 CPU `torch.Generator(seed+200000)`，每批生成相同 `[批量,256]` 掩码，保留概率 0.7、保留值除以 0.7。编码器提取、初始化、诊断和验证不消耗此随机流。

每个模型分别重置以上随机流，因此同种子共同训练阶段的点位顺序和 Dropout 掩码一致。模型若不同轮次早停，只要求重叠训练阶段一致；新模型训练超过历史参照轮数时继续同一规则生成随机流。未来验收要逐元素核对输出层初值、点位顺序和掩码，而不是只核对种子数字。

本次已验证历史种子 42 的输入/输出初值重建一致、41 轮点位顺序重建一致。新模型尚未实现，不能提前宣称三模型运行已验证一致。[历史初值][旧初值文件]、[历史点位顺序][旧顺序文件]、[采样与 Dropout 原代码][旧随机流]

### 5.3 “-1 惩罚”是什么意思，以前是否用过

Pearson 相关需要预测和真值都有变化。假设某条通路的真值是 0、1、2，而模型对三个点都预测 0.5，则预测方差为 0，PCC 不可定义。若选模时直接跳过这条失败通路，模型可能反而因只剩较容易的通路而得到偏高分数。原实现因此把这一项的**选模分数**记为 -1，再参与患者—通路等权平均。

这是已有检查点排序规则，**不进入 MSE 损失，也不额外扣训练损失**。真实测量 PCC 仍为 NA（不可定义），并记录原因；若真实计算得到 PCC=-1，则是有效的完全负相关，应照常报告。真值本身为常量或点数少于 2 时，则按旧规则排除并记明原因。

第一轮配置明确有 `constant_prediction_selection_penalty=-1`，训练每轮调用该实现，所以该规则此前已经启用。本次读取种子 42 正式最佳的内部预测，六患者×30 通路中常量预测和常量真值均为 **0 项**；这只说明该最佳检查点没有触发常量情形，不代表检查了全部轮次或全部种子。[原配置][旧配置选模]、[原处理代码][旧选择指标]、[核对的预测文件][旧内部预测]

## 6. 精度推荐与暂缓事项

### 6.1 本轮只选 FP32

推荐**新特征提取和预测头训练均采用 FP32（单精度）**，不同时运行 FP16（半精度）版本，也不增加两种精度的嵌入相似度对比。

| 考虑 | 依据及取舍 |
|---|---|
| 旧实验连续性 | 原 UNI2-h 提取代码未启用 AMP，缓存样本为 float32；第一轮头部训练明确 FP32。新模型沿用 FP32 可避免为了改用 FP16 再动旧缓存 |
| 服务器资源 | 2026-09-05 实测为 RTX 4080，显存 17,170,956,288 字节（约 16 GiB）；PyTorch 2.6.0+cu124、torchvision 0.21.0+cu124、timm 1.0.27。不是本机 RTX 4060 8 GB |
| 工作量 | 11,589 个固定图像点位；只对 UNI、Virchow2 新提取一次，不反向训练编码器，各种子共享缓存 |
| 显存安排 | 一次加载一个编码器，起始提取批量 16；显存不足依次降至 8/4/2/1。训练头的批量保持 256 |
| 官方 FP16 建议 | Virchow2 作者确实推荐 GPU 上用 FP16 自动混合精度提高运行效率；它是可采用的推理方式，不意味着 FP32 输出无效。本轮优先旧协议连续性 |
| 性能限制 | FP32 可能比混合精度慢；当前没有现场耗时测量，不承诺具体时长，也不保证批量 16 一定装得下 |

资源依据：[服务器原始检查报告][服务器检查]；精度建议来源：[Virchow2 模型卡](https://huggingface.co/paige-ai/Virchow2)。历史检查不是当前可用显存或空闲状态，服务器启动后读取实际资源即可，不因此安排双精度实验。

新运行关闭 AMP 及 TF32，缓存保持 float32。旧特征的 dtype 不能证明其当年所有算子精度；历史缺少 TF32 开关记录时如实登记，不伪装成已经与新流程逐算子一致，也不仅因此重提取。

## 10. 本地评价口径与首批报告

### 10.1 两种 PCC 并列

PCC 为 Pearson 相关系数。内部验证和 XZY 分别报告：

- **患者—通路等权平均 PCC**：先在每位患者、每条通路的点位之间计算相关，再在有效通路和患者层面等权汇总；同时保留不可定义计数和选模惩罚口径。
- **pooled PCC（整体展平 PCC）**：将该集合所有点位×30 条通路的 z 分数整体展平，再计算一次相关。

两种 PCC 的汇总对象不同，不能因一种绝对值更高就认定其方法更好。若另外计算“合并点位后逐通路平均 PCC”，用 `pooled_pathway_pcc` 单独命名，不与上述两种混用。该统计名称也与 Virchow2 图像 token 的平均汇总无关。

本轮首先对齐实际第一轮的算术等权 PCC。若后续分析需保留既有指标合同中的 Fisher-z 聚合（先变换相关系数再汇总），应另起明确字段并对三个模型对称计算，不能悄悄替代选模或旧基线的算术均值；当前不因这项扩展延迟 CLS 主比较。

### 10.2 误差、其他指标与原标度真值

首批核心表包括双 PCC、z-MSE、原标度 MAE、最佳轮次、训练时长、特征提取时长、显存峰值和预测头参数量。保留各患者、各通路明细，并按现行项目合同保留 z-RMSE、z-MAE、CCC（一致性相关）、Spearman（秩相关）、原标度 R²、训练标准差归一化误差，以及可定义的空间结构指标和 Top-k 通路重叠。

可由原始预测导出的指标、图表与汇总都在本地完成。服务器仅计算训练、早停、选模所需指标，保存原始预测、真值和必要元数据。指标的患者/通路聚合与整体展平口径应在字段名和说明中区分，不能直接复用旧分析函数中的整体 R² 或整体 Spearman 代替逐患者逐通路指标。

原标度预测按 `pred_raw = pred_z × train_sd + train_mean` 逆变换一次，不重新标准化，不额外裁剪预测。既有 z 标签经过 [-100,100] 裁剪时，逆变换后的真值不一定等于原始 ssGSEA 真值。因此优先使用按身份对齐的原始真值计算 raw-MAE/raw-R²；若只能还原裁剪后的真值，明确标注该口径，不冒充原始未裁剪指标。原始真值与修复标签存在差异时先报告差异，不静默覆盖。

空间指标如果使用坐标邻接或空间窗口，应在本地对所有模型采用同一评价定义；不能拿随编码器特征变化的图权重评价不同模型。尚未固定窗口、有效 mask（掩膜）或 Top-k 的 k 值时保留明确的不可计算/未预定义状态，不为凑齐表格临时填值。

首批只显示种子 42，明确为单种子结果，不生成三种子标准差。三种子齐备后，先逐种子计算指标，再报告均值和样本标准差；先平均预测再评价的集成结果属于另一方法，不替代这一主表。

| 独立运行与回传 | 新包脱离上级仓库仍可运行；新权重、新缓存、原始输出分别落入指定根目录；历史资产保留旧路径 |
| 本地评价 | 统一复算或核对双 PCC 和误差；测量 PCC 与选模惩罚分开；单种子无虚假三种子标准差 |

以上为后续代码验收要求。本次只做原有文档、配置、文件和局部历史逻辑核验，没有运行新包测试。

处理实际故障即可：权重权限或网络失败记录具体原因；新模型加载不匹配停止该模型；身份或数值问题先定位修复；显存不足降低提取批量。训练中断保留日志、检查点和部分结果，修复后另建运行目录。未安排审计建议中的强制负对照训练、双精度对比或“特征余弦必须明显偏高”判定。

## 13. 以后增加其他病理基础模型

增加模型时，先确认它在同一图像块视野上的主输出接口，然后添加适配器和模型清单项，明确官方版本、权重文件、输入尺寸、输出维数及汇总定义。有 CLS 时优先延续 CLS 主比较；无 CLS 时明确接口差异，由用户决定如何纳入。通过接口测试后，接入共同 d→256→30 预测头和现有训练、评价流程。

新增模型默认也先运行种子 42，报告全部已完成模型的匹配结果，并按用户安排补种子。已有特征和结果只在共同合同一致时复用；若新模型要求全组改变预处理或训练方法，应建立新协议版本，而不是改变已有比较表的含义。
