## 优先学习与关键决策点（KDP）

### KDP-1：服务器传输层是否永久彻底禁用 Git LFS 并改用普通 Git Blob？
- **为什么关键**：Gitee 远端免费/基础仓库不支持 Git LFS。根目录 `.gitattributes` 中的 `*.pth filter=lfs` 导致 RCC 模型权重在回传 push 时触发 Exit 40 阻断，是 W007 最严重的传输故障。
- **可选方案与代价**：
  - **方案 A（建议）**：在全仓库属性及传输规范中明确禁用 Git LFS，轻量模型权重（$\le 10\text{MB}$）强制采用普通 Git Blob 传输，超大资产只记录路径与 SHA-256。
  - **方案 B**：为每个实验单独编写局部 `.gitattributes`。代价是容易在后续新实验中遗漏，再次引发推送失败。
- **用户确认点**：是否同意项目级默认禁用 Git LFS 并规范化 10MB 内权重的普通 Git 传输。

### KDP-2：治理状态机是否正式采纳“终态 Attempt 解耦源码 Rebind”（SSRR-11）？
- **为什么关键**：原状态机只要检测到历史存在 `EXPERIMENT_STARTED` 就永久锁死 source commit，导致在多阶段实验中发生故障并完成单臂恢复后，无法为后续臂绑定修复后的新代码。
- **可选方案与代价**：
  - **方案 A（建议）**：状态机仅对处于 live（运行中）状态的 Attempt 保持源码硬锁定；历史 Attempt 均为 `RESULT_RETURNED` / `ATTEMPT_FAILED` / `REJECTED` 等终态且剩余预算 $>0$ 时，允许重新绑定新 source commit。
  - **方案 B**：保持原锁死策略，每次遇到代码修复必须强行新建实验与 W###。代价是实验编号迅速消耗膨胀，破坏预注册批次的因果完整性。
- **用户确认点**：是否批准将 SSRR-11 终态解耦规则固化为项目通用治理标准。

### KDP-3：多臂探针实验应采用“原子结果集模型 (`result_set_v1`)”还是拆解为单臂独立实验？
- **为什么关键**：W007 的 FBR/RCC/HCR/CPGCR 是同时预注册、共享基线与因果对照的四臂实验。通用 importer 强制要求单 job/单 source/单 result.json，导致四臂无法合规入库。
- **可选方案与代价**：
  - **方案 A（建议）**：引入 `result_set_v1`，顶层登记实验整体信息与公平性评估顺序，底层逐臂独立绑定 Attempt、Source Commit、Return Commit 与原始预测表，四臂全部验证通过后原子写入。
  - **方案 B**：将四臂强行拆成四个独立实验分别导入。代价是破坏了多臂同批对照的科学设计，并篡改了初始批准的语义。
- **用户确认点**：是否批准在通用治理层支持 `result_set_v1` 原子导入。

## 1. 方案目标与非目标

### 1.1 治理目标
1. **基础设施加固**：消除 Gitee LFS 传输冲突，建立操作卡绝对解释器路径静态扫描机制，避免 Exit 9009 / Exit 40 类低级运行与传输阻断。
2. **状态机鲁棒性**：固化终态 Attempt 解耦、单臂已完成幂等续接（`resume`）、非破坏性日志回传（`--run-root`）及 `local_only` 文档扫描豁免。
3. **数据模型升级**：在治理 CLI 中规范化 `result_set_v1` 多臂原子导入模型，完整保留分段源码（Segmented Source）的来源链。
4. **技能体系优化**：更新 `sync-server`、`train-guide`、`post-train` 与 `pfmval-audit` 技能说明，将排障经验固化为操作规范。

### 1.2 非目标
- 不启动任何模型训练或重跑；
- 不修改既有 accepted 实验证据及数值；
- 不依据 XZY 指标做模型选择或超参调整；
- 不重写历史 Git commit 树；
- 不引入外部未授权的远程控制通道（保持 Gitee-only 边界）。

## 3. 具体调整清单与实现规范

### 3.1 配置与传输层（Layer 1）
1. **修改根目录与工作树 `.gitattributes`**：
   ```gitattributes
   # 明确禁用 Git LFS，避免 Gitee Push Exit 40
   *.pth -filter -merge -diff text=auto
   *.pt -filter -merge -diff text=auto
   ```
2. **强化 `server_paths.yaml` 运行时契约**：
   - 增加运行时静态扫描规则：任何由模板生成的 `.cmd` 或 Markdown 操作卡，必须包含解释器存在性前置断言（`if not exist "C:\Users\AIPatho1\pfmval_env\Scripts\python.exe" ...`），严禁包含裸 `python` 命令。

### 3.2 治理状态机与代码约束层（Layer 2）
1. **状态机 Attempt 状态机逻辑升级**：
   - 在 `scripts/pfmval_state.py::bind_experiment_execution` 中实现：
     ```python
     # 仅当存在运行中的 attempt 时阻断 rebind
     live_attempts = [a for a in attempts if a.status in ['STARTED', 'RUNNING']]
     if live_attempts:
         raise GovernanceError("Cannot rebind source: live attempts in progress")
     # 终态 attempt 且预算充足时，允许为后续 attempt 绑定新 source
     ```
2. **原子结果集导入器规范**：
   - 支持 `deploy/pfmval_ops.py result import-set`，要求传入包含四臂 return ref 的清单，独立重算每臂 Internal/External 指标，全量通过后单次事务写入 `experiments/experiment_registry.json`。
3. **划分与标签路径隔离**：
   - 在训练上下文准备逻辑中，强制校验 `split_manifest` 来源与 `data_manifest_id` 对应的修补目录，禁止共用同一个根路径前缀以防 HYZ15040 类重复标签污染。

### 3.3 技能文件（Layer 3）
1. **`.agents/skills/sync-server/SKILL.md`**：
   - 补充说明：明确 Gitee 传输通道为 Pure Git 模式，严禁开启 LFS；大文件回传前必须检查局部 `.gitattributes`。
2. **`.agents/skills/train-guide/SKILL.md`**：
   - 补充说明：生成的训练卡必须显式引用注册的虚拟环境绝对解释器，并在本地使用静态语法分析检查。
3. **`.agents/skills/post-train/SKILL.md`**：
   - 补充说明：增加多臂实验分段回传规范，明确 `--run-root` 仅用于日志恢复，不得触发重新训练。

## 5. 风险控制与回退预案

- **风险 1：状态机修改引入非预期行为**
  - **控制**：所有状态机修改必须伴随红灯/绿灯单测；任何修改前备份 `project_state/` 快照。
- **风险 2：禁用 LFS 导致大于 100MB 单文件推送失败**
  - **控制**：PFMval 的回传模型头权重通常为 6~8MB；若未来出现超大模型，强制采用“本地计算/服务器留存 + SHA256 元数据回传”策略，不破坏 Gitee-only 通道。
- **回退策略**：若修改导致现有门禁异常，使用 Git 一键回滚到修改前基线提交，不改变任何已入库的实验数据。
