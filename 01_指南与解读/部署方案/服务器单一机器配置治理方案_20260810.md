## 目标

`configs/server_paths.yaml` 是唯一人工维护的服务器机器配置。机器路径、Python 解释器和 Gitee 传输约束只在此文件维护；科学协议不再写入服务器机器配置。

## 已实施治理

1. **SPD1 服务器配置概要设计（Server Profile Design）**：将机器配置升级为 Schema `2.0`，新增 `runtime` 和 `transport`，保留已登记的路径状态、角色和写入策略。
2. **CM2 配置迁移（Configuration Migration）**：Python 与路径事实归入 `server_paths.yaml`；患者、交叉验证继续由 `config.yaml` 管理。旧 Phase 3 CLAM 配置不再作为服务器机器配置；其现有科学事实仍受当前 directive 与后续 critical contract 约束。
3. **CR3 消费端改造（Consumer Rewrite）**：Python 解析器从 `runtime.python_interpreter` 读取解释器；通用配置加载不再接受 `PFMVAL_CONFIG`。启动器不再写入 `PFMVAL_CONFIG` 或 `PFMVAL_PYTHON`。
4. **LR4 旧配置退役（Legacy Retirement）**：根目录与 `configs/` 下的 `config.server.yaml` 均为 fail-closed legacy 指针；两个旧 server config path id 标为 `deprecated`，不得用于新输出。
5. **VT5 最小验证（Validation Tests）**：验证 Schema、运行时解释器、Gitee-only 传输、遗留变量拒绝和既有严格启动门禁。

## 边界与后续门禁

- 本治理不验证服务器目录或解释器真实存在；带有 `live_verification_required` 的路径仍须经用户批准的 Gitee diagnostic 现场核验。
- 未创建或修改实验、job、attempt、结果包、受保护 MPP 资产或科学结论。
- `CURRENT_STATE.md` 的来源摘要更新需要哈希治理确认；本轮不执行状态同步或摘要重算。
