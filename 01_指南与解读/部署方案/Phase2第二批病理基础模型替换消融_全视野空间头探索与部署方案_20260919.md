## 五、统一输入协议与模型原生预处理

### 5.1 不变的几何协议

三个新编码器与三个基线必须共享同一几何协议：

```text
full_fov_224_bicubic_v1:
1. 读取完整 patch。
2. 转为 RGB。
3. 要求宽度等于高度；非方形立即失败。
4. 将完整方形精确缩放到 224×224，bicubic，antialias=true。
5. 转为 float32，像素范围 [0,1]。
6. 再执行该编码器的原生归一化。
```

禁止事项：

- 不允许 `resize shorter side -> center crop` 的旧裁剪协议。
- 不允许随机裁剪、旋转、翻转、颜色扰动或其他数据增强。
- 不允许对非方形图像静默拉伸、中心裁剪或补边。
- 不允许依据模型推荐 MPP 重新切 patch；这会改变实验问题和数据输入。

### 5.2 输入归一化：旧模型已有，H-optimus 使用不同配置

这里的归一化是**输入图像的逐通道标准化**。图像先转换为 `[0,1]` 范围的 RGB 浮点数，再对红、绿、蓝三个通道分别执行：

```text
normalized_channel = (pixel_channel - channel_mean) / channel_std
```

`mean`（均值）和 `std`（标准差）决定模型实际看到的数值坐标系。它们不是根据本项目训练集临时计算的参数，而是与病理基础模型预训练时的输入处理配套的固定常数。预训练权重是在该数值分布下学到的；如果换成另一套均值和标准差，即使原始 patch 完全相同，送入编码器的张量也会明显改变，可能形成输入分布偏移。因此，不能为了表面上的“所有模型使用相同数字”而覆盖模型要求的归一化。

这不是三款新模型才有的步骤。原先的 UNI2-h、UNI 和 Virchow2 实验也执行了输入归一化，只是三者当时恰好共用同一套 ImageNet RGB 配置，所以旧方案中不需要为每个模型单独分支。已接纳全视野代码在 `experiments/phase2_fullfov_hpo_v1/src/transforms.py` 中对三者统一执行 `(x-mean)/std`，冻结配置 `training_reference/effective_config.json` 也记录了相同数值：

```text
mean = (0.485, 0.456, 0.406)
std  = (0.229, 0.224, 0.225)
```

三个新模型中，情况分为两类：

- **Phikon-v2** 仍使用 ImageNet RGB 均值和标准差，因此和原先的 UNI2-h、UNI、Virchow2 相同。
- **H-optimus-0 和 H-optimus-1** 的官方加载示例指定了 H-optimus 专用 RGB 均值和标准差，因此必须单独建立 `hoptimus_rgb_v1` 配置。两款 H-optimus 彼此使用同一套数值。

所以，本批并不是“只有新模型才做归一化”，而是把原先隐含的单一公共配置改成显式的**按模型选择配置**：几何处理仍完全一致，最后一步的 RGB 数值标准化与各模型预训练接口保持一致。

| 模型 | 旧实验是否已有输入归一化 | 本批归一化配置名 | mean | std |
|---|---|---|---|---|
| UNI2-h | 有 | `imagenet_rgb_v1` | 0.485, 0.456, 0.406 | 0.229, 0.224, 0.225 |
| UNI | 有 | `imagenet_rgb_v1` | 0.485, 0.456, 0.406 | 0.229, 0.224, 0.225 |
| Virchow2 | 有 | `imagenet_rgb_v1` | 0.485, 0.456, 0.406 | 0.229, 0.224, 0.225 |
| H-optimus-0 | 新增该模型，但归一化步骤本身不是新增概念 | `hoptimus_rgb_v1` | 0.707223, 0.578729, 0.703617 | 0.211883, 0.230117, 0.177517 |
| H-optimus-1 | 新增该模型，但归一化步骤本身不是新增概念 | `hoptimus_rgb_v1` | 0.707223, 0.578729, 0.703617 | 0.211883, 0.230117, 0.177517 |
| Phikon-v2 | 新增模型；沿用旧实验同类配置 | `imagenet_rgb_v1` | 0.485, 0.456, 0.406 | 0.229, 0.224, 0.225 |

实现上应将“全视野几何协议”和“归一化配置”拆成两个独立字段。例如，六个模型都使用 `full_fov_224_bicubic_v1`，但 H-optimus-0/1 绑定 `hoptimus_rgb_v1`，其余四个模型绑定 `imagenet_rgb_v1`。这样既能保证各模型看到完全相同的图像范围和 224×224 尺寸，也能保证输入数值符合各自预训练接口。

需要特别区分两类容易混淆的归一化：

- 本节讨论的是**图像输入归一化**，发生在病理基础编码器之前，参数来自模型预训练接口。
- 项目另有**30 条通路标签的 z-score 标准化**，发生在预测目标上，参数只由训练集估计，用于防止量纲差异和数据泄漏。

两者作用对象、参数来源和执行位置均不同，代码与元数据中不得共用同一个 `mean/std` 字段而不注明所属对象。

因此，本实验比较的是“编码器及其配套输入归一化”这一完整特征提取管线，而不是把所有权重强行置于相同像素归一化下的纯权重比较。对本批而言，这种处理比强制统一数值更符合模型的预期使用方式。若要单独研究共同归一化的影响，应另建敏感性实验，不能混入本批主比较。

### 5.3 MPP 风险边界

H-optimus-0/1 官方期望约 0.5 µm/px；当前项目输入属于 `MPP2/group_2`，但本地冻结配置中的 `patch_coverage_size` 尚缺失，不能仅凭组名和网格坐标确认图像物理覆盖范围或与 0.5 µm/px 完全匹配。

实施要求：

- 在缓存元数据和最终报告中记录 `official_expected_mpp=0.5` 与 `project_mpp_status=unverified`。
- 不因该警告自动重切图、重采样原始 WSI 或改变现有 patch。
- 结论表述限定为“在当前项目固定 patch 协议下的替换结果”，不能写成三个模型在各自最佳原生扫描尺度上的绝对排名。

## 六、输出适配合同

现有全视野代码的编码器适配器偏向三维 token 输出，不能原样套到两个 H-optimus 模型。建议在 `inputs/model_manifest.json` 为每个模型显式定义 `loader_type`、`output_mode`、`feature_dim` 与 `normalization_profile`。

建议的输出模式：

```text
timm_tokens_cls
  适用：现有 UNI、UNI2-h、Virchow2。
  输入：模型返回的 token 张量。
  输出：按既有已验证逻辑提取 CLS。

timm_final_embedding
  适用：H-optimus-0、H-optimus-1。
  输入：model(x) 返回的二维张量 [B,1536]。
  输出：原样使用，不做 token 切片或均值。

transformers_last_hidden_cls
  适用：Phikon-v2。
  输入：outputs.last_hidden_state [B,197,1024]。
  输出：[:,0,:]，得到 [B,1024]。
```

适配器必须进行硬校验：

- 输出 rank 与 `output_mode` 一致。
- 最后一维与 manifest 的 `feature_dim` 一致。
- batch 维与输入一致。
- 全部值有限，不含 NaN/Inf。
- 保存前显式转为 CPU float32。
- H-optimus 若返回三维张量或 Phikon 若没有 `last_hidden_state`，应失败并报告接口变化，不得猜测替代输出。

本批主缓存只保存选定的单 patch 特征。不要为三个新模型额外保存未使用的 mean-patch、register token 或全 token 张量。

## 七、特征维数与预测头参数量

### 7.1 不做公共维数投影

本批必须保留每个编码器的原生特征维数：

- H-optimus-1：1536。
- Phikon-v2：1024。

- 既有 Virchow2：1280。

### 7.2 空间头随输入维数变化

固定空间头结构为：

```text
H: Linear(d, 256, bias=True) + exact GELU
C: Linear(256, 30, bias=True)
B: Linear(256, 30, bias=False)，初始权重全零
```

空间臂总参数量为：

```text
256 × d + 15,646
```

| 特征维数 d | 对应模型 | 空间头参数量 |
|---:|---|---:|
| 1536 | H-optimus-0、H-optimus-1、UNI2-h | 408,862 |
| 1280 | Virchow2 | 343,326 |
| 1024 | Phikon-v2、UNI | 277,790 |

不同输入维数导致第一层参数量不同，这是替换原生编码器时的自然结果，不是实现错误。最终报告必须披露该差异，避免把实验描述成“预测头参数量完全相同”。更准确的表述是：头部拓扑、隐藏维度、激活、失活、训练和图参数相同，输入层宽度随编码器原生特征维数变化。

### 7.3 初始化的严格配对

已接纳 Phase2 基线运行包含 `raw/initial_weights.pt`。对于特征维数相同的新旧模型，Grok 应实现全 state dict 精确比对：

- H-optimus-0 与 H-optimus-1 分别对照 UNI2-h 的同种子初始权重。
- Phikon-v2 对照 UNI 的同种子初始权重。
- 种子 45、46、47 分别一一对应。

只要构建顺序、随机数消费和实现保持一致，整个 H/C/B state dict 应完全相等。如果不相等，应修复模型头创建顺序、随机数设置或多余随机操作，不能只说“种子相同即可”。不同输入维数之间不要求完整 state dict 相等，因为输入层形状和随机数消费不同。

## 八、冻结的全视野空间预测头

### 8.1 数学结构

对中心点 i：

```text
h_i = GELU(W_H x_i + b_H)
center_i = W_C h_i + b_C
delta_i = sum_j a_ij × (h_j - h_i)
spatial_i = W_B delta_i
y_i = center_i + spatial_i
```

其中：

- `x_i` 是选定的单 patch 特征。
- H 将原生特征维数映射到 256。
- C 输出 30 条通路的中心预测。
- B 输出空间残差，`bias=False`，权重从全零开始。
- dropout=0.3 只施加于训练阶段中心 H→C 路径；推理使用 `eval()`，不使用 dropout。
- 不对输入特征做额外 z-score、标准化或 L2 归一化。
- 图的图像余弦相似度内部可以对特征做 L2 归一化，但这只用于计算边权，不能覆盖训练输入。

### 8.2 固定图参数

| 参数 | 固定值 |
|---|---:|
| hops | 1 |
| radius_in_native_steps | 2.0 |
| max_neighbors | 12 |
| distance_sigma | 0.5 |
| use_image_similarity | true |
| image_temperature | 0.7716396069760084 |
| self_raw_weight | 0.5 |
| directed | true |
| normalization_epsilon | 1e-12 |

图只能在同一切片、同一数据划分内连接。必须按既有 native grid 坐标构建有向一跳邻接，禁止跨患者、跨切片、跨 train/validation/external 连接。

图的候选邻居集合、半径和公式固定，但边权中的图像余弦相似度依赖当前编码器特征。因此每个新编码器必须重新计算自己的图权重，不能复制 UNI2-h、UNI 或 Virchow2 的已存边权。编码器变化导致图权重变化是预期现象，不是额外实验因素。

孤立点没有邻居时，空间项为零，只保留 C 的中心预测。

1. `model_manifest.json` 明确三个 repo、revision、许可提示、loader、output_mode、feature_dim、归一化。
2. 边缘标记的方形测试图经全视野预处理后四边信息均保留。
3. 非方形输入明确失败。
4. Phikon-v2 不发生重复 rescale/normalize。
5. 严格离线零样本测试得到 H-optimus-0/1 `[1,1536]`、Phikon-v2 `[1,1024]`，全部 finite float32。该项只能在服务器权重就绪后标记通过。

### 17.2 缓存与数据

6. 缓存没有 `COMPLETE`、revision 不同、预处理不同、维数不同或身份不同，均不得复用。
7. train/internal/XZY 身份和点位数与合同一致，无重复、缺失或交叉。
8. 标签 z-score 仅来自训练集冻结参数。
9. 30 条通路名称和顺序在标签、预测、内部和外部之间完全一致。

### 17.3 头部、图和训练

10. H-optimus-0/1 与 UNI2-h、Phikon-v2 与 UNI 的同维同种子初始 H/C/B state dict 精确相等。
11. 小批次前向/反向中 H、C、B 均有有限梯度并按实际 Adam 配置更新；编码器无梯度且不进入 optimizer。
12. B 初始权重全零、无 bias；H/C bias 配置正确；激活为 exact GELU。
13. 图只连同切片同划分；有向、半径、邻居上限、距离核、图像温度、自权重和归一化符合冻结值。
14. 每个编码器使用自己的特征重算图像相似边权；不能复用基线边权。
15. 孤立点退化为中心 C 预测。
16. 合成验证历史覆盖 formal epoch 1、41 轮才开始累计早停、patience=20、主指标和平分指标逻辑。
17. 实际 optimizer 记录显示 lr=1e-4、weight_decay=0、B 倍率=1.0，且训练 float32/AMP=false/TF32=false。

### 17.4 任务与报告

18. 9 个新任务覆盖 3 模型×3 种子且无重复；缺失/失败任务在汇总中显式暴露。
19. 外部评估只有在相应正式 checkpoint 存在后才允许运行，并记录其来源。
20. `baseline_reference_manifest.json` 只读取已接纳的 9 个全视野空间基线任务。
21. 报告分列内部和外部、两种 PCC、误差、单种子、均值和样本标准差。
22. `run.ps1` 默认只检查输入；下载、特征提取、训练和外部评估必须显式选择。
23. 本地单元测试不要求网络、服务器权重或 GPU；真实严格加载单独在服务器预检阶段执行。
24. 回传含 `model_weights.json` 和 `feature_caches.json`，不含权重与特征缓存二进制。
25. 包内生成 `audit_summary.md`，按项目 `pfmval-audit` 日常最小自检记录已通过项、未核实项和证据路径。

## 十八、关键风险与结论措辞

最终报告必须同时说明：

1. H-optimus-0/1 的 0.5 µm/px 原生期望与当前 patch 物理尺度关系尚未核实。
2. 不同模型使用各自官方归一化，因此比较对象是完整编码器输入管线。
3. 特征维数不同导致头部参数量不同；本批没有通过附加投影强行统一。
4. 图像特征参与图边权，替换编码器也会改变图权重；这是空间头定义的一部分。
5. H-optimus-1 有人工访问审批和更严格非商业许可。
6. 外部 XZY 只有一个历史患者，只用于模型固定后的参考评估。
7. 所有新模型共享 UNI2-h 路线上冻结的 `spatial-11`，因此结果不代表各编码器独立调优后的性能上限。
8. H-optimus 选择官方二维 final embedding，Phikon-v2 选择官方 CLS；这保证接口明确，但不证明其他输出聚合永远更差。
9. 模型实际严格加载、依赖兼容、GPU 显存和提取吞吐目前均为待服务器核验事项。

允许的结论形式：

> 在固定 MPP2/group_2 数据、完整方形 patch→224 全视野输入、模型原生归一化、冻结 spatial-11 空间头和种子 45/46/47 的条件下，模型 A 在内部验证的预定主指标上相对基线 B 呈现何种配对差异；外部 XZY 的两种 PCC 与误差指标分别如何。该结果反映共享 Phase2 配方下的替换表现，不等同于模型各自最佳调优性能或跨患者普遍优越性。

禁止的结论形式：

- “某模型全面优于所有模型”，如果不同指标排名不一致。
- “证明泛化更强”，如果证据只有单一外部患者 XZY。
- “纯编码器能力差异”，因为原生归一化、特征维数和图像相似边权也随编码器变化。
- “三个模型都完成”，如果 H-optimus-1 因访问限制未运行。

## 十九、给实现者的执行顺序

1. 从 `experiments/_template/` 建立新实验包，记录复制来源和代码版本。
2. 从第一批模型替换包与修复后全视野包复制必要代码到新包内部，不从上级目录运行时导入。
3. 建立三个模型的固定 manifest 与基线只读 manifest。
4. 实现三种明确的 `output_mode`，先完成无权重的适配器单元测试。
5. 实现模型原生归一化与统一全视野几何测试。
6. 实现缓存元数据、完成标记和严格复用检查。
7. 接入冻结 H/C/B、图、训练和选模逻辑；完成同维初始化精确比对。
8. 完成任务覆盖、外部评估门控、合并分析与路径登记。
9. 完成本地零训练测试和 `audit_summary.md`。
10. 向用户交付代码包文件夹和服务器操作卡；不得代替用户启动下载或训练。

服务器实际运行时：先逐模型申请/下载并做严格离线形状测试，再准备特征，然后运行 9 个正式训练，最后才运行外部 XZY 和本地合并分析。
