# 服务器零训练 Gitee 往返试点检查方案（2026-08-10）

> 状态：`pending_user_review`
>
> 适用范围：仅供后续其它 agent 在**用户另行指派**时执行一次 W006 或更高编号的新实验零训练试点。
>
> 本文件角色：二合一总方案——前半用于审核边界，后半用于执行检查。

## 1. 审核边界

### 1.1 目标

验证后续新实验在**不训练、不导入结果、不接纳证据**的前提下，是否可以完成一次仅通过 Gitee 的最小往返闭包：

- 本地冻结 `source_commit`；
- 通过 allowlisted diagnostic 核验服务器治理目录、持久 `W###` 目录、外置 run/return/diagnostic 根和解释器存在性；
- 生成一次最小 return 闭包；
- 回收到本地后核对 remote tree 闭包、原始 CSV/TXT force-add、生效的 `return_profile_v1` 合同与终态记录。

### 1.2 适用范围

- 仅适用于 **W006 或更高永久编号** 的新实验。
- **W005 已为 `abandoned_reserved`**，不得复用。
- 仅适用于 **Gitee-only** 传输。
- 仅适用于 **零训练（no training）** 试点。

### 1.3 前置条件

执行前必须同时满足：

1. `project_state/schemas/return_profile_v1.schema.json` 已进入受管状态。
2. `configs/server_paths.yaml` 是唯一机器配置事实源。
3. `server_config` 与 `server_governance_config` 仅视作 retired pointer，不得作为当前机器配置事实源。
4. 已有最终部署方案，且用户明确批准准备进入实验绑定。
5. 已创建对应的 `project_state/implementation_plans/W###-<工作树名>_实施方案.md`，并经用户二次明确批准。
6. 本地已经冻结本次试点使用的 `source_commit`，且当前试点不附带训练、调参、结果导入或 accepted evidence 决策。

### 1.4 禁止事项

本试点**明确禁止**：

- 正式训练、smoke、single-batch forward 之外的任何训练性执行；
- SSH、SCP、HTTP remote command、Remote Tunnel；
- result import、result accept、accepted metrics 结论更新；
- 复用 W005；
- 未经用户批准直接创建/绑定新 W### 工作树；
- 直接把旧 `config.server.yaml` 或 legacy checkout 当作当前机器配置事实源。

### 1.5 判定口径

#### GO

以下条件全部满足：

- 路径核验通过；
- 解释器核验通过；
- allowlisted diagnostic 成功返回；
- 最小 return 闭包完整；
- 被忽略的必传 CSV/TXT 已精确 force-add；
- remote tree 闭包、terminal receipt、started receipt、resolved argv/config 对账通过；
- 无新增 FAIL。

#### CONDITIONAL GO

没有新增 FAIL，但存在需要用户知情后再推进的 WARN，例如：

- supporting/diagnostic 补充材料不足；
- 诊断根目录需要后续现场创建批准；
- 旧历史 WARN 仍存在但与本次试点无直接冲突。

#### NO-GO

出现任一情况即为 NO-GO：

- 服务器解释器或关键目录不存在；
- 诊断请求越界；
- return 闭包缺失原始 CSV/TXT、terminal receipt 或 remote tree 闭包；
- 实际使用了非 Gitee 通道；
- 未经批准创建/绑定 W###；
- 任何步骤实质进入训练、结果导入或 accepted evidence 更新。

## 2. 执行清单

### 2.1 本地准备

1. 确认本次任务已有最终部署方案，且用户批准进入绑定准备。
2. 创建并获得批准：`project_state/implementation_plans/W006-<工作树名>_实施方案.md`。
3. 冻结本次试点使用的 `source_commit`。
4. 记录计划使用的：
   - `workspace_id`
   - `source_commit`
   - `diagnostic_id`
   - `return_revision`
5. 再次确认当前规则：
   - `configs/server_paths.yaml`
   - `project_state/plans/server_maintenance.md`
   - `AGENTS.md`

### 2.2 Gitee 诊断请求

1. 只使用 allowlisted diagnostic command id。
2. 请求中不得包含任意 shell 文本、训练参数、result import 指令。
3. 请求必须绑定：
   - 精确 `source_commit`
   - 固定 source/return branch
   - command id
4. 诊断分支必须位于 `automation/diagnostics/*`。

### 2.3 服务器 allowlisted diagnostic

至少核验以下对象：

- `server_governance_checkout`
- `server_experiment_worktrees`
- `server_experiment_runs`
- `server_result_returns`
- `server_diagnostics`
- `server_runtime_bundles`
- `C:\Users\AIPatho1\pfmval_env\Scripts\python.exe`

核验内容至少包含：

- 是否存在；
- 是否是正确类型（directory / git_worktree / file）；
- 是否位于已登记边界内；
- 是否没有把 retired pointer 误当作当前机器配置事实源。

### 2.4 最小 return 闭包

零训练试点的最小 return 必须至少包含：

- terminal receipt
- started receipt
- resolved argv/config
- 至少一个原始训练 CSV
- 至少一个原始训练 TXT
- remote tree 闭包校验结果

要求：

- 被 `.gitignore` 命中的必传 CSV/TXT 必须精确 force-add；
- 使用 `return_profile_v1` 约束核对成功/失败/incomplete 的终态矩阵；
- 不生成训练结果结论，不导入 Registry。

### 2.5 本地回收核验

回传到本地后，逐项核对：

1. `source_commit` 是否与试点前冻结值一致；
2. `workspace_id` 是否为 W006 或更高；
3. terminal / started receipt 是否成对存在；
4. CSV/TXT 是否进入 staged/remote tree；
5. remote tree 闭包是否与 manifest 对账一致；
6. 本次试点是否引入新增 FAIL；
7. 是否误触发了训练、结果导入或 evidence accept。

### 2.6 失败分流与补证

如果失败，按下面分流记录：

- **路径失败**：记录缺失 path id、类型错误、边界错误。
- **解释器失败**：记录路径、版本、依赖缺失。
- **传输失败**：记录 branch/ref、expected/staged/remote tree 差异。
- **return 闭包失败**：记录缺失 artifact kind、receipt 或 force-add 差异。
- **越界失败**：记录触发的非 Gitee 通道、训练行为或未经批准的绑定动作。

失败后只形成补证或修订建议，不得在同一任务中顺手转入训练。
