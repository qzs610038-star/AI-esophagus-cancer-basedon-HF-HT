# UNI2-h 服务器离线加载排障记录_20260703

> **问题**：服务器在 `HF_HUB_OFFLINE=1` 且 HF 缓存目录有 `pytorch_model.bin`（2.7 GB）的情况下，`timm.create_model("hf-hub:MahmoodLab/UNI2-h")` 仍然联网超时报错。
> **根因**：`timm` 的 `hf-hub:` 加载路径在 huggingface_hub 某些版本下**即使 `HF_HUB_OFFLINE=1`，仍会先发 HEAD 请求**检查远程文件，而且缓存文件**不在标准 `blobs/` 下**（Windows symlink 问题导致文件直存 `snapshots/`），致使 huggingface_hub 的缓存查找逻辑失败 → `LocalEntryNotFoundError`。
> **最终方案**：在 `uni2h/uni2h_utils.py` 中添加本地缓存 fallback——直接通过 `refs/main` → snapshot hash → 定位 `pytorch_model.bin`，绕过 timm 的 HF hub 加载链路。

## 解决方案：`_find_local_uni2h_ckpt` 三重查找策略

修改位置：`uni2h/uni2h_utils.py` 的 `_find_local_uni2h_ckpt()` 和新增 `_load_uni2h_from_local()`。

### 代码结构

```
load_uni2h_backbone()
  ├─ _find_local_uni2h_ckpt()     ← 优先
  │    ├─ 策略1: 显式 cache_dir 参数
  │    ├─ 策略2: refs/main → snapshot hash → 直构路径  ← 最可靠
  │    └─ 策略3: rglob 兜底
  ├─ 找到 → _load_uni2h_from_local()   ← 本地构造+加载权重
  └─ 没找到 → _load_uni2h_from_hfhub() ← HF hub fallback
```

### `_load_uni2h_from_local()` 的关键细节

```python
from timm.models.vision_transformer import VisionTransformer

# 直接构造模型（不依赖 HF hub）
model = VisionTransformer(
    img_size=224, patch_size=14, depth=24, num_heads=24,
    embed_dim=1536, mlp_ratio=2.66667 * 2, init_values=1e-5,
    num_classes=0, no_embed_class=True, global_pool="",
    mlp_layer=timm.layers.SwiGLUPacked,
    act_layer=torch.nn.SiLU,
    reg_tokens=8, dynamic_img_size=True,
)

# 加载 state_dict（去掉 head/pre_logits 键）
state = torch.load(ckpt_path, map_location="cpu", weights_only=True)
state = {k: v for k, v in state.items()
         if not k.startswith("head.") and not k.startswith("pre_logits.")}
model.load_state_dict(state, strict=False)
```

### 加载优先级

1. **显式 `local_cache_dir`**（参数传入路径，适用于已知路径）
2. **自动搜索 `HF_HOME` 缓存**（适用于标准 HF 缓存布局）
3. **HF Hub 在线加载**（仅当以上都失败时，需要网络）

## 最终根因确认（2026-07-03）

历经 3 次迭代修复后成功。确切根因是多个因素的组合：

1. **`Path.read_text(encoding="utf-8")` vs `open()+read()`**：服务器 Windows Python 环境下，`Path.read_text` 可能因底层编码检测或文件系统特性异常，且被 `except Exception: pass` 静默吞掉
2. **`Path.exists()` vs `os.path.isfile()`**：某些 Windows 路径（含特殊字符/深度嵌套）下 `Path.exists()` 行为与 `os.path.isfile()` 不一致
3. **`except Exception: pass` 陷阱**：原始代码的 silent `pass` 导致所有诊断信息丢失，无法区分是"路径不存在"还是"读取异常"还是"文件不存在"

**经验教训**：`except: pass` 永远是 bug 的温床。至少应 `print(f"[WARN] ... : {e}")` 输出异常信息。

### 最终代码关键点

```python
# ✅ 使用 os.path 替代 Path 进行关键文件检查
refs_main = os.path.join(model_cache, "refs", "main")
if os.path.isfile(refs_main):
    try:
        with open(refs_main, "r") as f:          # ✅ open()+read() 而非 Path.read_text()
            snapshot_hash = f.read().strip()
        if snapshot_hash:
            ckpt = os.path.join(model_cache, "snapshots", snapshot_hash, "pytorch_model.bin")
            if os.path.isfile(ckpt):               # ✅ os.path.isfile 而非 Path.exists()
                return ckpt
    except Exception as e:
        print(f"[WARN] 读取 refs/main 失败: {e}")  # ✅ 输出异常而非静默 pass
```

| # | 问题 | 说明 | 缓解 |
|---|------|------|------|
| 1 | **`HF_HUB_OFFLINE=1` 下 timm 仍发 HEAD 请求** | 某些 huggingface_hub 版本的 `local_files_only=True` 实现不彻底 | 使用本地 fallback 完全绕过 timm 的 HF hub 路径 |
| 2 | **Windows HF 缓存结构可能不标准** | Windows 无/有 symlink 权限时，文件可能直存在 `snapshots/` 而非 `blobs/` | 策略 2（refs/main → hash）不依赖 blob 结构 |
| 3 | **VisionTransformer 构造参数在不同 timm 版本可能不同** | 新 timm 版本可能改参数字段名 | 先检查服务器 timm 版本 `python -c "import timm; print(timm.__version__)"` |
| 4 | **HF 缓存可能被其他工具清空** | Docker/conda 清理可能误删 | 定期用 `folder_inventory_cache.txt` 核对 |
| 5 | **UNI2-h 需要 HF token（gated model）** | 如果缓存不完整需要重新下载，需要 token | 设置 `HF_TOKEN` 环境变量或通过 `HF_ENDPOINT=https://hf-mirror.com` 镜像下载 |
