## 一、方案定位与关联关系

本方案是[《空间转录组评价指标与论文对比建议》](./空间转录组评价指标与论文对比建议_20260823.md)的执行配套方案。两份文档职责不同：

| 文档 | 职责 | 不承担的职责 |
|---|---|---|
| 《空间转录组评价指标与论文对比建议》 | 说明文献常用指标、项目现有指标、可比性边界和新增指标优先级 | 不授权实际复算，不产生新数值 |
| 本复算部署方案 | 固化首批指标定义、输入证据、执行步骤、质量门、报告结构和登记流程 | 不批准训练，不改变任何实验状态 |
| 最终复算报告 | 呈递实际复算数值、配对效应、置信区间、限制与论文表述建议 | 用户审查前不是正式长期结论 |

首批复算只落实建议文档中的P0指标，并补充一项空间支持指标：

1. patient-balanced mean per-pathway PCC（患者等权逐通路皮尔逊相关）；
2. patient-balanced mean per-pathway CCC（患者等权逐通路一致性相关）；
3. patient-balanced z-RMSE / `NRMSE_sigma_train`（患者等权标准化误差）；
4. per-pathway SSIM（逐通路空间结构相似性）；
5. 配对效应量、改善比例、中位数、IQR和95%置信区间；
6. Moran's I保持度，作为空间支持指标，不替代SSIM。

MI、JS-Div、AUC、HVP/SVP子集、ARI/NMI、临床C-index和效率指标不进入本批，避免第一次复算同时引入过多自由度。它们保留为后续独立方案。

- 重新生成MPP标签、划分、z-score参数或manifest；

- 写`experiments/experiment_registry.json`、导入结果或把复算值标成accepted；
- 推送到Gitee或GitHub；

## 四、首批指标协议

### 4.1 聚合层级

内部六患者统一使用以下顺序，禁止把pooled、逐通路、逐患者口径混写：

1. 先在每名患者、每条通路内跨spot计算指标；
2. 再对患者等权汇总，得到每条通路的patient-balanced指标；
3. 最后跨30条通路报告均值、中位数、IQR、最小值、最大值和有效通路数。

PCC在患者层使用Fisher-z变换：将相关系数裁剪到`[-0.999999, 0.999999]`，对6名患者的`atanh(r)`等权平均后再`tanh`还原。CCC、RMSE和SSIM直接对患者等权平均。

XZY只有一名患者，只报告逐通路和跨通路分布；XZY空间块区间不得称为“跨患者置信区间”。

### 4.2 PCC与CCC

- PCC（Pearson Correlation Coefficient，皮尔逊相关系数）评价线性趋势；少于3个有效spot或真值/预测方差为0时记为`NA`并报告原因，不以0代替。
- CCC（Concordance Correlation Coefficient，一致性相关系数）按Lin定义计算：同时惩罚均值偏移和尺度偏差。
- 同时保留legacy pooled PCC，只用于回算一致性和衔接既有accepted结果；不得把它与patient-balanced mean per-pathway PCC混为同一指标。

### 4.3 z-RMSE与NRMSE

- `z-RMSE`在冻结z-score标签空间计算，按患者、通路等权聚合。
- `NRMSE_sigma_train = raw RMSE / sigma_train`，其中每条通路的`sigma_train`只能读取冻结训练期z-score参数；它与z-RMSE理论上应一致，用作raw/z字段和反标准化链的双向核验。
- 不使用XZY自身极差、均值、标准差或分位数作为归一化分母。
- 继续报告z-MAE、raw MAE和mean pathway raw R²作为负向护栏，避免只选择有利指标。

### 4.4 SSIM

SSIM（Structural Similarity Index Measure，结构相似性指数）只对具有可靠坐标的实验计算，并固定以下选择规则：

1. 真值与预测必须使用完全相同的spot集合、坐标、组织掩膜和空间范围；
2. 只依据坐标占用率选择实现，不查看模型结果：规则网格占用率达到90%时使用标准网格SSIM；否则使用显式掩膜的局部SSIM，并命名为`masked_SSIM_PFMval`；
3. 窗口大小固定为7；不足以形成有效窗口的患者×通路单元记为`NA`；
4. 数值范围使用训练期每条通路的冻结尺度，不用XZY真值动态缩放；
5. 不插值填补缺失组织区域，不把大面积背景纳入平均；
6. 报告网格方式、占用率、有效窗口数和`data_range`来源。

若无法复现Wang/HEtoSGEBench完全相同的空间预处理，报告必须写明“内部统一协议SSIM，不能与Wang表格数值直接比较”。

### 4.5 Moran's I保持度

复用已有本地空间分析的rook邻接构图，计算：

- `truth_moran_i`；
- `prediction_moran_i`；
- `moran_delta = prediction - truth`；
- `abs_moran_delta`；
- 残差Moran's I。

Moran's I用于说明空间自相关是否被保留；单独较高的预测Moran's I不代表预测准确，必须与PCC、CCC、SSIM及残差空间聚集共同解释。

### 4.6 配对效应与不确定性

所有基线对照统一报告：

- 每条通路`ΔPCC、ΔCCC、Δz-RMSE、ΔSSIM`；
- Δ的均值、中位数、IQR、改善通路数和改善比例；
- 内部六患者采用患者级配对Bootstrap，外部XZY采用空间块配对Bootstrap；
- 固定随机种子`20260823`，Bootstrap重复`10000`次；
- 区间为percentile 95% CI；同时输出原始重采样单位数和有效重复数。

PCC、CCC和SSIM越大越好；RMSE、`abs_moran_delta`越小越好。报告中的Δ方向统一转换成“正值表示候选模型优于对照”，避免同一张表正负含义相反。

30条通路的改善比例和IQR是描述性证据。不得把“跨通路Bootstrap”冒充跨患者泛化区间；只有患者级或空间块配对区间进入主报告。

## 五、一键复算流程

### SVC1 启动与版本核验（Startup and Version Check）

1. 完整读取`AGENTS.md`、本方案、关联指标建议、`pfmval-governance`和`pfmval-audit`技能；
2. 调用agentmemory recall；失败只记WARN；
3. 记录分支、HEAD、dirty状态和Python解释器；
4. 运行`python deploy/pfmval_ops.py agent start-check --strict`；必须`FAIL=0`；
5. 确认全程无服务器访问、训练、工作树注册和Registry写入。

### LBC2 本地主分支基线提交（Local Baseline Commit）

1. 按第2.3节处理`.qmd/`本地缓存；
2. 打印全部非忽略文件、大小和状态；
3. 排除密钥、大模型、原始患者数据等异常后，创建一次本地基线提交；
4. 不push，记录基线commit；
5. 基线提交完成后再次确认工作区干净，才允许开始写代码或运行复算。

### IER3 输入证据解析（Input Evidence Resolution）

1. 从Registry读取限定实验的状态和result id；
2. 解析第3.2节输入；
3. 生成`input_inventory.json`，只记录路径、大小、mtime、行列数、列族、患者和通路覆盖，不计算哈希；
4. 验证配对键和受保护输入只读性；
5. 为每个实验写入`accepted / accepted_smoke / rejected_excluded`标签。

### MPS4 指标协议固化（Metric Protocol Specification）

1. 在读取任何新指标数值前写出`metric_protocol.json`；
2. 固化公式、聚合顺序、SSIM分支规则、邻接图、Bootstrap单位、随机种子、重复次数和NA规则；
3. 协议文件生成后不得因结果“不好看”而修改；如实现错误必须生成新revision并在报告中披露原因；
4. 分析代码统一放在`scripts/explorations/mpp2_metric_recalculation_v001/`。

### MRC5 指标复算（Metric Recalculation）

1. 先计算基线legacy指标并与Registry accepted值回传对齐；
2. 计算全部可用实验的逐患者×逐通路长表；
3. 生成patient-balanced与XZY逐通路汇总；
4. 对有坐标实验计算SSIM和Moran's I；
5. Huber缺标识部分明确输出`not_computable_missing_identifier`，不得按行序补齐；
6. Ridge只用于验证既有PCC/CCC函数是否能复现其候选线索，不进入报告主结果。

### PEA6 配对效应分析（Paired Effect Analysis）

至少完成以下对照：

- S0 frozen smoke vs S1 LoRA r=8 smoke；
- S0 frozen smoke vs LoRA dropout10 smoke；
- accepted MSE baseline vs accepted Huber；
- W007 FBR vs RCC、HCR、CPGCR。

对照必须具有同一数据split、通路集合和可验证配对单位。对Huber只做逐通路指标差值及其描述性分布，不生成伪空间区间。

### QAV7 质量保证与验证（Quality Assurance and Validation）

只实施最小必要测试：

1. 完美预测：PCC、CCC、SSIM为1，RMSE为0；
2. 仿射偏移：PCC保持接近1，但CCC下降；
3. 患者等权：spot数量不同不改变患者权重；
4. 键顺序打乱：按键配对结果不变，缺键必须失败；
5. 固定种子：Bootstrap重复运行结果一致。

运行后还必须验证：

- baseline XZY legacy pooled PCC回算到accepted `0.6549`附近；
- baseline XZY pooled z-MSE回算到`0.6620768`附近；
- baseline XZY z-MAE回算到`0.6191227`附近；
- baseline raw MAE回算到`1176.2114`附近；
- mean pathway raw R²回算到`-0.0880`附近；
- 指标长表每个实验、split、患者和30条通路的覆盖与NA原因闭合；
- 输入文件运行前后大小和mtime不变；
- 严格门禁仍为`FAIL=0`。

数值一致性容差必须在代码中显式设置并写入报告；不得仅凭四舍五入字符串判断。

### RRD8 复算报告交付（Recalculation Report Delivery）

1. 生成中间输出到`experiments/explorations/mpp2_metric_recalculation_v001/`；
2. 把最终中文报告写入`01_指南与解读/分析报告/MPP2首批评价指标复算报告_<执行日期>.md`；
3. 报告链接本方案和指标建议方案；
4. 报告显式区分accepted输入、accepted-smoke输入、rejected校验线索和新计算的pending-review指标；
5. 报告中同时呈现有利指标、R²/误差护栏、无增益或不利结果，不选择性展示；
6. 生成本地报告提交，记录commit但不push；
7. 在对话中呈递报告链接、主要数值、限制和唯一审计判定`CONDITIONAL GO`或`NO-GO`，随后停止等待用户审查。

### URG9 用户审查门（User Review Gate）

用户审查可以：

- 批准报告原文；
- 要求修订表述、图表或指标口径；
- 拒绝将部分候选指标纳入长期文档。

未收到明确“审查通过并批准登记”前：

- 不写experiment Registry或current state；
- 不把报告称为active长期文档；
- 不声称新指标已成为论文正式成绩。

### DRC10 文档登记闭环（Document Registration Closure）

该步骤只登记最终复算报告，默认`authority=reference、lifecycle=active`；不会把复算数值升级为accepted实验结果。

当前文档登记CLI会对文档范围计算content SHA-256并重写`project_state/document_registry.json`，随后`state sync --with-docs`还会刷新`PROJECT_GUIDE.md`和派生状态。启用原因是Registry schema要求内容指纹；必要性是让以后对话能从active文档路由到最终报告；负面影响是会扫描多份文档、修改Registry和派生文件并推进状态revision。

因此，呈递报告时必须把上述原因、必要性和负面影响再次申报给用户，并取得单独明确批准后，才能运行：

```powershell
python deploy/pfmval_ops.py docs scan --write
```

然后从Registry解析该报告的真实`doc_id`，不得手工编造，再运行：

```powershell
python deploy/pfmval_ops.py docs set-lifecycle `
  --doc-id <真实doc_id> `
  --lifecycle active

python deploy/pfmval_ops.py state sync --with-docs

python deploy/pfmval_ops.py agent start-check --strict
```

登记后必须验证：

- 报告路径在document Registry中唯一；
- `lifecycle=active`且`authority=reference`；
- `PROJECT_GUIDE.md`能够路由到该报告；
- strict为`FAIL=0`；
- experiment Registry没有任何变化；
- 登记改动已形成单独本地提交，未push。
