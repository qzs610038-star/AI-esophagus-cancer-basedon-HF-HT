## 1. 原则

1. 只把现网 **FAIL 降为 WARN**，或对不存在/prunable 的 worktree 路径停止 `resolve(strict=True)`。不新增 CLI task，不新增实施方案字段，不改结果导入链。
2. 结果准确性与防误改保持 HARD：`experiment_registry` / 受保护资产 / repair / `server_paths` 哈希、Gitee-only、正式批准、`source_commit`、关键结果 SHA、`result import` 原子事务、inbox 一致性、**当前 checkout** 的工作树身份。
3. 训练入口 `deploy/run_experiment.ps1` 仍调用 `agent start-check --strict`。
4. `--task diagnostic` 已对文档新鲜度宽松；本轮不改其行为目标。
5. 代码实施（获批后）在本地 `main`：不涉及服务器、训练或结果 import。按 `DIR-20260801-008`，动手前先把非忽略工作区提交到本地 Git，不自动 push。获批执行时用 `state record-directive` 追加一条门禁降级指令。
6. 任一步把「当前 checkout 身份错误」「关键结果被改仍可导入」「无批准可派发正式训练」放成 WARN 或跳过，必须停止。

## 2. 问题与证据

统一 `agent start-check --strict` 把知识层账本和实验身份绑在同一条硬门上。2026-08-21 的 CA2 / 超参数只读审计因此停在与 MPP2 训练代码无关的两项 FAIL 上（随后治理提交已使当时 HEAD 的 `--strict` 恢复 FAIL=0；问题机制仍在，随时会再挡只读审计）：

| 现网 FAIL | 机制 | 是否保护结果字节 |
|---|---|---|
| `document_registry_sha256` 与 `current_state.source_hashes` 不一致 | 知识层 Registry 语义哈希为 HARD；改文档登记后未立刻 `state sync` 即阻断 | 否。`experiment_registry_sha256` 当时一致 |
| `git worktree list` 中 prunable Temp 路径 `Path.resolve(strict=True)` | 全量扫描每条 worktree；目录不存在即 `[WinError 2]` | 否。持久 W### 仍在 |

同一次 `--strict` 里，学习指南 freshness、Dashboard、README、`PROJECT_GUIDE.md` 过期、`CURRENT_STATE.md` 内容过期已经是 WARN。本轮不重复「删除」这些 WARN。

`DIR-20260807-001` 已要求 Evidence/Governance HARD、Knowledge/Navigation SOFT。`experiment_dashboard_sha256`、`experiment_progress_sha256`、`workflow_catalog_sha256` 已在 `SOFT_SOURCE_HASH_KEYS`。独留 `document_registry_sha256` 和多数 active normative 文档 content SHA 为 FAIL，与该指令不一致。

## 4. 波次 A（必做）

第一次「批准执行」且未点名 B 时，只做本节。顺序固定，完成一条再做下一条。

### A1 `document_registry_sha256` HARD → SOFT

**现网锚点**

- `scripts/pfmval_state.py`：`SOFT_SOURCE_HASH_KEYS`（约第 45–49 行）目前不含 `document_registry_sha256`
- 同文件 `validate_state()` 约第 3098–3109 行：不在 SOFT 集合中的 `source_hashes` 失配走 `report.fail`

**改动**

将 `document_registry_sha256` 加入 `SOFT_SOURCE_HASH_KEYS`。失配改为 WARN。不改 `compute_source_hashes()` 的语义字段集合。

**保持 HARD**

`experiment_registry_sha256`、`asset_registry_sha256`、`workspace_registry_sha256`、`mpp_path_index_sha256`、`server_paths_sha256`、`mpp_repair_registry_sha256`。

**测试**

- 保留 `test_document_registry_semantic_hash_ignores_derived_view_bookkeeping` 等指纹稳定性断言
- 新增：改文档 Registry 语义内容但不 `state sync` 时，`--strict` 对该键只有 WARN、没有 FAIL；同时 `experiment_registry_sha256` 失配仍 FAIL（可对照 `test_generated_view_hash_drift_is_soft_but_registry_drift_remains_hard`）

### A2 失效 / prunable worktree 不得 FAIL

**现网锚点**

- `scripts/pfmval_state.py` `validate_governance_v3_state()` 约第 2650–2684 行
- 对 `git worktree list --porcelain` 的每条 `path`，以及登记绝对路径，使用 `Path.resolve(strict=True)`
- 登记目录不存在时，`strict=True` 直接抛 `[WinError 2]`，被收成 `workflow governance v3 state invalid` FAIL

**改动**

- 列举 worktree 时：路径不存在或 git 标为 prunable 则跳过该条，不得抛未捕获的文件系统错误
- 登记绝对路径：目录不存在时不要 `resolve(strict=True)`
- `tombstoned` 现有逻辑保留（路径仍应不存在、分支引用仍检查）

**测试**

新增：`git worktree list` 含一条已删除 Temp 路径时，`validate_state()` / `validate_governance_v3_state()` 不得因此 FAIL；可 WARN。

### A3 非当前 checkout 的其它 W### 身份漂移 → WARN

**现网锚点**

- 同函数对每个带绝对路径的 local host：分支不等于登记分支 → `ValueError` → FAIL
- 非 `governance_maintenance` 且 HEAD 不是登记 `current_source_commit` 的后代 → FAIL（`task=knowledge` 时该项已 WARN）
- 登记路径不在 `git worktree list` 匹配结果中 → FAIL

**改动**

仍遍历 `workspace_registry.json`。HARD 身份失败只对 **`root` 解析后等于该登记绝对路径** 的那一棵工作树生效。其它绝对路径工作树的同类问题改为 `report.warn`。

这是放松现有全量 HARD，不新增 `--workspace` 参数或 `--task development`。

当前 checkout 若分支错误、HEAD 不是登记提交后代、或根本不是登记的 git worktree，仍 FAIL。

**测试**

- 保留 `test_knowledge_task_downgrades_only_workspace_head_drift`
- 新增：当前 `root` 身份错误仍 FAIL
- 新增：另一棵已登记绝对路径工作树分支/HEAD 不对，只 WARN

### A4 active normative 文档 content SHA FAIL → WARN

**现网锚点**

- `scripts/pfmval_state.py` `validate_state()` 约第 2950–2957 行
- `_is_soft_content_hash_document()` 已覆盖 `AGENTS.md`、`.agents/skills/`、`.claude/skills/` 及 `skill:` / `skill_adapter:` scope
- 其它 `lifecycle=active` 且 `authority=normative` 的文件（例如 `project_state/plans/mpp_training.md`）content SHA 失配仍 FAIL

**改动**

该 content SHA 失配改为 `report.warn`。不删除 `content_sha256` 字段，不改 document Registry schema。

**必须改的现有测试**

- `tests/test_pfmval_state.py` `test_diagnostic_gate_allows_document_freshness_drift_but_keeps_transport_hard`：full gate 对该 stale 计划文改为断言 WARN，不再断言 FAIL；diagnostic 对 `server_transport.mode=ssh` 仍须 FAIL
- 同文件 `test_skill_content_hash_drift_is_soft_and_excluded_from_hard_registry_fingerprint`：末尾 `mpp_training.md` 编辑后改为断言 WARN，不再断言 FAIL

### A5 `document_registry` 落后超过 1 个 `state_revision` FAIL → WARN

**现网锚点**

- `validate_state()` 约第 2943–2945 行：`revision_delta > 1` → FAIL
- `validate_diagnostic_state()` 对同一条件已是 WARN

**改动**

全量门与 diagnostic 对齐：改为 WARN。

**测试**

新增或改最小夹具：`current_state.state_revision` 比 document Registry 超前超过 1 时，`validate_state()` 只有 WARN、没有该项 FAIL。
