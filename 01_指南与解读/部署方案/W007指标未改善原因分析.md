## 先说结论边界

现在还不能直接说“就是 z-score 导致的”。

更准确的说法是：

- z-score **可能解释**为什么 external XZY 的相关性仍为正，但 raw R² 全部为负；
- 但四个实验使用同一套 z-score，所以它**不能单独解释**为什么 RCC、HCR、CPGCR 相对 FBR 几乎都没有提升；
- 要先排除“代码虽然运行成功，但新增模块实际上只产生了很小修正”以及“实验设计把新增信号压住了”这两类问题。

因此按下面顺序分析，不一开始就重做 z-score。

## 当前已经确认的现象

1. 四臂使用相同的 internal-val 和 XZY 样本，样本编号与真实值一致。
2. 指标已从原始预测重新计算，与回传结果一致，因此目前没有发现指标登记错误。
3. RCC 在内部验证略好；HCR 的 external PCC 略好；CPGCR 的 external z-MSE、raw MAE 和 raw R²略好。
4. 所有优势都很小，没有一个实验臂在主要指标上形成一致领先。
5. Internal mean pathway raw R²约为 `0.635–0.637`，external XZY 则为 `-0.088–-0.080`；external pooled PCC 仍约为 `0.654–0.656`。
6. 当前只有一个随机种子 `seed=42`，不能判断这些微小差异是否能稳定重复。

## 分析顺序总览

```text
先查代码是否真的产生了不同预测
        ↓
再查训练设置是否把新增作用压得太小
        ↓
单独检查 z-score 是否造成目标和指标错位
        ↓
最后判断是否主要是数据差异或模型能力上限
```

## CR-1 代码检查（Code Review）

### 要回答的问题

RCC、HCR、CPGCR 虽然使用了不同损失，最终是否真的学出了明显不同于 FBR 的预测？

### 为什么先查这里

如果新增残差很接近零，或者三个训练臂的预测几乎相同，那么后面讨论 z-score、数据分布和模型上限都不是首要问题。首要问题会是：新增模块在代码上存在，但实际作用太弱。

### 具体查看什么

1. 逐样本比较每个训练臂与 FBR 的预测差值。
2. 统计残差分支输出的平均幅度，并与 FBR 原预测幅度比较。
3. 分通路检查：是否只有少数通路发生变化，其余通路几乎完全沿用 FBR。
4. 核对三个训练臂加载的初始化、batch 顺序和 checkpoint 是否符合原方案。
5. 核对 HCR、CPGCR 的对比损失是否真正参与总损失和梯度更新，而不只是写入训练日志。

### 如何判断

- 如果预测差异几乎为零：优先归为代码连接或残差强度问题。
- 如果预测已有明显差异，但验证指标不变：继续检查实验设计和训练目标。
- 如果三个训练臂彼此也非常相似：说明新增的 HCR/CPGCR 机制没有形成可辨别作用。

## ER-2 实验设计检查（Experiment Review）

### 要回答的问题

代码即使正常，当前训练设置是否把新增机制的作用压得太小，或者让模型过早停止？

### 当前值得优先核对的线索

1. 三个训练臂都从零残差开始，学习率为 `0.0001`。
2. 对比损失权重固定为 `0.1`。
3. checkpoint 只按 internal patient-balanced z-MSE 选择。
4. 早停要求改善超过 `0.0001` 才算有效改善。
5. HCR 最终选择 epoch 1；CPGCR 选择 epoch 5。

训练日志还显示：

- HCR 的对比损失从约 `1.25` 降到 `0.29`，但 internal z-MSE 没有同步改善；
- CPGCR 的对比损失只从约 `3.33` 缓慢降到 `3.30`，变化很小；
- RCC 的训练误差持续下降，但验证误差在 epoch 5 后变差，出现过拟合迹象。

### 具体查看什么

1. 总损失中绝对误差与对比损失各自贡献多大。
2. 对比损失下降时，预测误差是否同步下降。
3. 残差幅度是否随 epoch 增大，但验证效果反而变差。
4. `min_delta=0.0001` 是否让非常小的改善无法进入最佳 checkpoint。
5. patient-balanced batch 是否因为重复采样小患者而改变了实际训练分布。

### 如何判断

- 对比损失下降、回归指标不动：更像“学会了对齐表示，但没有帮助最终预测”。
- 训练误差持续下降、验证误差变差：更像过拟合或数据量不足。
- 残差一直很小：更像学习率、初始化或损失连接导致新增模块作用不足。

## ZR-3 z-score 检查（Z-score Review）

### 要回答的问题

训练集拟合的 z-score 是否让模型优化的目标，与我们最后关心的 raw MAE 和 raw R²不完全一致？它是否又放大了 XZY 与训练患者之间的尺度差异？

### 为什么 z-score 确实值得怀疑

模型在 external XZY 上仍有约 `0.655` 的 PCC，说明大致的高低排序并非完全失效；但 raw R²为负，说明绝对数值和波动范围没有预测好。这种组合可能来自均值偏移、尺度偏移或预测振幅被压缩，而这些都可能和 z-score 的训练集均值、标准差有关。

### 为什么暂时不能把问题都归给 z-score

四个实验臂使用相同的 train-only z-score、相同逆变换方法和相同 XZY。因此 z-score 更容易解释“四臂共同存在的 external 校准问题”，不能直接解释“为什么三个新方法没有明显超过 FBR”。

### 具体查看什么

本阶段只读取现有受保护参数和预测，不重新生成 z-score：

1. 逐通路比较训练患者、internal-val 和 XZY 的真实值均值与标准差。
2. 检查 XZY 中是否有大量通路整体偏离训练均值。
3. 比较每条通路的预测振幅与真实振幅，判断是否普遍被压缩。
4. 检查 raw R²较差的通路是否集中在训练标准差特别大或特别小的通路。
5. 分开计算“只修正均值”“只修正尺度”后，raw R²理论上能恢复多少；这只作为诊断，不用于选择模型或修改 XZY 结果。

### 如何判断

- 如果 PCC 尚可，但预测斜率明显小于 1、均值或尺度偏移明显：z-score/校准问题可能是 external 失败的重要原因。
- 如果 z-score 分布正常，而三个残差臂仍与 FBR 高度重合：主要原因不在 z-score。
- 如果只有少数通路受标准差影响严重：应归为逐通路尺度问题，不应笼统否定整套 z-score。

## DM-4 数据与模型检查（Data and Model Review）

### 要回答的问题

如果代码、训练设置和 z-score 都没有明显异常，是否是图像特征本身无法提供更多通路信息，或者 XZY 与训练患者差异过大？

### 具体查看什么

1. 哪些通路在 internal-val 能预测、到 XZY 后明显失效。
2. 失败是否集中在某类通路，而不是全部 30 条通路。
3. 六名内部患者之间的波动，是否已经接近 XZY 的失败方向。
4. 图像特征对患者身份的区分是否强于对通路状态的区分。
5. 新增对比学习是否只学到了患者、染色或组织背景差异。

### 如何判断

- internal 良好、XZY 普遍下降：更像跨患者或批次差异。
- internal 和 external 都无新增收益：更像现有 UNI2-h 特征或残差结构的能力上限。
- 只有个别通路失败：更像通路标签噪声或图像不可识别性，而不是整个模型失败。

## UA-5 不确定性检查（Uncertainty Assessment）

### 要回答的问题

现在看到的细小差异，到底是真实差异，还是单次训练波动？

### 当前边界

- 只有 `seed=42`。
- Internal 的 1,078 个 spot 来自 6 名患者，spot 之间并不完全独立。
- External 的 1,039 个 spot 全来自 XZY 一名患者，不能把它们当成 1,039 次独立重复。

因此当前只能说“数值改善很小且方向混合”，还不能严格说某个臂在统计上显著优于或不优于另一个臂。多随机种子或新实验不属于本文件授权范围，需要用户另行决定。

## 最终如何归因

完成以上只读分析后，按下面规则归类：

| 看到的主要现象 | 更可能的问题位置 |
|---|---|
| 三个训练臂与 FBR 的预测几乎相同 | 代码连接、残差幅度或优化强度 |
| 对比损失明显下降，但预测指标不变 | 对比目标与最终回归任务脱节 |
| 训练误差下降，internal-val 变差 | 过拟合或训练设置不合适 |
| Internal 尚可，XZY 的 PCC 尚可但 raw R²很差 | z-score、绝对尺度校准或患者分布偏移 |
| Internal 和 XZY 都没有新增收益 | 图像表征或模型结构达到上限 |
| 仅少数通路严重失败 | 通路尺度、标签噪声或图像不可识别性 |
| 各种差异都非常小且不稳定 | 单随机种子不足，暂时无法可靠归因 |

## 建议的分析顺序与停止点

### Code Difference Check（代码差异检查，CDC-1）

先用现有预测和 checkpoint 检查残差输出及四臂预测差异。若发现实现连接错误，停止后续科学归因，先向用户报告代码问题；本文件不授权修复。

### Training Behavior Check（训练行为检查，TBC-2）

读取三份 training history，对照绝对损失、对比损失、验证误差和最佳 epoch。若新增机制确实工作但不能改善回归，再进入 z-score 检查。

### Z-score Effect Check（z-score 影响检查，ZEC-3）

只使用已有 z-score 参数和预测表检查均值、尺度、预测振幅及逐通路 R²。不重建任何受保护资产，也不根据 XZY 调参。

### Data and Representation Check（数据与表征检查，DRC-4）

比较逐患者、逐通路和 internal—external 变化，判断主要问题是患者分布差异还是图像表征上限。

### User Review（用户审核，UR-5）

向用户提交一份简短归因表，分别标记：已排除、较可能、仍不确定。用户确认后，才讨论是否需要代码修复、新的分析脚本或新实验。
