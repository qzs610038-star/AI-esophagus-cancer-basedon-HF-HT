## 已核验事实

1. 现行划分是 **六名患者内空间 block 约 10% 作 internal-val**（`block_size=672`），不是患者留出。当前 manifest 对每名患者仅暴露一套坐标且没有 `slice_id` 字段；这支持“manifest 中未区分第二切片”，但不能单独证明物理采集层面一人一张切片。train 与 val 的患者集合相同；当前清单中同一 `patient+patch_stem` 不跨 split；XZY 不在 manifest，checkpoint 冻结后评估一次。
2. 选模 / 早停信号是与训练共享患者身份的 internal `val_loss`。内部 val 的标签 z 接近 (0,1)；230/230 个 val block 与同患者 train block 四邻接。因此 **internal PCC≈0.80 不是新患者难度的无偏代理**。
3. z-score **只在 train 拟合**（`fit_split=train`，排除 internal_val / external_test / embargo）。val 与 XZY 只 transform。没有发现用 val/XZY 拟合。不必回到 CA2 修代码。
4. 冻结基线（accepted）：内部 PCC≈0.797，外部 XZY PCC≈0.655，raw R²≈−0.088。PCC 对仿射不敏感，R² 敏感；XZY 在 train-z 尺度上有均值偏移与预测振幅压缩，故 **PCC 尚可与 raw R² 为负可以同时成立**。
5. Huber / W007 / Ridge 在同一划分与同一 z-score 下没有把外部 PCC 带离约 0.65。Ridge 保持 `rejected`。
6. 当前源码、accepted 结果和可用资产未显示 CA2 六类一般性硬 Bug。训练绑定 split 的逐行内容尚未在本机恢复，因此 CA2-1 / CA2-3 对实际历史运行是条件性通过。现阶段可以停止把 0.65 **首先**归因于一般性硬 Bug，但不能写成所有历史输入已经逐行完整复核。

点名条件（讨论任何新协议时必须保留）：

- 当前跟踪的 `split_manifest.csv` sha256 `1f7d1345…` ≠ 训练绑定 `babfa2b1…`。逻辑计数一致，但不是 Huber job 逐字节同一文件。
- in-repo 旧 `labels/train` CSV 仍有冲突重复 barcode；accepted 训练绑定 repaired staging。**不得把旧 CSV 当训练输入**。
- **不能**把内部 0.80 与外部 0.65 的差写成已定量的「划分 X%、z-score Y%、生物学 Z%」。
- “一名患者对应一张物理捕获切片”尚缺采集元数据确认；讨论划分时只使用 manifest 可证明的患者、坐标和 split 关系。

## 待讨论选项（只列代价，不锁定）

| 选项 | 可能换来什么 | 代价与边界 |
|---|---|---|
| 患者留出 val（6 人留 1） | 内部指标更接近「从未见过的患者」；选模不再看同切片邻域 | 训练少 1 人；单次 holdout 方差大；须按折重拟合 train-only z-score；**不保证** XZY PCC 上升 |
| 训练患者重复 LOPO / nested CV，XZY 仍一次性 | 内部估计更稳，仍不读 XZY 选折 | 计算与合同更重；XZY 只评一次 |
| 维持空间划分，只改报告口径 | 最低代价：停止把 0.80 写成可推广到新患者 | **不改变**选模乐观性；PCC 外部数字不会因此自己变好 |
| 新划分下按折重拟合 train-only z-score | 新 train 集合有自己的 (0,1) | 新资产；旧 manifest / params **只读保留**，不得覆盖 |
| 患者内相对标准化 / 排名 | 可能减弱跨患者位置项对 R² 的打击 | **改任务定义**（相对活性，不再是当前绝对 ssGSEA 尺度） |

历史 V3bis（MPP-3，5 训练 + ZHZ 整患者 val）仅为 `historical` 形态对照，不得锁定本讨论的协议。
