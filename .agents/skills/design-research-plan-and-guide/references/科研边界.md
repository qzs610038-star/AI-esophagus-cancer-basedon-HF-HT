# PFMval 科研方案边界

本文件只补充 PFMval 项目特有约束；冲突时以根目录 `AGENTS.md`、当前用户指令和机器可读事实源为准。

## 事实读取

1. 依次读取 `CURRENT_STATE.md`、`project_state/current_state.json`、active 文档 Registry 和相关 experiment Registry。
2. accepted、diagnostic、explore、historical 和 proposed 明确区分。
3. Phase 2 与 Phase 3 的目标和选择标签不得相互污染；下游价值可以作为动机，不能自动成为上游选择依据。

## 实验与资产

- 新实验遵守部署方案、实施方案、W### 绑定和正式训练批准的分阶段门禁。
- 监督预处理只在训练折拟合，再应用于验证和外部测试。
- ssGSEA、标准划分、z-score、manifest 和 embargo 等受保护资产不得因方案写作而重建。
- 外部测试集不得参与 checkpoint、超参数或实验臂选择；若用户批准逐臂查看，必须先冻结合同并写明反馈禁区。

## 工程与传输

- 服务器往返仅使用 active Gitee 通道。
- 方案可描述一键控制、故障即停和日志回传，但不因此获得服务器或训练权限。
- 普通日志与预测文件按当前治理要求登记；不得自行扩大哈希治理范围。

## 文档生命周期

- 新部署讨论稿只写入 `01_指南与解读/部署方案/`。
- 学习指南与部署方案建立明确关联和版本边界。
- 部署方案批准后仍需实施方案再次批准，才可绑定工作树或填写实验代码。
- 本 Skill 不自动修改 Registry、状态、实验、结果或团队稳定结论文档。
