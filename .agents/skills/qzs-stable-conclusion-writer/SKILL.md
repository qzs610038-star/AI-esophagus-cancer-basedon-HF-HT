# qzs 本机稳定结论文档撰写

## 必读与准备

1. 依次读取 `AGENTS.md`、`CURRENT_STATE.md`、`project_state/current_state.json`、`experiments/experiment_registry.json`。
2. 读取 `references/evidence-and-approval-boundaries.md`、`references/experiment-section-schema.md` 与 `references/pseudocode-and-visualization-policy.md`。
3. 运行 `python deploy/pfmval_ops.py agent start-check --strict`。
4. 对将修改的 qzs 维护文档和图表目录建立仓库外临时快照。

## 强制边界

- 写入正式 qzs 文档前，先向用户展示准备写入的概要；只有用户明确批准后才能落盘。
- 禁止覆写、删除、替换、重排或移动既有维护内容。新实验追加新章节；修正旧内容时，在需修正位置紧邻追加独立补充说明并保留原文。
- 不把探索、计划、未导入结果或历史参考写成稳定结论。已完成但效果不满足使用条件的实验可以作为负面结果记录，但必须明确边界。
- 外部测试集不得用于模型选择或继续调参；文档必须说明内部选择与外部描述性评估的边界。
- 不用“门控”“合同”或 `NO-GO` 代替解释。写明满足/未满足的具体条件、实际数值以及因此采取的下一步。

## 执行流程

1. 从 Registry、结果封装、正式关闭记录和实现代码中收集证据。完成日期以成功结果生成时间或正式科学结论关闭日期为准，涉及时区要换算并说明。
2. 区分五类状态：稳定结论、已完成负面结果、待补充工作、本地探索、历史参考。
3. 形成待审概要，至少列出方案、比较条件、结果、结论、下一步、完成日期、证据、代码和图表计划。
4. 等待用户显式批准。未批准时不修改正式文档或汇总索引。
5. 获批后使用 `assets/stable-conclusion-template.md` 追加章节。每项实验固定包含可折叠的 1/2/3/4 四部分。
6. 为每项实验链接真实实现代码，并提供中文逻辑与英文伪代码。英文变量名、函数名和参数名必须与真实代码匹配。
7. 将正文引用的全部图表复制或绘制到 `团队项目进度与结论/qzs/可视化图表/`。已有权威图复制后校验哈希；新图同时保存 PNG 与 SVG，并记录数据来源。
8. 如允许使用子代理，可把独立绘图任务交给经济型模型；主代理必须复核数值、视觉尺度、中文标注、结论边界和文件位置。
9. 向对应汇总板块追加索引，不复制整份 qzs 文档。
10. 运行 `scripts/validate_qzs_document.py`、`scripts/validate_visual_assets.py` 和 `scripts/validate_append_only.py`。修正任务必须使用 `--correction-mode`。
11. 再次运行项目严格检查，报告验证结果和证据限制。

## 每项实验必须回答

- 采用了什么方案，唯一变化是什么。
- 与什么对照比较，哪些条件必须满足。
- 实际结果和关键数值是什么。
- 满足或未满足哪些条件，因此下一步做了什么。
- 实验何时完成，日期依据是什么。
- 哪些代码实现了该方案，关键逻辑是什么。
- 哪些图表支持结论，图表数据来自哪里。
- 当前结论不能被扩展到哪些范围。

## 追加修正规则

修正旧结论时，在旧内容紧邻位置追加：

```html
<details>
<summary><strong>补充说明（YYYY-MM-DD，已获用户审核）</strong></summary>

- 原内容保留原因：……
- 需要补充或修正的事项：……
- 新证据与代码：……
- 更新后的理解与适用边界：……

</details>
```

不得借修正之名重写整个章节。若无法在原位置安全追加，停止并请求用户决定。
