# 证据、审核与结论边界

## 事实源优先级

1. `experiments/experiment_registry.json` 中已接纳的结果状态。
2. 不可变 job/result 封装及正式科学结论关闭记录。
3. 与对应 commit 一致的真实实现代码。
4. 派生报告和可视化数据。
5. 历史文档只作背景，不覆盖当前事实源。

## 完成日期

- 有成功 `result.json` 时，使用其 `created_at`，并按用户时区换算。
- 配对实验以正式科学结论关闭为完成边界时，使用关闭记录日期并明确说明。
- 任务名中的日期只用于辅助定位，不能替代结果时间。
- 仅有文件修改时间时标为“日期待核验”，不得据此声明完成。

## 用户审核

- 用户明确说“写入”“审核通过”“可以正式维护”才视为批准。
- 用户只同意总体方向时，仍需展示具体写入概要。
- 写入范围变化、结论变化或新增推断需要重新审核。
- 修正旧内容同样需要审核，且只能追加补充说明。

## 结论分级

- 稳定结论：证据已接纳，可作为后续比较依据。
- 已完成负面结果：实验完成，但没有满足继续采用的具体条件。
- 待补充：证据或图表缺失，不形成正式判断。
- 本地探索：不进入长期稳定结论，只能明确标注为探索材料。
- 历史参考：不得作为当前执行依据。
