## 优先学习与关键决策

### KDP-1：四臂应作为一个原子 result set，还是拆成四个实验结果？

- 为什么关键：当前 W007 是一个预注册四臂实验，但现有 Registry 每个 experiment 只承载一个 result。
- 可选方案与代价：原子 result set 保留预注册因果结构，需新增最小 schema/CLI；拆成四个实验可复用旧 importer，但会改写既有实验身份和审批语义。
- 建议默认值：新增 W007 兼容的原子 `result_set_v1` 导入，不拆实验。
- 用户需要确认：是否接受“一个 experiment、一个 result set、四个 arm result”的表示。
- 优先学习：[指南 KDP-1](../学习指南/W007四臂结果导入治理缺口修复学习指南_20260815.md#kdp-1)

### KDP-2：如何保留 segmented source（分段源码）绑定？

- 为什么关键：FBR、RCC、HCR/CPGCR 分别绑定 `7be042a`、`24a87c7`、`0f81be3`，不能强行改成同一 source commit。
- 可选方案与代价：按 arm/attempt 保留 source 最忠实；统一到最终 source 会破坏可追溯性。
- 建议默认值：result set 顶层记录 protocol，arm 层记录 attempt/job/source/return commit。
- 用户需要确认：是否接受逐 arm source 作为正式 provenance（来源链）。
- 优先学习：[指南 KDP-2](../学习指南/W007四臂结果导入治理缺口修复学习指南_20260815.md#kdp-2)

### KDP-3：缺少普通 stdout/stderr 文本时采用豁免还是补充回传？

- 为什么关键：现行 return profile 要求 raw CSV/TXT；W007 成功训练臂有 `training_history.csv`，但没有普通训练 TXT，FBR 本身没有训练历史。
- 可选方案与代价：补充回传证据更完整但需要服务器侧另行取回；使用 `DIR-20260811-005` 的 supporting-log 豁免最省动作，但必须明确其是否覆盖 formal result import。
- 建议默认值：优先只读补充回传；若文件已不存在，再由用户显式批准一次 W007 专项豁免，绝不伪造日志。
- 用户需要确认：补充回传优先，还是专项豁免优先。
- 优先学习：[指南 KDP-3](../学习指南/W007四臂结果导入治理缺口修复学习指南_20260815.md#kdp-3)

## 1. 一句话治理问题

如何在不修改四个原始 return commit、不扭曲 attempt/source 绑定、不手改 Registry 的前提下，将 W007 四臂批次作为一个可审核、可回滚、可重复验证的正式结果集导入。

## 2. 当前事实与证据边界

- `main` 中 W007 是 `planned/preflight/run_limit=1`；W007 分支最终状态是 `running/formal/run_limit=3`，但尚未 import。
- 四个 return commit 已存在并完成 inventory、size 与 Git tree 只读核验。
- 原始预测独立重算与回传指标一致，最大绝对差 `5.37e-8`。
- 当前 CLI 在 `result import` 首步要求 `result.json`；W007 包只有 `return_manifest.json`。
- 当前 importer 还要求 `automation/jobs/<job_id>/job.json`、单一 source/job 绑定和单一 result_id。
- 本部署方案不把 pending_review 结果提升为 accepted。

## 3. 目标与非目标

目标：恢复 W007 append-only 治理历史；校验四个 immutable return refs；原子导入四臂 result set；生成 Registry 派生视图；保留 quarantine 和原始日志位置。

非目标：不训练、不重跑、不根据 XZY 选配置、不改原始回传文件、不把四臂拆成事后定义的新实验、不合并 return commits 到 main、不扩大普通文件哈希治理。

## 4. 最小数据模型

拟新增 `result_set_v1`：

- 顶层：`result_set_id`、experiment、workspace、protocol revision、approval、critical contract、四臂冻结顺序、evidence status。
- arm 层：`arm_id`、attempt/job、source commit、return ref/commit、artifact inventory、internal/external metrics、checkpoint 说明。
- FBR 明确为 `baseline_replay/no_training`；RCC/HCR/CPGCR 明确为 `formal_training/seed_42`。
- 只有四臂全部通过硬验证，才允许一次事务写入；任一失败则全部停留 quarantine。

## 5. 原始证据合同

- 原始 return commit 永不改写，importer 只读。
- 必须存在每臂 internal-val 与 XZY 的逐样本预测和 metrics。
- 训练臂必须存在 `training_history.csv`；普通 TXT 的缺口按 KDP-3 处理。
- FBR 必须存在 `checkpoint.json` 和 `baseline_replay_check.json`，且 replay contract PASS。
- 样本 ID、truth、split、患者数和行数必须跨臂一致。
- 指标从预测表重算并与 JSON 比较；不新增对普通预测/日志文件的 SHA-256 治理。

## 5.1 数据泄漏与外部评估边界

- importer 必须原样保留 `external_may_select=false`：XZY 不能选择 checkpoint、改变配置、触发重跑或生成新的 experiment revision。
- internal-val 是唯一选择来源；XZY 只作为四臂配置与 checkpoint 冻结后的外部 benchmark。
- 导入和报告阶段只读取既有结果，不重新拟合 z-score、模型或任何校准参数。

## 6. 实施步骤与停止点

### Return Profile Contract（回传画像合同，RPC-1）

定义 W007 四臂 result-set schema、arm/source 绑定和 FBR 免训练合同。若无法表达 segmented source，停止。

### Historical State Replay（历史状态重放，HSR-2）

通过 append-only CLI 从 W007 分支重放 directive、approval、attempt 和 workspace/experiment 生命周期，不直接覆盖 main JSON。若 CLI 无法幂等重放，停止并补接口测试。

### Quarantine Set Validation（隔离结果集验证，QSV-3）

从四个精确 Gitee ref/commit 读取包，验证 Git tree、库存、大小、样本闭包、指标重算和 arm/source/attempt 绑定。禁止 checkout/merge 到 main。

### Atomic Result-Set Import（原子结果集导入，ARSI-4）

用事务一次写入一个 result set 和四个 arm result；写前生成 preview，写后生成 Registry/Dashboard/Current State。任一文件写入失败则完整回滚。

### Pending Conclusion Projection（待审结论投影，PCP-5）

先登记 `pending_review` 比较；只有用户审核结论后，才允许 CLI 把 evidence status 转为 accepted，并投影“无明确优胜者”的结论。

### Minimal Governance Verification（最小治理验证，MGV-6）

只覆盖：旧单结果 importer 回归、W007 四臂 happy path、缺一臂/错 source/错样本/错指标/重复导入、事务回滚、Gitee ref 精确核验。禁止运行模型训练测试。

## 8. 风险与回退

- 风险：将 W007 历史分支状态整体覆盖 main。控制：只允许 append-only replay，不允许文件级覆盖。
- 风险：四次单结果 import 相互 supersede。控制：只允许一个 atomic result set。
- 风险：把 XZY 优势写成选择依据。控制：schema 固定 `external_may_select=false`。
- 风险：为兼容 importer 改写原始 return。控制：原始目录只读，转换产物另存并标明 generated。
- 回退：事务失败恢复写入前 Registry/state；quarantine 和原始 commits 不变。
