## 摘要

本专项审计针对用户对基础模型替换消融部署方案中指出的事实——“*默认 `crop_pct=0.875`，对正方形图片保留的是中心约 87.5% 边长、76.56% 面积*”进行深度溯源。核心审计结论如下：

1. **历史时间节点**：该现象确切始于 **2026 年 7 月 3 日**。在解决服务器离线无法从 HuggingFace Hub 加载 UNI2-h 权重的工程排障中，团队在 [`uni2h/uni2h_utils.py`](../uni2h/uni2h_utils.py) 中重构了纯本地加载函数 `_load_uni2h_from_local()`，其调用的 `timm.data.create_transform` 未传 `crop_pct` 参数，由此在整个项目的历史特征提取链中永久固化了该裁剪逻辑。
2. **操作原因**：工程排障焦点集中在“离线权重加载与键值兼容”，视觉预处理借用了 `timm` 的通用图像分类默认设置，产生了对通用 CV 库缺省行为的认知盲区，脱离了 MahmoodLab 官方推荐的无裁剪缩放代码。
3. **双刃剑效应**：
   - **潜在优势**：客观上起到了滤除 WSI 边界扫描伪影、增大相邻 patch 物理防泄漏间隙、贴合通用 ViT 尺度先验的副作用红利；
   - **严重危害**：人为破坏了空间转录组（Visium HD）真值标签与图像感受野的物理对应关系（丢失了切块周边 23.44% 的转录微环境信息），截断了边缘拓扑结构，并在多模型横向比较中制造了视野混杂门槛。

## 二、 底层操作根源与代码实证

### 1. 真实代码切片
在 [`uni2h/uni2h_utils.py:119-128`](../uni2h/uni2h_utils.py#L119-L128) 中，离线加载分支代码如下：

```python
# UNI2-h 预处理（已知常量，不依赖 pretrained_cfg）
from timm.data import IMAGENET_DEFAULT_MEAN, IMAGENET_DEFAULT_STD
transform = create_transform(
    input_size=timm_kwargs["img_size"],    # 传入 224
    is_training=False,
    mean=IMAGENET_DEFAULT_MEAN,
    std=IMAGENET_DEFAULT_STD,
    interpolation="bicubic",
    # 缺失的关键参数: crop_pct=1.0
)
return model, transform
```

### 2. timm 内部预处理机制剖析
`timm` 的 `create_transform` 是专为 ImageNet 分类训练与测试设计的工厂函数。当 `is_training=False` 且未提供预训练配置时：
- 内部自动读取缺省常量：`DEFAULT_CROP_PCT = 0.875`；
- 计算短边放大尺寸：
  $$\text{Scale Size} = \lfloor \frac{\text{input\_size}}{\text{crop\_pct}} \rfloor = \lfloor \frac{224}{0.875} \rfloor = 256$$
- 生成的处理对象为 torchvision 的 `Compose` 容器：
  1. `Resize(size=256, interpolation=BICUBIC, antialias=True)`
  2. `CenterCrop(size=(224, 224))`
  3. `MaybeToTensor()`
  4. `Normalize(mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225))`

### 3. 与官方原生规范的偏离对比
MahmoodLab 官方在开源仓库（[`mahmoodlab/UNI`](https://github.com/mahmoodlab/UNI)）与模型卡中，对 UNI/UNI2-h 推荐的原生评估代码非常明确：

```python
# 官方推荐的原生预处理方式（无放大、无裁剪、完整保留 100% 视野）
from torchvision import transforms

transform = transforms.Compose([
    transforms.Resize(224), # 直接缩放到 224
    transforms.ToTensor(),
    transforms.Normalize(mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225)),
])
```
**偏离事实**：本项目因为将加载封装委托给了 `timm` 的通用构造器，未补齐 `crop_pct=1.0`，导致最终执行的行为偏离了官方原生示例。

## 三、 当初为什么会这样操作？（归因分析）

1. **工程排障环境下的“聚焦偏差”**：
   - 2026-07-03 的服务器排障记录显示，当时的紧急矛盾是“服务器因联网限制无法提取特征，全组训练进度受阻”。
   - 调试力量全部倾注于修复 Windows 路径分隔符、`refs/main` 快照哈希解析、PyTorch 权重字典键过滤（剔除 `head.` 和 `pre_logits.`）。
   - 只要能够运行并通过 `forward_features` 提取出 `[1536]` 维度的张量，功能就被认定为“交付完成”，而未对黑盒函数返回的 `transform` 具体算子进行单步诊断。
2. **对通用 CV 库封装行为的“经验惯性盲区”**：
   - 在 PyTorch / timm 生态中，开发者习惯性认为：既然输入的切块已经是 $224 \times 224$，传入 `input_size=224` 就理应维持原样。
   - 鲜有开发者会在未专门通读源码的情况下意识到 `timm` 会隐式对尺寸完全匹配的正方形图像重新放大到 256 再切除边缘。
3. **从在线加载切为离线构造时的配置脱落**：
   - 在线加载时，`timm` 通常通过 `resolve_data_config(model.pretrained_cfg)` 自动获取模型专属配置；
   - 切换为离线手动实例化 `VisionTransformer(...)` 后，`pretrained_cfg` 丢失，开发者手动声明常量时遗漏了裁剪控制参数。

## 四、 这种操作（CenterCrop 0.875）客观上存在什么优势？

在数字病理分析的局部场景下，这种裁切边缘的操作在客观上带来了一定的“副作用红利”：

1. **滤除切片边缘伪影（Edge Artifact Suppression）**：
   - 数字病理切片在制作与扫描切块时，patch 四周边界极易出现：
     - 机械切割造成的组织拖尾或挤压撕裂；
     - 显微镜物镜边缘场曲、像散造成的散焦与模糊；
     - 组织贴片气泡与封片剂边缘暗角。
   - 中心裁剪（保留中心 76.56% 面积）自动将周围 12.5% 的边界像素废弃，天然起到了“形态学边缘去噪”的效果，使得送入 ViT 的像素质量相对纯净。
2. **扩大点位间的物理安全防线（Safety Margin Expansion）**：
   - 在空间转录组密集点位阵列中，如果相邻 spot 距离接近，全视野图像切块的边缘往往会有微弱重叠。
   - 裁掉边缘组织相当于收缩了模型对每个 spot 的有效感知半径，在空间几何上拉开了相邻点位之间的物理距离，间接减轻了点位间图像特征的假性自相关（Moran's I 虚高）。
3. **符合通用 ViT 的尺度纹理先验**：
   - 基础模型预训练过程中大量使用了 RandomResizedCrop 等缩放增强。测试期的适当放大与中心切块，使细胞核直径、染色质微结构的像素尺度与 ImageNet 经典流派在分布上更协调。

## 五、 这种操作带来了什么可能的危害？（空间转录组科研硬伤）

在 **Visium HD 空间转录组通路活性预测** 这一高度严谨的量化任务中，该操作引发了实质性的科学与工程缺陷：

### 1. 测序真值与形态视野的严重空间失配（Spatial Misalignment）
- **核心逻辑冲突**：
  - 空间转录组点位的真值标签（30 条通路 ssGSEA 评分）是通过捕获**该点位所覆盖的完整组织区域**内的 mRNA 分子测序计算得到的；
  - 深度学习模型的训练目标，是在图像形态特征与这 30 个基因表达值之间建立函数映射：$f(\text{Image}) \to Y_{\text{pathway}}$；
  - 裁剪操作将切块四周 **23.44% 的组织从图像中彻底抹除**，但预测目标仍然包含这 23.44% 区域所贡献的全部转录活性！
- **科学后果**：
  - 若某些关键生物反应（如局部浸润淋巴细胞、肿瘤出芽边缘）恰好富集在切块的四周，输入模型的图像上根本没有这些形态证据，模型却被强行逼迫拟合其标签，直接向系统引入了无法解释的**标签对齐噪声**。这极有可能是外部独立测试集（XZY）上预测相关性产生瓶颈的隐性诱因之一。

### 2. 关键微环境拓扑结构的截断（Topological Truncation）
- 肿瘤微环境（TME）的典型生物学结构（如三级淋巴结构 TLS、肿瘤侵袭前沿、间质屏障、血管新生条带）通常呈现跨越式的空间延伸。
- 切除四周边缘直接打破了组织连续性，使模型丧失了对边界连续微环境的感知能力。

### 3. 多模型消融基准的“隐性混杂偏差”（Benchmark Confounder）
- 若后续对比其他未受 timm 该默认影响的基础模型（如原生使用 `crop_pct=1.0` 的 Virchow2 或其他官方接口模型）：
  - 新模型将天然拥有比旧 UNI2-h 多出 $30.6\%$ 的视野信息（$100\% / 76.56\% \approx 1.306$）；
  - 审稿人若质疑“新模型的性能提升仅仅是因为看到了更广阔的组织边缘，而非编码器更强大”，我们将无法通过实验数据予以反驳。

## 六、 应对策略与建议

根据项目当前资产现状与研究边界，提出如下分步应对规范：

1. **当前 Phase 2 消融（必须严格对齐旧基线）**：
   - 鉴于第一轮 accepted 的 UNI2-h 历史基线已全面基于 76.56% 视野运行，且重提取重训练整个系统代价巨大；
   - **消融主协议执行严格对称性约束**：新引入的 UNI、Virchow2 在特征提取代码中，**必须显式复现完全相同的变换流水线**（`Resize(256) -> CenterCrop(224) -> Normalize`）；
   - 保证三者在同等局部视野（76.56% 面积）下进行公平单点性能消融，在论文中如实公开这一已知几何设定。
2. **未来 Phase 3 与最终系统升级（全视野重提取与对比）**：
   - 在后续独立开展的“空间分辨率与视野完整性消融”或 Phase 3 空间残差深度重构中，重构全视野提取链（`Resize((224, 224))`、`crop_pct=1.0`）；
   - 单独设置对照组，验证“从 76.56% 恢复至 100% 完整视野”对 30 通路预测带来的纯几何收益。

### 补充二、代码、历史原因及原报告说明的复核

#### 1. 当前执行链确实裁剪，且新消融已显式继承

[旧加载器](../uni2h/uni2h_utils.py)中，`load_uni2h_backbone`（基础模型加载函数）找到本地权重后进入 `_load_uni2h_from_local`（本地加载分支）；其 `create_transform`（预处理构造函数）仅指定输入尺寸、评估模式、双三次插值和通道归一化。[提取脚本](../extract_uni2h_mpp.py)确实对 PNG 应用该变换，再用 `forward_features`（提取中间表征）取第 0 个 CLS token（整块汇总向量）。

本次在本机 Python 环境直接构造同参数预处理，实际输出为：

```text
timm 1.0.26
Resize(size=256, interpolation=bicubic, antialias=True)
CenterCrop(size=(224, 224))
MaybeToTensor()
Normalize(ImageNet mean/std)
```

这一检查不加载模型权重，也未提取真实样本特征。[timm 1.0.26 评估变换源码](https://github.com/huggingface/pytorch-image-models/blob/v1.0.26/timm/data/transforms_factory.py)及[默认常量](https://github.com/huggingface/pytorch-image-models/blob/v1.0.26/timm/data/constants.py)与结果一致。[现有服务器回传检查](../experiments/server_load_check_20260905/deliverables/20260905_234330_776_3c6878e3/report.json)登记了 timm 1.0.27，并包含 224×224 图像样本；它是历史环境/样本证据，不是每批缓存的预处理证明。

[新消融代码的 SharedTransform（共同变换）](../experiments/phase2_backbone_point_ablation_20260914/src/transforms.py)已显式实现相同的双三次缩放、中心裁剪、张量转换与归一化。[部署方案第 4.3 节](../01_指南与解读/部署方案/Phase2_UNI与Virchow2基础模型替换消融_完整部署方案_20260914.md)还要求核对旧缓存实际来源，若旧链不同则对齐实际旧链。因此当前属于“已识别并冻结的历史协议”，后续实现不能再由各模型默认值任意决定视野。

#### 3. 原报告三项“优势”需要收窄

- **去伪影：缺乏本项目证据。** 数字切块边缘不等于组织的物理切割边缘、扫描视场边缘或气泡边界。除非能证明低质量像素集中在每块外圈，否则中心裁剪同样可能删去正常且有用的组织。不能把整张切片上的伪影规律直接套到规则网格的每个 patch。
- **防泄漏：只可能改变图像覆盖，不能作为划分保障。** 裁剪不改变患者身份、点位坐标、标签聚合区域及真实组织自相关。相邻图像仍可能重叠，相关性降低也不等于泄漏已经消除；恢复全视野时应按完整图像支持域核查既有空间隔离，而不是依赖裁剪带来的间隙。
- **更贴预训练尺度：方向未知。** 训练期裁剪增强不自动证明测试期固定中心放大更优。Virchow2 的作者模型卡甚至专门将裁剪缩放增强替换为扩展上下文平移；这支持“尺度策略值得研究”，不支持通用裁剪天然适合所有病理模型。[Virchow2 模型卡](https://huggingface.co/paige-ai/Virchow2)、[作者论文](https://arxiv.org/abs/2408.00738)。

### 补充三、究竟丢了什么：几何面积、标签支持域与有效尺度

#### 1. 面积比例明确，信息损失比例不明确

对于边长为 L 的正方形原图，当前链名义上保留中心 0.875L × 0.875L；每侧削去 **0.0625L，即每侧 6.25%**，不是每侧 12.5%。若原图是 224×224，对应中心约 196×196，每侧约 14 个原图像素；丢失名义面积 23.4375%。双三次插值在边界附近有有限像素混合，故该比例描述几何覆盖，不能解读为精确的信息隔绝边界。

恢复全图相对当前视野多约 30.61% 的**几何面积**，不等于多 30.61% 的“有效信息”。被删区域可能是背景，也可能是稀有细胞群或组织交界；信息与面积并不线性对应。ssGSEA（单样本基因集富集评分）也不能视为各块面积贡献的简单加和。

若原图物理像素间距为 m 微米/像素，原边长 L，则当前网络输入的名义物理像素间距为 `0.875Lm/224`，全图缩放为 `Lm/224`。当 L=224 时分别为 0.875m 和 m。**两者比较同时改变视野与物体在输入中的像素尺度：当前形态线性放大约 1.143 倍，但不会凭空增加采集细节。** 仅凭“MPP2”目录名或 224 像素不能确认真实物理视野，还需图像生成时的缩放、层级和像素间距。

#### 2. “标签与图像严重失配”成立需要什么条件

本次相关代码读取已有标签 CSV，未找到能够闭环证明当前标签聚合窗口与整个 PNG 严格同域的原始生成链。[既有项目梳理](../01_指南与解读/分析报告/AI预测食管癌性能评估_对话仓库与98模块综合信息表_20260715.md)第 57、358 行也把 bin（表达聚合单元）尺寸、聚合及配准规则列为缺项。“一 patch 对应一 spot”只能说明索引关联，不能证明两者物理面积相同。Visium HD 原生为 2×2 微米方格，并可聚合成更大单元；平台名称本身不能决定本项目标签覆盖多大组织。[10x 官方介绍](https://www.10xgenomics.com/blog/your-introduction-to-visium-hd-spatial-biology-in-high-definition)。

| 实际标签来源 | 裁剪的可能影响 | 推理成立条件 |
|---|---|---|
| 整个 PNG 对应区域内表达聚合后评分 | 预测目标包含模型未直接看到的边缘组织，增加条件预测不确定性 | 标签确实覆盖完整区域；边缘表达有中心形态难以推知的变化 |
| 中心小 bin/spot，PNG 提供周围上下文 | 主要减少周围微环境线索，不必然截掉标签直接对应区域 | 中心位置及配准准确，标签支持域完全位于保留区域内 |
| 邻域加权、细胞分割或其他不规则区域聚合 | 严重程度由区域交叠和权重决定 | 需恢复实际聚合窗口/权重及图像坐标映射 |

因此前文“标签仍包含被删 23.44% 区域的全部转录活性”应作为**第一种情况下的条件性解释**，目前不能当作本项目已核实事实。更准确的表述是“有效形态视野缩小，可能减少标签对应区域或周围上下文的可观测信息”。中心裁剪本身保留中心位置，不等于自动产生坐标平移错误。

### 补充四、对性能、对比学习和空间关系的可能影响

#### 1. 公开研究支持哪些推理

Hist2ST（结合图像、全局和邻域信息的空间表达预测方法）分别建模 patch 内形态、整图关系和相邻点位关系；作者在多个数据集上报告这些信息的联合应用。这支持“单块形态与跨块上下文可能互补”，但该研究并未在本项目 UNI2-h、30 通路任务上比较 0.875 与 1.0，不能据此估计我们会提高多少 PCC（皮尔逊相关系数）。[Hist2ST 原始论文，2022](https://doi.org/10.1093/bib/bbac297)。

Virchow2 的混合倍率训练及病理专用增强设计支持“物理尺度和上下文保留会影响表征”的合理性；其任务与本项目不同，不能直接推导全图缩放一定优于中心裁剪。[Virchow2 原始论文，2024](https://arxiv.org/abs/2408.00738)。以下均为基于上述资料与本项目实现提出的假说。

| 候选影响 | 可能的因果链 | 成立条件及可能反向结果 |
|---|---|---|
| 单点预测受限 | 边缘细胞组成/界面被删 → 中心表征不能区分完整标签差异 → 部分通路误差增加 | 边缘具有中心不能替代的信息；均质组织或中心充分代表标签时影响可很小 |
| 组织交界预测变差 | 肿瘤—间质或免疫浸润边界在外圈 → 过渡线索不完整 → 边界点预测偏向中心组织 | 边界确实位于外圈、尺度可见且与目标有关；并非每个 patch 都有该结构 |
| 关系/对比学习收益受限 | 目标按完整标签相似性组织样本，而图像只看中心 → 形态与标签相似关系不一致 → 关系约束难以满足或与回归冲突 | 丢失部分决定关系、且邻域/中心不可替代；若主要问题是损失权重、负样本或标签噪声，补边缘未必有效 |
| 空间聚合受限 | 邻居也只保留中心 → 邻接交界没有直接证据；特征余弦相似性也可能变化 → 聚合权重不理想 | 依赖边界连续性、形态权重对裁剪敏感；全图也可能增加跨组织混合而加重平滑 |
| 外部泛化受限 | 中心—边缘关联在开发患者稳定，在 XZY 不稳定 → 裁剪导致的替代线索失效 | 外部组织构成、尺度或配准确有这种差异；现有资料没有证明它是 XZY 的主要瓶颈 |
| 模型排名受影响 | 编码器对相同视野/缩放的敏感度不同 → 当前排名依赖协议 | 即使三模型都裁剪，也只能证明当前统一协议下的差异，不能宣称分别使用最佳原生输入时排名不变 |

#### 2. 本项目空间模块的具体受影响路径

[第一轮模型实现](../experiments/phase2_softlink_local_v2/src/model.py)以中心和邻居的汇总特征构造加权差值，再预测空间残差；它没有直接拼接原始 patch 边缘。[构图实现](../experiments/phase2_softlink_local_v2/src/graph.py)按坐标距离确定邻域，并可叠加图像余弦相似性权重。[已运行配置快照](../experiments/results/phase2_softlink_local_v2/20260908_005325_810_8d306c10/config_snapshot.json)中 `use_image_similarity=true`（启用形态相似性加权）。所以裁剪可能通过两条途径起作用：改变节点表征、改变形态边权；**坐标本身及由坐标定义的邻接关系不会因中心裁剪自动消失。**

若规则网格步长等于原图边长 L，裁剪后相邻有效视野的名义间隙为 `L−0.875L=0.125L`；L=224 时约 28 个原图像素。此时邻居中心也未必看到交界条带，增加图聚合不能直接取回该条带的真实图像。若步长小于 0.875L，则有效视野仍可能重叠，邻居可部分补足。这里是几何条件示例，不是对所有患者的实际步长认定。

**空间模块增益可能变大，也可能变小。** 如果缺失边缘使单点更弱而邻居仍能提供替代信息，现协议可能放大空间模块的相对收益；如果所有邻居都缺掉关键交界，现协议也可能压低空间收益。恢复全图后，单点变强而空间增益缩小，仍可能意味着系统整体改善。

#### 3. 已有结果不支持“空间信息一直没有用好”的笼统归因

[实验登记表](../experiments/experiment_registry.json)将 `phase2_softlink_local_v2` 的 `20260908_005325_810_8d306c10` 四臂三种子结果登记为已确认描述性证据，结论是主要收益来自 spatial（空间臂），relation（关系臂）增量小且不稳定。下表来自该批[双 PCC 汇总](../experiments/results/phase2_softlink_local_v2/20260908_005325_810_8d306c10/analysis/pcc_side_by_side.csv)，为 3 个种子的均值±样本标准差。

| 数据集 | 臂 | 患者—通路等权平均 PCC | 整体展平 pooled PCC |
|---|---|---:|---:|
| 内部验证 | point（单点） | 0.65326±0.00086 | 0.79847±0.00021 |
| 内部验证 | relation（关系） | 0.65305±0.00096 | 0.79861±0.00001 |
| 内部验证 | spatial（空间） | 0.66628±0.00071 | 0.80564±0.00050 |
| 内部验证 | joint（联合） | 0.66598±0.00068 | 0.80565±0.00037 |
| XZY | point（单点） | 0.51306±0.01145 | 0.65010±0.01196 |

这些数据说明现有输入仍支持空间增益，不能证明裁剪无害，也不能说明补边缘会进一步放大增益。此前其他对比方案若使用不同输入、划分或训练配方，必须逐项核对，不能从本次加载器发现直接统一归因。关系目标、样本构造、组织异质性、患者数、优化和冻结表征容量都是仍需保留的竞争解释。

### 补充五、推荐操作：当前保持一致，后续用小规模成对验证定位影响

#### 1. 当前继续完成消融

赞同用户先完成现有消融的安排。当前最有价值的是在同一输入条件下完成编码器对照，而不是中途改变一个模型的视野。

- 沿用既定共同变换、划分、标签、训练参数和选模规则；核对开发患者与 XZY 缓存来源，保留实际展开的预处理记录。旧元数据缺项如实标记，不凭当前实现补写历史事实。
- 在本轮结论中注明“固定历史中心裁剪输入协议下的编码器比较”。相同几何输入能控制视野差异，但不等于每个编码器都处于各自最优预处理条件。
- 不在已经训练的旧预测头前直接换成全图特征。新旧特征分布不同，直接替换只能作为分布变化诊断，不能用于公平评估全视野方案。
- 此处不启动训练或修改实验代码；原始 PNG、旧缓存、权重、结果保持原状。若发现实际缓存混用不同变换、身份错配或划分泄漏，则应定向处理真实问题，不能以“以后补视野实验”为由忽略。

#### 2. 后续先明确标签区域，再做最小对照

**先补几何事实。** 找到生成 PNG 与标签的原始规则，确认标签是中心 bin 还是区域聚合，坐标为中心还是左上角、像素间距和图像缩放链；在少量代表性训练样本上叠加完整视野、保留中心及标签区域。样本可包括均质组织与组织交界，不依据 XZY 预测误差挑选。

**先比较总体效果。** 在同一 UNI2-h 和同一标签/划分下，比较现有裁剪与全图缩放，固定输出尺寸、双三次插值和归一化，仅改变视野/缩放几何；各自训练匹配的单点头。这样测的是“视野与尺度策略的联合效果”，不能命名为纯边缘信息的因果收益。若要与官方示例比较，还应单独记录插值差异，不能同时换插值后全部归因于视野。

**再判断空间收益是否受压制。** 采用以下最小四格设计；计算资源紧张时可先单种子探索，正式解释再补配对种子，并保留种子差异。

| 输入 | 单点预测 | 同配方空间预测 |
|---|---|---|
| 现有中心裁剪 | A | B |
| 全图缩放 | C | D |

同一指标下，`C−A` 表示单点变化，`D−B` 表示空间系统整体变化，`(D−C)−(B−A)` 表示空间增益随视野改变的差值。该差值为正才支持“恢复全图后，空间模块的额外价值上升”；若单点和空间都改善但差值不为正，则支持整体输入改善，不能声称此前空间增益被裁剪压制。实际空间系统会随特征更新形态边权；若还要区分节点表征和边权影响，再补固定边权诊断，不必首次就扩大实验矩阵。

若关注关系/对比学习，则对应比较两种输入下的 point 与 relation，控制关系构造及训练配方。若最终要宣称多个编码器的排名不依赖视野，则需另补“编码器×输入协议”对照，单个 UNI2-h 的四格实验不能回答全部模型排名问题。

**进一步分离机制是可选项。** 若四格显示明显变化，可在全图尺度下遮蔽外圈，以探查边缘内容贡献；但遮蔽会引入人工边界和输入分布变化。也可探索保持组织尺度的更大输入，但这同时改变 token 数量与计算，不能宣称任何一个简单对照完全隔离了全部机制。

#### 3. 评价和后续资产安排

采用既定内部验证选模，报告两种 PCC、逐通路及可用患者/种子差异，尤其区分均质区域与组织交界；全视野协议不能根据 XZY 成绩反复选择。XZY 已被多轮查看，应继续称为历史外部参考，最终更强泛化判断仍需新的独立患者。恢复全视野前核查完整图像和标签支持域的空间隔离；若确需改划分，应在新划分上重新做匹配对照，不能直接与旧数字相减。

未来获授权开展该实验时，使用独立代码包与独立特征缓存，登记视野、缩放、软件版本和原始来源；不覆盖旧缓存。新缓存遵循项目服务器 `feature_caches` 专用目录规则，结果回传只带路径登记。当前仅完成预研判，不新增运行或科研接受状态。

**最终建议：把此问题作为一个值得验证的输入协议因素，允许当前消融继续；优先补齐标签—图像物理对应关系，随后用配对视野对照检验。现阶段最可信的推理是“可能减少有用形态或微环境线索，并改变尺度与形态边权”，而不是“已证实丢掉四分之一标签信息，或已经找到既往空间/对比方案效果有限的主因”。**
