## 4. 问题一：消融设计是否恰当——输入输出差异的处理

### 4.1 处理得当之处

1. **输出侧完全共享**。三模型都预测同一顺序 30 条通路、同一训练集拟合的 z 标度、同一损失，逆变换只做一次。输出侧不存在模型间差异，无需额外处理。
2. **输入侧“像素级共同协议”**。同一原始 PNG → RGB → 完整视野缩放到 224 → ImageNet 均值/方差。三模型官方预处理均使用 ImageNet 常量（UNI/UNI2-h 模型卡、Virchow2 `config.json`），因此统一归一化不是对任何一方的偏离。方案明确“不能只调用各自默认 transform”是正确的，且有本地反例支撑（见 4.2 第 4 点）。
3. **维数差异的处理选择合理**。原生 d 直接映射到 256，不补零、不截断、不 PCA、不加投影，报告实际参数量，并把实验准确描述为“冻结编码器及其原生输入接口的替换比较”。这是病理基础模型基准（linear/MLP probe）领域的通行做法，比强行对齐维数更少引入人为因素。
4. **随机性配对设计细致**。输出层初值复制自同种子 UNI2-h 模板；样本顺序与 Dropout 掩码走独立随机流（现有 `train.py` 已用 numpy PCG64 与独立 `torch.Generator` 实现），模型初始化消耗随机数不会串扰。
5. **Virchow2 token 布局理解正确**。`output[:,0]` 为 CLS、`output[:,1:5]` 为 register、`output[:,5:]` 为 256 个图像 token，与作者示例一致；第 12 节用人工 token 验证排除 register 的做法值得保留。
6. **精度统一为 fp32**。虽偏离 Virchow2 官方的 fp16 建议，但对三模型一致且更保守；方案已规定不得只改一个模型的精度。

### 4.2 风险与建议

1. **汇总方式（pooling）与编码器绑定，形成混杂**。UNI2-h/UNI 用 CLS，Virchow2 用 CLS⊕mean-patch。若 Virchow2 领先，审稿人第一问会是“是编码器更好，还是多了 mean-patch 汇总？”。方案第 3.2 节将 CLS-only 排除在主协议之外是可以的，但应把它变成**预注册的敏感性臂**：
   - Virchow2-CLS(1280)：直接取 2560 缓存的前 1280 维，零提取成本，只多训练一组预测头。
   - 在提取 UNI、UNI2-h 时**同时保存 mean-patch 向量**（UNI `tokens[:,1:]` 均值，UNI2-h `tokens[:,9:]` 均值，排除 8 个 register），各约 45 MiB 与 68 MiB。这样“CLS⊕mean-patch”对三模型都可算，pooling 轴对称，且不必日后重提取。
   - 主表仍报告作者推荐表征；敏感性臂单列，用于机制解释。
2. **同一训练配方对不同特征标度的隐性偏向**。lr/wd/dropout/60 轮预算是在 UNI2-h 特征上形成的；AdamW 对梯度标度不敏感，但函数空间步长仍随输入范数变化，post-LayerNorm CLS 与 256 个 token 平均后的向量范数分布不同。方案拒绝“只对某一模型标准化”是对的；建议追加**对三模型对称**的两项敏感性分析（都只用训练集/内部验证）：①训练集拟合的逐维标准化；②等预算小范围学习率扫描（如 {1e-4, 3e-4, 1e-3}×单种子）。同时在缓存元数据中记录每个模型特征的逐维均值/方差与范数分布，报告中呈现。
3. **缩放实现细节**。三名患者（HYZ15040、LMZ12939 为 336 像素，JFX 为 448 像素）需要降采样到 224，PIL 双三次（抗锯齿）与 torch `F.interpolate(mode="bicubic")`（默认不抗锯齿）得到的像素不同；TGC/XSL/ZHZ 为 224 像素则不重采样。方案需写明：对 PIL 图像用 torchvision `Resize((224,224), interpolation=BICUBIC)`（或等价 PIL 调用）、`antialias` 状态、库版本，并落入缓存元数据。这样也便于解释旧缓存差异。
4. **旧 UNI2-h 缓存的具体差异应写实，并直接决定重提取**。本地旧提取链 `extract_uni2h_mpp.py → uni2h_utils.load_uni2h_backbone`：离线模式下命中共享 HF 缓存 → `_load_uni2h_from_local` → `create_transform(input_size=224, is_training=False, interpolation="bicubic")`，未传 `crop_pct` → timm 默认 0.875 → `Resize(256) + CenterCrop(224)`（本机 timm 1.0.26 实测；服务器 1.0.27 行为相同）。同时该加载器 `strict=False`、cuDNN TF32 未显式关闭。因此旧缓存与新协议在视野、重采样路径、加载严格度上均不同，第 4.3 节的“证明一致才复用”在事实上不可能满足，应直接写为“重提取”，并明确：
   - 已接受的第一轮 point 成绩（内部患者—通路等权 PCC 0.653263、pooled 0.798467；XZY 0.513057 / 0.650099）**不是**本轮匹配参照；重提取后的 UNI2-h point 才是。
   - 新旧 UNI2-h point（同种子）差异作为“协议迁移核对”单独报告，用于说明主方法（第一轮 spatial 臂，基于旧特征）与本轮消融（新特征）之间的桥接，不作为模型比较结果。
   - 提取正确性锚点：同一小样本上新旧 UNI2-h CLS 的余弦相似度分布应明显偏高（视野重叠约 77% 面积，预期高度相关）；若接近 0，说明某一侧提取有误。这是诊断，不是等值检验。
5. **倍率/视野域差是三模型间最大的“非对称先验”**。Virchow2 预训练覆盖 2.0/1.0/0.5/0.25 µm/px（5×–40×），UNI 仅 20×（约 0.5 µm/px）256/512 像素块，UNI2-h 模型卡未注明倍率。group_2 各患者块像素不同、统一缩放到 224 后有效 µm/px 不同，方案未给出 group_2 的物理分辨率（`split_info.json` 只注明 MPP-3=0.27、MPP-5=0.54）。建议在方案第 4.2 节增加一张表：患者 × 原生像素 × 原生 µm/px × 缩放后有效 µm/px（含 XZY，现为 `unverified`），并写明各编码器预训练倍率范围。这不影响公平性，但决定结果如何解释，也是第 6 节机制分解的前提。
6. **register token 的对称处理**。若采纳第 1 点保存 mean-patch，UNI2-h 必须排除 8 个 register（`[:,9:]`），UNI 无 register（`[:,1:]`）；第 12 节的人工 token 测试应覆盖三模型。
7. **fp32 与官方 fp16 建议的偏离**。保留 fp32 主协议；建议在小样本上记录 fp16 autocast 与 fp32 嵌入的余弦相似度与最大绝对差，作为工程诊断随缓存元数据保存，回应可能的“未按作者建议推理”质疑。

## 6. 问题三：替换基础模型后性能反而提升时的处理协议

### 6.1 定性与原则

- “与预期不符”只是相对团队假设（UNI2-h 最优）而言。Virchow2 训练数据更大（3.1M WSI）、覆盖 2.0 µm/px 低倍率、参数量相近，在接近 5× 的输入上领先在文献上并不反常；UNI（前代、单倍率、0.3B）领先则更出乎意料，需要更高的怀疑强度。方案第 1 节“不预设赢家”与 Registry `narrative_evidence_status=hypothesis_pending_experiment` 已为此留好位置。
- 原则：**先证伪工程错误，再确认稳健性，再做机制分解，最后改叙事**。任何一步都不得回头改动主协议、选模规则、评价集合或模型名单来“修正”结果。协议若必须改，按方案第 9 节新开协议版本，对全部模型重跑，旧结果保留并报告。

### 6.2 第一步：工程核对清单（结果确认前必须全部通过）

| 核对项 | 做法 | 通过标准 |
|---|---|---|
| 身份对齐 | 逐模型核对特征行 ↔ 标签 ↔ 划分的身份键与显式行索引 | 无缺失、无重复、三模型身份集合完全相同 |
| 负对照 | 对每个模型做一次“打乱特征行”或“打乱标签”的训练（工程输出，不入科研表） | 内部 PCC 塌缩到接近 0；若仍偏高，存在泄漏或对齐错误 |
| 严格加载 | 三模型 `strict=True`，无 missing/unexpected 键；UNI 含 LayerScale 键；Virchow2 含 SwiGLUPacked 与 4 个 register；UNI2-h 含 8 个 register | 加载日志留档 |
| 汇总正确性 | 人工 token 测试（排除 register、覆盖全部图像 token）；真实图像上 CLS 与 mean-patch 的范数量级合理 | 第 12 节测试通过 |
| 视野一致 | 抽样图像三模型输入张量在归一化前逐像素一致（同一函数产生） | 差异为 0 |
| UNI2-h 新旧锚点 | 小样本新旧 CLS 余弦相似度分布 | 明显偏高；若接近 0 则新旧之一提取有误 |
| 训练轨迹 | 三模型 history：是否触及 60 轮上限、早停轮次、warmup 分数是否异常高（异常高提示泄漏） | 无异常 |
| 随机流配对 | 同种子三模型 `center_orders`、Dropout 生成器状态、输出层初值一致 | 一致 |
| 精度与环境 | 提取与训练均 fp32、TF32 关闭，环境文件一致 | 一致 |

### 6.3 第二步：稳健性确认

- 三模型补齐 43/44（预先承诺），逐种子计算后给均值与样本标准差；先在患者内对种子取均值，再做患者级配对差值（候选−UNI2-h）、方向一致数与患者配对 bootstrap 95% CI。
- 两种 PCC、z-MSE、CCC、Spearman 同向性检查；逐通路差值分布（哪些通路带来增益，是否集中在少数通路）。
- 内部验证与 XZY 的方向是否一致，仅作报告，不作为筛选。
- 若增益在多数患者、多数种子上一致，且工程核对全部通过，则认定为本协议下的真实发现。

### 6.4 第三步：机制分解（预注册的探索分析，均只用训练集/内部验证）

1. **汇总方式**：Virchow2-CLS(1280) 切片臂；若 ≈ UNI2-h，则增益主要来自 mean-patch，而非编码器；再用保存的 mean-patch 训练 UNI2-h⊕mean-patch、UNI⊕mean-patch 做对称验证。
2. **容量/维数**：训练集拟合 PCA 到共同维数（如 1024）对三模型重训；若排名不变，增益不来自更多输入参数。
3. **倍率**：按患者原生像素（224 vs 336/448）分层看差值，对照各编码器预训练倍率覆盖；Virchow2 的低倍率预训练是候选解释。
4. **特征标度与配方**：对称逐维标准化臂、等预算 LR 扫描臂；若排名随配方翻转，说明主协议差异在配方敏感范围内，应如实写明。
5. **特征层诊断**（无需训练）：逐模型特征范数分布、有效秩、患者身份可预测性（批次效应代理）、kNN 检索一致性。

### 6.5 第四步：登记与叙事处理

- 结果先以 `pending_review` 登记，用户审核后方可 `accepted`；分析报告写入对应运行目录 `analysis/`，跨模型机制探索写入项目分析报告目录。
- Registry `phase2_pathology_model_benchmark_v001_20260904` 的 `expected_paper_narrative` 应由用户触发更新，明确写入实际结论；不得保留“若支持 UNI2-h 最优”的单向表述。
- 论文叙事改为：UNI2-h 为方法开发阶段的骨干（历史/访问原因）；替换消融显示某替换模型在本队列单点预测上更优；经典空间残差方法与骨干无关，预计可迁移。是否在获胜骨干上补跑 spatial 臂做确认属范围扩大，由用户决定。
- 反向情形同样适用：若 UNI2-h 领先，也必须通过 6.2 与 6.4（尤其配方偏向）后才能写“UNI2-h 最优”。

### 6.6 禁止事项

不得在看到结果后：改选模指标或评价集合；只对某一模型调参/标准化/改精度；把某模型剔出名单或加入新模型再平均；用 XZY 决定任何选择；把 43/44 的新协议结果与 42 的旧协议结果混成均值；以“未收敛”为由单独延长某模型预算。

### 二、对“必须重提取”的不同判断

原审计指出了真实的**协议差异**：v1.0 全图缩放到 224，与旧本地加载分支的 Resize(256)→CenterCrop(224) 不同。本次接受这个发现，但不接受“因此只能重提取旧模型”的唯一解。

用户当前优先复用旧资产。可行的修订是撤销新加的全视野缩放要求，让 UNI、Virchow2 对齐第一轮实际输入处理。这样不需要仅为适应新方案而改变 UNI2-h。若以后确认旧缓存存在具体错配或错误，应针对该证据处理；缺少元数据不是已经发现错误。

原审计也注明服务器实际命中未核实，因此第 4.2 节“证明一致在事实上不可能满足”和第 7 节“应判定重提取”比现有证据更强：

- 本地代码中的 `strict=False` 允许不匹配加载，但若实际 missing/unexpected 为空，主干仍可能完整加载；必须看实际键匹配情况，不能从开关直接推出错载。
- 未显式关闭 cuDNN TF32 说明历史算子设置没有完全记录，不证明所有运算用了 TF32，也不证明保存为 float32 的特征一定由纯 FP32 算出。新代码关闭 TF32，旧缺项如实说明。
- 合作方缓存和 flat 缓存可由不同来源生成。现存提取脚本及本机 transform 展开不能独自证明所有旧文件实际执行了这条链。
- 图像覆盖约 76.6% 面积是几何关系，不能据此规定 CLS 余弦相似度“必须明显偏高”，更不能把接近 0 无条件当作某一侧错误的充分证据。本轮不安排该相似度对比。

方案已明确：优先读取旧缓存和匹配 point 的原始预测、初值、训练记录及正式检查点；若缺真值则补身份对齐的真值，在本地统一评价。不能复用时先汇报具体问题；不默认重提取、重训或迁移 Phase 3，也不把尚未查明的旧预处理写成已经完全匹配。

### 四、CLS 与辅助均值的边界

原审计关于 pooling（特征汇总方式）存在额外差异的提醒有用。本版直接将主实验统一为 CLS，因而当前不需要另外训练 Virchow2-CLS“敏感性臂”。作者推荐 2560 拼接表征及允许 CLS 单独使用均有依据，修订后报告应明确称“Virchow2-CLS”，不冒充作者完整推荐表征的结果。[官方说明](https://huggingface.co/paige-ai/Virchow2)

提前保存新模型均值可以避免将来重复前向，但 UNI2-h 不能无成本保证取得：已知主缓存只有 1536 维 CLS；另见 65-token 样本，不是完整 265-token 输出。**65-token 缓存不能用 `[:,9:]` 求“全部 256 个图像 token”的平均值。** 必须先核对 token 布局和完整性；没有完整输出就保持辅助向量不可用。

未来若用户决定研究 CLS+均值，需对该问题另行安排比较。也不能仅凭“Virchow2-CLS≈UNI2-h”就直接证明某次增益完全来自均值；这类机制归因需要相应比较，当前不作该结论。

### 五、FP32 推荐及审计建议的取舍

Virchow2 模型卡推荐 FP16 自动混合精度以提高 GPU 效率。这是合理选项，原审计建议比较两种精度也可作为特定故障诊断，但**不是本次必须额外做的一组实验**。

本轮推荐 FP32 的依据是：旧 UNI2-h 提取代码没有 AMP、第一轮头部训练明确 FP32；复用旧参照能省去一套编码器提取和重复基线训练；服务器约 16 GiB 显存、冻结编码器逐个推理，采用可降低的提取批量是合理起点。FP32 可能较慢，当前没有现场测时；不能把这个资源推断写成批量 16 保证可运行或已经验证吞吐。方案只选 FP32，显存不足先减提取批量，不双跑精度、不自动改训练批量。

### 1. 核心定性：输入 Patch 是否完整？
**事实确证**：在第一轮实跑并已沉淀为特征缓存的旧提取链中，送入 UNI2-h 编码器的图像**确实始终不是完整的磁盘 Patch，而是丢失了四周边缘、仅保留中心约 76.56% 面积的局部视野**。
- **磁盘静态图像**：服务器数据源中各个患者的 `patch_images/*.png` 本身是完整的正方形图像（经实测均为 $224 \times 224$ 像素）。
- **张量变换裁剪**：旧提取代码（[`extract_uni2h_mpp.py`](../extract_uni2h_mpp.py) 配合 [`uni2h/uni2h_utils.py:121`](../uni2h/uni2h_utils.py#L121)）调用了 `timm` 的默认评估预处理 `create_transform(input_size=224, is_training=False, ...)` 且未传 `crop_pct`，触发了默认常量 `crop_pct=0.875`。流水线实际执行了 `Resize(256) -> CenterCrop(224) -> Normalize`，致使周边约 **$23.44\%$ 的组织面积在进入模型前被丢弃**。

### 2. 溯源与操作简况
- **始发时间点**：**2026 年 7 月 3 日**。在进行“服务器离线加载 UNI2-h 权重排障”时，为绕过 HuggingFace Hub 在线检查，开发者手写了纯本地离线加载函数 `_load_uni2h_from_local()`，其中构建预处理时遗漏了 `crop_pct=1.0`，导致后续全量提取的 `MPP-2` 等特征缓存均携带该几何裁剪。
- **当初操作的原因**：排障焦点集中在权重下载与张量键值匹配，视觉预处理直接依赖了通用计算机视觉库 `timm` 的 ImageNet 默认测试流派，产生了对库黑盒缺省行为的认知盲区，脱离了作者官方推荐的无裁剪代码。
- **客观优势**：客观上滤除了切片扫描切割的边缘伪影、增大了相邻密集 spot 之间的物理防泄漏间隙、贴合了 ViT 预训练的高频纹理先验。
- **潜在危害**：在空间转录组（Visium HD）任务中，该操作导致**测序真值标签与图像形态感受野发生物理失配**（真值反映全块转录组，而图像丢失了 23.44% 边缘微环境），截断了边缘拓扑结构，并在多模型横向消融中构成了视野混杂。

### 3. 消融部署方案处理准则
- **严格视野对齐**：新模型（UNI、Virchow2）在特征提取代码中，**必须显式复现完全相同的变换流水线**（`Resize(256) -> CenterCrop(224) -> Normalize`），保证三者在**完全对齐的 76.56% 局部视野**下进行公平受控消融；
- **事实公开透明**：在论文与报告中如实陈述该几何设定，绝不隐瞒或虚构宣称“输入了完整视野”；
- **未来展望**：在后续独立实验或 Phase 3 中再行设立“100% 全视野重提取”对照臂，评估视野恢复带来的纯几何收益。
